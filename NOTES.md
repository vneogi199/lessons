# Teaching and Product Notes

- Optimize the curriculum for international full-stack AI engineering interviews, portfolio credibility, and relocation-friendly hiring.
- Go deep: teach internals, failure modes, tradeoffs, debugging, and production behavior alongside practical implementation.
- Include JavaScript and Node.js as first-class deep tracks, not only as prerequisites for React.
- Use focused lessons with code, analogies, high-contrast visuals, blackboard diagrams, and one mastery check. Beginner lessons can take 15–35 minutes.
- Use a dark, high-contrast focus-mode interface with IBM Plex Mono Nerd Font and comfortably readable text.
- Keep `PLAN.md` synchronized whenever product or curriculum decisions change.
- Pre-generate every mapped topic through Codex; do not generate lessons in the browser or on application startup.
- Treat JavaScript as a complete deep-dive curriculum, including specification literacy, values, execution and object models, functions and closures, modules, asynchronous scheduling, cancellation, resource management, binary and shared memory, engine internals, performance, security, testing, debugging, production architecture, extensive code, practical exercises, and interview preparation.
- Treat TypeScript as a complete deep-dive curriculum, including compiler internals, inference, structural relationships, narrowing, generics, advanced type transformations, modules, declarations, runtime validation, framework integration, testing, project scaling, performance, upgrades, safe AI-assisted development, production architecture, extensive code, practical exercises, and interview preparation.
- Treat Node.js as a complete deep-dive curriculum, including V8 and libuv architecture, event-loop scheduling, the worker pool, binary data, streams and backpressure, files and networking, HTTP, modules, package behavior, processes, workers, security, testing, diagnostics, memory, performance, native boundaries, process lifecycle, production architecture, extensive code, practical exercises, and interview preparation.
- Treat React as a complete deep-dive curriculum, including every current stable React and React DOM hook with examples, runtime internals, server features, practical exercises, and extensive code where the concept requires it.
- Treat FastAPI as a complete deep-dive curriculum, including ASGI and Starlette internals, the full documented request/response and dependency surface, security, data, testing, operations, deployment, extensive code, practical exercises, and interview preparation.
- Treat Python as a complete deep-dive curriculum, including its execution and object models, language protocols, typing, concurrency, memory, testing, packaging, native boundaries, security, production architecture, extensive code, practical exercises, and interview preparation.
- Treat Cloud and AWS as a complete independent deep-dive curriculum, including shared responsibility, accounts, IAM, networking, edge delivery, compute, storage, databases, events, operations, infrastructure as code, reliability, cost, Bedrock, SageMaker, extensive code, practical exercises, and interview preparation.
- Treat DevOps as a complete independent deep-dive curriculum, including delivery flow, Linux, networking, shell, Git, CI/CD, software supply-chain security, release strategies, observability, incidents, infrastructure as code, platform engineering, extensive code, practical exercises, and interview preparation.
- Treat Docker as a complete independent deep-dive curriculum, including engine and image internals, BuildKit, process behavior, isolation, networking, storage, Compose, observability, registries, multi-platform builds, hardening, extensive code, practical exercises, and interview preparation.
- Treat Kubernetes as a complete independent deep-dive curriculum, including API machinery, control-plane reconciliation, scheduling, workloads, networking, storage, configuration, security, autoscaling, observability, extensibility, cluster operations, EKS, extensive code, practical exercises, and interview preparation.
- Treat PostgreSQL, Redis, and Data Systems as a complete independent deep-dive curriculum, including relational modeling, SQL, planner and storage internals, MVCC, isolation, indexing, maintenance, WAL, replication, recovery, security, observability, performance, Redis structures, persistence, clustering, streams, caching, coordination, extensive code, practical failure experiments, and interview preparation.
- Treat API Design and Distributed Systems as a complete independent deep-dive curriculum, including HTTP and schema contracts, protocol styles, API evolution, security, explicit L4/L7 load balancing, streaming, partial failure, clocks, deadlines, retries, overload, messaging, workflows, replication, consistency, consensus, sharding, multi-region operation, system-design interviews, extensive code, practical fault experiments, and interview preparation.
- Treat International Interviews and Relocation Readiness as a complete practical module, including role targeting, ATS resumes, LinkedIn and GitHub, job portals, employer verification, application tracking, ethical local automation, recruiter screens, coding and technical loops, system design, AI, behavioral and situational model answers, technical storytelling, influence without authority, ethical persuasion, portfolio presentations, networking, referrals, relocation research, sponsorship, salary and offer negotiation, and measured mock practice. Never teach deception, coercion, scraping, automated engagement, or mass application submission.
- Assume the learner has no familiarity with each lesson topic. Apply the same detailed beginner format to all 602 lessons and all 26 tracks.
- Use human language based on ASD-STE100 Simplified Technical English. Prefer short active sentences, complete words, consistent technical nouns, gradual detail, concrete examples, and one instruction per sentence.
- Define every title-level term once in plain language, then connect the terms with one mechanism explanation.
- Keep the beginner foundation, four-stage walkthrough, practical steps, code-reading guidance, common mistakes, failure diagnosis, and interview answer frame concise and human. Do not add agendas, outcome cards, or repeated templates.
- Keep lesson headings compact; generated lesson titles use a responsive 22–34 px range.
- Do not repeat the track goal and generic interview-readiness introduction beneath every lesson title.
- Omit generic content headings that only restate their section label.
- Add each lesson's content revision to its iframe URL so regenerated lesson HTML cannot remain stale in the browser cache.
- Cover LangChain v1, LangGraph, and reproducible LLM benchmarking through dedicated practical lessons, while still teaching the underlying framework-independent mechanisms.
- Cover MCP, vector databases and their index and storage internals, AI frontend engineering, production webhooks, application file storage, durable background jobs, audit logs, and admin systems through dedicated practical lessons with beginner definitions, failure experiments, extensive code, and interview preparation.
- Treat software design as a dedicated practical track. Cover clean code, DRY, KISS, YAGNI, cohesion, coupling, SOLID, composition, GoF pattern families, safe refactoring, and architecture patterns without teaching principles as dogma or adding patterns before current requirements justify them.
- Treat DSA interview preparation as a 15-lesson progression with dedicated coverage of sorting, binary search, array and string patterns, linked lists, trees, graphs, backtracking, dynamic programming, greedy proof, and bit manipulation.
- Treat microservices, domain-driven design, event-driven systems, and Kafka as one dedicated 9-lesson architecture track. Compare modular monoliths before extraction, preserve explicit service and data ownership, and teach reliable event delivery, schemas, replay, testing, observability, and operations.
- Use topic-aware trace language throughout lessons; reserve “unit of work” for the database transaction pattern where it is the actual concept.
- Blackboard visuals must teach the real mechanism with readable stages, a concrete experiment, and evidence to inspect; never fill diagram boxes by splitting the lesson title.
- Keep the focus-mode sidebar header minimal and omit the removed curriculum manifesto tagline.
- Allow a mastered lesson to be marked incomplete individually so progress can be corrected without resetting the curriculum; keep it keyboard and screen-reader accessible with native button behavior, a visible focus ring, a status announcement, and Alt+U.
- Keep a separate focus-mode dashboard for a concise summary of overall and per-track progress, with JSON backup and restore for local progress.
- The learner has basic JavaScript and Python familiarity and can study approximately 6–8 hours per week.
