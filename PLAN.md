# Full Stack AI Engineer Tutorial Site

## Summary

Build a local-first tutorial site using plain HTML, CSS, and JavaScript. It will provide a 24-week international-interview core plus self-paced deep extensions, 644 pre-generated self-contained interactive lessons authored by Codex through the `teach` workflow, mastery-based progress tracking, and topic/overall completion percentages.

The curriculum assumes basic JavaScript and Python knowledge, 6–8 study hours per week, and targets production full-stack AI engineering, international interview performance, relocation-friendly hiring evidence, and three progressively more capable portfolio applications.

## Implementation

- Create a responsive roadmap showing:
  - Topics, weeks, prerequisites, and ordered lessons.
  - Completed versus total lessons per topic.
  - Topic and overall completion percentages.
  - Recommended-next-lesson highlighting without locking other lessons.
  - Filtering by topic, status, and project.
- Keep `roadmap.yaml` as the editable source of truth. Derive stable slug-based lesson IDs so lessons can be reordered without losing progress.
- Display separate interview-core, deep-curriculum, and portfolio progress so optional depth does not obscure core readiness.
- Use `scripts/generate-lessons.mjs` as the Codex-authored build step: it validates the controlled roadmap schema and writes the checked-in HTML lessons plus `lessons/manifest.json`. Run it only while authoring or changing the curriculum, never on application startup.
- At runtime, load the generated `/lessons/manifest.json` catalog and embed its declared lesson paths. Start the local HTTP server from the workspace root and open `/`.
- Store a deterministic content revision for every generated lesson and append it to the iframe URL so browser caches refresh when lesson HTML changes.
- Store versioned progress in `localStorage` under `full-stack-ai-roadmap.progress.v1`.
- Provide a focus-mode dashboard with overall mastery, mastered and remaining lesson counts, started and completed track counts, every track percentage, and a link to each track's next unfinished lesson.
- Allow progress to be exported to and restored from a validated versioned JSON backup. Ignore unknown lesson IDs and reject malformed or oversized files.
- Count a lesson as complete only after its mastery check passes. Calculate percentages by completed lessons divided by total lessons, with every lesson weighted equally.
- Provide a full-progress reset with confirmation and a visible `mark_incomplete()` control for the active mastered lesson. The control is reachable with Tab, activates with Enter or Space, exposes its accessible name and shortcut to assistive technology, announces the resulting status, restores focus to the lesson after activation, and supports Alt+U from both the shell and embedded lesson.

### Current MVP direction

- Use the repository root as the selected Focus Mode prototype and baseline for future interface work.
- Present lessons in a dark, high-contrast, distraction-free interface using IBM Plex Mono Nerd Font when installed, with IBM Plex Mono and system monospace fallbacks.
- Keep body, lesson, code, diagram, navigation, and mastery text comfortably readable; metadata may be smaller but should not drop below a practical 10–11 px visual size. Display curriculum track names such as React, Python, and GenAI at 12 px or larger with clear emphasis. Keep generated lesson titles within a compact 22–34 px responsive range.
- Preserve the focus prototype's active-lesson persistence, URL deep links, reading progress, previous/next navigation, keyboard shortcuts, mastery feedback, and recommended-next flow.
- Keep the sidebar header compact: show the Deepstep brand and build tag without an additional curriculum-manifesto block.
- The root `index.html` owns the Focus Mode progress dashboard; `lesson.html` owns the lesson view.
- The focus-mode MVP loads the complete catalog from `lessons/manifest.json` and embeds the corresponding pre-generated lesson HTML. The original six demonstration lessons remain available only in the archived comparison prototypes.

Every lesson will:

- Teach one tightly scoped, mission-related capability.
- Assume no prior knowledge of the lesson topic. Define the shared words `input`, `boundary`, `state`, `mechanism`, `output`, `evidence`, `failure mode`, and `tradeoff` before advanced content.
- Apply core ASD-STE100 Simplified Technical English rules: short active sentences, complete words, consistent terms, gradual detail, one topic per paragraph, and imperative steps.
- Include detailed theory, an analogy, runnable or inspectable code, and a readable topic-aware blackboard flow with four meaningful mechanism stages.
- Name the concrete mechanism being traced in each blackboard, interview prompt, and teach-back field—such as a render cycle, HTTP request, import, iterator step, concurrent task, transaction, retrieval query, or evaluation case—instead of using “unit of work” for every lesson.
- Begin each lesson with its title and a compact beginner foundation; omit agenda, outcome, track-goal, and interview-readiness introductions.
- Give every blackboard a mechanism-specific input-to-outcome sequence, a falsifiable experiment, and named evidence to inspect. Do not derive diagram boxes from comma-separated title fragments.
- Define every title-level term once, then explain how the terms connect through the lesson mechanism. Do not repeat the same example, verification, mistake, or interview template inside every term card.
- Expand the blackboard into a concise four-stage walkthrough with one failure experiment and the evidence to inspect.
- Include a four-step practical lab, a three-step code-reading guide, four short diagnostic mistakes, and a compact interview-answer frame.
- Include one auto-graded mastery check with immediate feedback and unlimited retries.
- Include a four-question interview bank covering the core expectation, mechanism tracing, practical evidence, and failure-mode diagnosis.
- Cite trusted sources and recommend one primary source.
- Link to relevant lessons and reference documents.
- Work independently for printing while appearing inside the site’s shared navigation shell.
- Provide a “Continue with Codex” button that copies the mastery evidence and follow-up prompt. Codex can then answer questions and create a qualifying learning record.

The focused beginner format applies to all 644 lessons across all 28 tracks. Every lesson defines each title-level term, connects the terms through one mechanism explanation, and retains the foundation, analogy, blackboard, concise walkthrough, practical code, mistakes, interview questions, and mastery check. Generic headings, repeated agenda, and template prose are excluded. Estimated lesson time scales from 15 to 35 minutes according to the number of title-level concepts.

Lessons communicate completion to the shell through a versioned event:

```js
{
  type: "teach:mastery",
  version: 1,
  lessonId,
  passed,
  score,
  completedAt,
  evidenceSummary
}
```

The shell will accept events only from the active same-origin frame and for lesson IDs and paths declared in the generated manifest.

## Curriculum Architecture

`roadmap.yaml` contains 28 tracks and 644 deep topic clusters. Each cluster records the underlying mechanism, a practical task, and the related interview expectation. The MVP produces one guided lesson per cluster; later curriculum passes may split a cluster into smaller lessons while retaining stable IDs and mastery migration rules.

The Software Design, Clean Code, and Patterns track has 12 lessons. It covers readable names, functions, control flow, comments, local reasoning, pragmatic DRY, KISS, and YAGNI decisions, cohesion, coupling, encapsulation, information hiding, all five SOLID principles, composition and inheritance, pattern decision literacy, the creational, structural, and behavioral GoF pattern families, code smells, behavior-preserving refactoring, layered and dependency-inverted architecture, vertical slices, repositories, units of work, and modular monoliths. Every principle and pattern is taught through its problem, forces, consequences, simpler alternative, practical refactor, and interview explanation rather than as a universal rule.

The Computer Science and Coding Interviews track has 33 lessons. It preserves the original complexity, core-structure, sorting, tree, graph, recursion, and interview-method lessons, then adds 18 pattern-practice modules for arrays and hashing, two pointers, sliding windows, stacks, linked lists, heaps, binary search, DFS, greedy algorithms, dynamic programming, graphs, backtracking, BFS, tries, prefix sums, matrices, intervals, and bit manipulation. Each pattern module progresses through three original problems and compares a baseline with an optimized invariant, explicit time and space costs, a concrete state trace, executable code, edge cases, and interview questions.

The Networking and Operating Systems Foundations track has 12 lessons. It traces requests from application messages through addressing, routing, transport, congestion control, DNS, TLS, and HTTP, then crosses the syscall boundary into processes, threads, scheduling, synchronization, virtual memory, filesystems, storage, namespaces, cgroups, containers, virtualization, resource limits, and observability.

The Low-Level Design and Machine Coding track has 12 lessons. It turns ambiguous prompts into executable requirements, domain models, relationships, interfaces, patterns, state machines, concurrency boundaries, persistence seams, and behavior tests, then applies them to parking-lot, expense-sharing, cache, and rate-limiter interview exercises.

## Assumptions

- V1 is for one learner on one browser, without accounts, cloud synchronization, or a backend.
- All 644 currently mapped lessons are generated ahead of use and checked into `lessons/`; startup only loads completed files.
- The browser does not invoke Codex or an external model API. Lesson generation, regeneration, and learning-record creation happen through Codex in this workspace.
- Progress remains local to the browser, but the learner can export and restore a JSON backup. Hosted synchronization remains a future enhancement.
- Relocation success cannot be guaranteed by a curriculum. Country-specific immigration research begins only after target destinations are selected and must use current official government sources.
