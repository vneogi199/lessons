Slack, Teams and Jira: events are not authorization

An incoming webhook commonly lets your application post into a channel; an events endpoint receives platform events. A bot token authorizes API operations under granted scopes. Treat webhook URLs and tokens as secrets. Interactive buttons submit action IDs and payloads, but an “Approve” label does not prove the user has permission to approve that exact action.

For Slack HTTP requests, verify the signature over the original raw body and timestamp before parsing, then enforce replay protection and workspace/actor scope. Use Slack's verification contract. Acknowledge within the platform's deadline and hand durable work to a queue; deduplicate redelivery using a platform event identity or your application operation key.

import hashlib
import hmac

def valid_slack(secret, body, timestamp, signature, now):
    if (not isinstance(timestamp, str) or not timestamp.isascii()
            or not timestamp.isdigit() or len(timestamp) > 12
            or abs(now - int(timestamp)) > 300):
        return False
    base = b"v0:" + timestamp.encode("ascii") + b":" + body
    expected = "v0=" + hmac.new(secret, base, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)

secret, body, timestamp = b"synthetic-secret", b'{"event":"demo"}', "1000"
signature = "v0=" + hmac.new(secret, b"v0:1000:" + body, hashlib.sha256).hexdigest()
assert valid_slack(secret, body, timestamp, signature, 1001)
assert not valid_slack(secret, body + b" ", timestamp, signature, 1001)
assert not valid_slack(secret, body, timestamp, signature, 1400)

This tests signature/freshness only, not replay storage or platform integration. Limit request bytes before verification and atomically deduplicate accepted events. For an interactive payload, resolve the actor from verified platform identity, look up the pending operation server-side and bind approval to its version/hash and expiry. Ignore client-supplied roles or arbitrary callback URLs.

Teams has distinct webhook/Workflow and bot application paths. Use the currently supported Teams webhook guidance; legacy connector lifecycle and tenant policies affect availability. An Adaptive Card can present actions, but the receiving service still validates identity, action scope and replay. Do not reuse Slack HMAC assumptions for Teams: follow the selected Teams/Bot authentication contract.

Jira lab: request only approved issue fields using the REST API and the caller's permitted project scope. Jira issues and Confluence pages are different resources; choose the appropriate connector. Treat descriptions/comments as untrusted instructions. For ticket creation, validate project, issue type and allowed fields against metadata; Jira Cloud rich-text descriptions may require Atlassian Document Format rather than a plain string. Record the created issue ID in a durable operation ledger. If the response is lost, reconcile before retrying because an arbitrary idempotency header is not automatically honored. See the Jira REST API.

WSDL, Zeep and safe XML boundaries

WSDL describes operations, messages, XSD types, bindings and service endpoints. SOAP carries a namespaced Envelope with optional Header and a Body containing an operation or Fault. SOAP 1.1/1.2 differ in transport details; let the reviewed WSDL binding drive serialization rather than concatenating XML strings. A transport HTTP status and an application SOAP Fault are separate failure signals.

from requests import Session
from zeep import Client, Settings
from zeep.transports import Transport
from zeep.exceptions import Fault
from zeep.helpers import serialize_object

def lookup_legacy(approved_wsdl, ca_bundle, customer_id):
    # The entire WSDL/XSD import closure and endpoints must be approved beforehand.
    with Session() as session:
        session.verify = ca_bundle
        transport = Transport(session=session, timeout=5, operation_timeout=10)
        settings = Settings(strict=True, forbid_dtd=True,
                            forbid_entities=True, forbid_external=True,
                            xml_huge_tree=False)
        client = Client(approved_wsdl, transport=transport, settings=settings)
        # Illustrative operation: use the actual reviewed WSDL's name/types.
        try:
            result = client.service.GetCustomer(CustomerId=customer_id)
        except Fault as exc:
            raise ValueError("legacy service rejected the request") from exc
        return serialize_object(result)

Read Zeep's client/binding behavior and XML parser settings. forbid_external protects XML external entities/DTDs; it is not a complete SSRF policy for WSDL imports or service calls. Pin an approved local WSDL/import bundle or enforce network allowlists, response-size limits and sandboxing. Never accept a user-supplied WSDL URL. Preserve TLS certificate validation and provision mTLS/WS-Security only as required by the service contract.

Use client.create_message to inspect a generated envelope without sending it, then compare namespaces, required elements and XSD order against a fixture. Deserialization can produce Decimal, datetime, lists and nested objects: define a JSON mapping explicitly. Preserve money as decimal strings or integer minor units, dates with timezone policy, null versus absent values and repeated elements as arrays. Do not flatten two same-named elements from different namespaces into one field.

Practice with a synthetic success, a typed business Fault, a malformed XML response, a timeout and an attempted external entity. Classify retryable transport failures separately from invalid input/business denial. Never log complete fault bodies containing PII. Mutation retries require an operation identifier/reconciliation plan; a timeout does not prove the legacy server did nothing. Zeep initialization may perform synchronous WSDL loading even in an async application; configure it at startup outside the request's hot path.

Interview: convert every XML node directly to a JSON key?

No. Attributes, namespaces, order, mixed content, repeated elements and numeric/date types can lose meaning. Define the target schema, validate it and retain source provenance. Conversion is a semantic contract, not merely a format change.

SQL Server/Oracle connections and constrained Text-to-SQL

Use an existing approved driver and encrypted connection with certificate verification. pyodbc uses an installed ODBC driver; python-oracledb has Thin/Thick modes with different prerequisites. SQLAlchemy wraps dialect/driver behavior; it does not make unsafe SQL or excessive database permissions safe. Keep connection secrets outside source and logs, bound pools/timeouts and close sessions promptly.

from sqlalchemy import text

def sqlserver_total(cursor, trusted_tenant, start_date):
    # pyodbc cursor from a TLS-verified, least-privilege connection.
    cursor.execute("SELECT SUM(amount_cents) FROM ai.invoice_view "
                   "WHERE tenant_id = ? AND issued_at >= ?", trusted_tenant, start_date)
    return cursor.fetchone()[0]

def oracle_total(cursor, trusted_tenant, start_date):
    cursor.execute("SELECT SUM(amount_cents) FROM ai_invoice_view "
                   "WHERE tenant_id = :tenant AND issued_at >= :since",
                   {"tenant": trusted_tenant, "since": start_date})
    return cursor.fetchone()[0]

def sqlalchemy_total(connection, trusted_tenant, start_date):
    statement = text("SELECT SUM(amount_cents) FROM ai.invoice_view "
                     "WHERE tenant_id = :tenant AND issued_at >= :since")
    return connection.execute(statement, {"tenant": trusted_tenant, "since": start_date}).scalar_one()

References: pyodbc parameter binding, Oracle binds and SQLAlchemy connections. Bind values, not table/column names. Use an allowlisted query catalog for identifiers and approved views. Configure SQL Server encryption with certificate verification rather than TrustServerCertificate=yes; use the organization's Oracle TLS/wallet configuration. Do not claim a read-only flag on a client replaces database grants.

-- SQL Server recipe for an existing authorized database user, not executed.
CREATE ROLE ai_reader;
GRANT SELECT ON OBJECT::ai.invoice_view TO ai_reader;
ALTER ROLE ai_reader ADD MEMBER ai_application_user;
-- Do not grant broad db_owner, write, DDL or unrestricted EXECUTE privileges.

Provide the LLM a curated schema description: approved tables/views, column types, join keys, units, null semantics, business definitions and examples using synthetic values. Exclude credentials and sensitive sample rows. Retrieve only relevant schema fragments. Tenant predicates must be service/database enforced, not entrusted to the generated query.

Start Text-to-SQL with intent → typed parameters → reviewed query template. If free-form SQL is necessary, parse a supported dialect into an AST, allowlist read constructs/functions/resources, reject multiple statements and cap cost/rows/time; database permissions remain the final boundary. A string beginning SELECT can still invoke expensive or unsafe functions. Use read-only views/RLS and a constrained execution identity. EXPLAIN and a row limit alone do not guarantee cheap execution.

Practice and fallback

Test a quote-containing customer name, cross-tenant request, ambiguous “revenue,” unauthorized column and timeout. Bind the name safely, deny forbidden scope, ask which revenue definition/time range applies, reject the column and return a bounded failure. Do not let a repair loop broaden permissions. Verify the computed result against a reference SQL query and explain null/empty aggregates.

Map Entra groups to application permissions

Azure AD is now Microsoft Entra ID. Authenticate by validating the token with a maintained library: signature/key provenance, allowed algorithm, issuer, audience and lifetime. Authorization then maps trusted identities/claims to application roles and resource access. Decoding a JWT without verification is not authentication; an ID token is not automatically the correct bearer token for your API.

Use stable tenant/object/group IDs rather than display names or email suffixes. The access-token claims reference describes group overage: large memberships can require a separate directory lookup. An omitted groups claim must not mean “all groups.” Use a trusted directory endpoint/client with least privilege rather than blindly following an arbitrary URL in a claim.

# Post-verification policy fixture: NOT a JWT validator.
ROLE_BY_GROUP = {"group-reviewers": "review", "group-readers": "read"}
def roles_for(verified_claims):
    if verified_claims.get("tid") != "tenant-A":
        return set()
    if verified_claims.get("hasgroups") or "groups" in verified_claims.get("_claim_names", {}):
        raise PermissionError("resolve membership through trusted directory first")
    groups = verified_claims.get("groups", [])
    if not isinstance(groups, list) or not all(isinstance(g, str) for g in groups):
        raise PermissionError("invalid group claim")
    return {ROLE_BY_GROUP[g] for g in groups if g in ROLE_BY_GROUP}

assert roles_for({"tid": "tenant-A", "groups": ["group-readers"]}) == {"read"}
assert roles_for({"tid": "tenant-B", "groups": ["group-reviewers"]}) == set()
assert roles_for({"tid": "tenant-A"}) == set()
try:
    roles_for({"tid": "tenant-A", "hasgroups": True})
except PermissionError:
    pass
else:
    raise AssertionError("overage treated as complete membership")

Apply RBAC to actions and document ACL/row-level rules to data. A reviewer role does not grant access to every tenant's document. Filter vector/keyword/graph retrieval before model exposure, recheck parent expansion and scope caches to effective permissions/version. SAML federation follows a different assertion-validation path; reuse the resulting local authorization model, not token parsers.

Provisioned identity test

Create synthetic reader/reviewer/no-access users in an approved tenant. Validate wrong audience, expired token, group removal, group overage and a shared-cache attempt. Measure membership-cache/session revocation delay. Do not report immediate revocation if existing sessions continue to carry earlier authority.

Presidio detection, redaction and reversible masks

Presidio separates detection (entity spans/types/scores) from transformations such as replacement, redaction or encryption. It is associated with the Microsoft Presidio project; the official repository/docs currently redirect to its maintained data-privacy-stack location. Detection depends on language models, recognizers, context and thresholds. “No entities found” is not proof there is no PII.

from presidio_analyzer import Pattern, PatternRecognizer
from presidio_anonymizer import AnonymizerEngine
from presidio_anonymizer.entities import OperatorConfig

def redact_fixture(analyzer):
    # Supply an already configured analyzer with local, approved NLP assets.
    employee = PatternRecognizer(supported_entity="EMPLOYEE_ID", patterns=[
        Pattern(name="employee-id", regex=r"\bEMP-\d{6}\b", score=0.8)
    ])
    analyzer.registry.add_recognizer(employee)
    sample = "Contact alex@example.test about EMP-123456."
    results = analyzer.analyze(text=sample, language="en",
        entities=["EMAIL_ADDRESS", "US_SSN", "CREDIT_CARD", "EMPLOYEE_ID"])
    return AnonymizerEngine().anonymize(text=sample, analyzer_results=results,
        operators={"DEFAULT": OperatorConfig("replace", {"new_value": "[REDACTED]"})}).text

See custom recognizers and anonymizer operators. Add the recognizer once at startup in a real service, not per request. Avoid automatic model downloads; provision assets separately. Use synthetic SSN/card/email positives, invalid/checksum negatives and domain IDs that resemble non-sensitive references. Regexes need boundaries, bounded input and performance testing; a broad pattern may redact useful dates/order numbers.

Irreversible redaction cannot be reversed. Reversible pseudonymization needs an encrypted, short-lived mapping scoped to tenant, user and run. Replace detected values with opaque collision-resistant tokens before the model call. Never place the mapping in model context, traces or a shared cache. After generation, restore only tokens issued for this run and only to an authorized recipient; reject unknown/replayed tokens and re-scan output. Do not globally substitute every token-looking string a model invents. Encryption operators likewise need key management and a release policy.

# Synthetic restoration-policy example, not encryption or a PII detector.
vault = {("tenant-A", "run-1", "opaque-token-7"): "synthetic-private-value"}
def restore(tenant, run, token, may_reveal):
    if not may_reveal or (tenant, run, token) not in vault:
        raise PermissionError("mask cannot be revealed")
    return vault[(tenant, run, token)]

assert restore("tenant-A", "run-1", "opaque-token-7", True) == "synthetic-private-value"
for tenant, run, permission in [("tenant-B", "run-1", True), ("tenant-A", "run-2", True), ("tenant-A", "run-1", False)]:
    try:
        restore(tenant, run, "opaque-token-7", permission)
    except PermissionError:
        pass
    else:
        raise AssertionError("cross-scope reveal")

Evaluate entity/span precision and recall by type/language; define exact versus overlap matching. False-positive rate is FP/(FP+TN) under a defined negative-unit convention, not FP/(TP+FP), which measures false discoveries among detections. Report utility loss when redaction removes needed context. Use holdouts and manual review of misses; do not promise a zero-leak rate from a finite test set.

Interview: a masked answer is safe to log?

Not necessarily. Undetected PII, linkable stable tokens, surrounding context or a leaked mapping can identify someone. Minimize logged content, control retention and test re-identification paths as well as literal PII strings.

NeMo Guardrails and Colang: checks at the right boundary

NeMo Guardrails can apply input, retrieval, dialog, action and output controls. Colang expresses conversational flows; Python actions implement application checks. Pin both library and Colang dialect: 1.0 and 2.x syntax/runtime configuration are not interchangeable. Read the Colang 1 input-rail tutorial and configuration reference.

# Colang 1.0 teaching flow; not a Colang 2.x configuration.
define bot scope refusal
  "I can help with the approved support workflow, not that request."

define flow enforce application scope
  $allowed = execute check_application_scope
  if not $allowed
    bot scope refusal
    stop
colang_version: "1.0"
rails:
  input:
    flows:
      - enforce application scope
  output:
    flows:
      - self check output

The fragment is incomplete until a reviewed check_application_scope action, model configuration and self-check prompt are supplied. In an existing NeMo environment, register the action with LLMRails and load these files through RailsConfig. The action should consult a trusted application route/intent policy; a semantic classifier may help with natural-language topicality but is not an authorization mechanism. Use a fixed refusal for denied scope and test legitimate edge cases to avoid blocking normal support.

A native Python pipeline can enforce deterministic order: validate bytes/schema → authenticate/authorize → detect/redact sensitive data → check topical/safety policy → retrieve authorized material → call model → validate output/grounding → check output PII → release. If a required security dependency fails, return a bounded unavailable/review outcome rather than silently bypassing it. For streaming, decide whether content is buffered until approved; an output rail cannot retract leaked tokens.

Threat model: direct and indirect prompt injection, unauthorized tool use, exfiltration, unsafe output handling, sensitive-data disclosure and resource exhaustion. Separate instructions from retrieved data, restrict network/tool capabilities and revalidate every action in the owning service. A jailbreak detector is one fallible layer; “prevention” is risk reduction with measured residual failures, not a guarantee.

Testing lab: use approved synthetic attack cases or an existing authorized jailbreak-testing library in a sandbox. Include benign lookalikes, multilingual/encoded requests, injected retrieved text, malicious tool results, secret-exfiltration attempts and rail timeouts. Measure unsafe pass rate, benign block rate, task utility and p95 latency. Never run attack suites against third-party production systems without permission.

Interview: input rail passed, but an agent leaked a document

The malicious instruction may have arrived through retrieved content or a tool result, or authorization may have been too broad. Input-only filtering does not cover those boundaries. Trace the data flow, limit capability and check output before release; adding more prompt warnings alone does not fix excessive authority.

Configure and test Bedrock managed guardrails

Separate control-plane creation/versioning from runtime application. Choose region/model support and policy scope, prepare synthetic positive/negative cases, and use a narrowly authorized deployment role. Guardrails do not replace IAM, retrieval ACLs, deterministic business rules or tool authorization.

def create_training_guardrail(bedrock):
    # Paid/external control-plane operation: never called by the local checker.
    return bedrock.create_guardrail(
        name="training-pii-guardrail",
        blockedInputMessaging="Input requires review.",
        blockedOutputsMessaging="Output requires review.",
        sensitiveInformationPolicyConfig={"piiEntitiesConfig": [
            {"type": "EMAIL", "action": "ANONYMIZE"},
            {"type": "US_SOCIAL_SECURITY_NUMBER", "action": "BLOCK"},
        ]},
    )

def check_training_text(runtime, guardrail_id, version, text):
    result = runtime.apply_guardrail(guardrailIdentifier=guardrail_id,
        guardrailVersion=version, source="INPUT", content=[{"text": {"text": text}}])
    return result  # Caller must inspect action and use transformed outputs/policy.

Follow the current Boto3 create_guardrail and apply_guardrail contracts. Provision clients with approved credentials, timeouts and bounded retries. Creation returns identifiers; create and approve a version, then bind the intended version to inference or apply it explicitly at INPUT and OUTPUT boundaries. A draft changing underneath a release makes evaluations hard to reproduce.

On intervention, distinguish blocking from anonymization. Do not forward the original text after a transformed result. If policy requires denial, return the configured safe response; if masking is allowed, use the returned sanitized content and revalidate the rest of the workflow. Record action/category/latency without raw sensitive text. Guardrail availability failure needs an explicit fail-closed or review policy.

Provisioned acceptance test

Test synthetic PII, harmless similar strings, an unsupported language case, a denied topic and a guardrail timeout. Verify both request and response paths and that raw input never reaches downstream logs/model when intervention is required. Compare results across guardrail versions before promoting; a console “enabled” flag is not sufficient evidence.
