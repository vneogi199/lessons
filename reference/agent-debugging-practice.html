Agent operations

Debug an agent from observable evidence

A reviewer approved a ticket, but the application did not create it. Inspect the synthetic event fixture before opening the answers. It records state transitions, tool arguments and policy decisions. It contains no private model reasoning.

First follow the run ID, then parent spans and sequence numbers. Event sequence describes this fixture's observed order. It is not a distributed clock. A production trace needs timestamps and context propagation across queued work, while keeping approval wait separate from machine latency.

1. Which event explains why no ticket exists?

Event 8 denies the write. The approved proposal hash is A, but the current proposal hash is B. Event 7 changed the project after approval. The deny is correct. Present the changed proposal for a new decision; do not bypass the check.

2. Does the first model failure justify retrying ticket creation?

No. Event 3 is a rate-limited model request before the write. Event 4 is a separate successful model attempt. Neither proves that a remote ticket write occurred. Retry decisions depend on the operation and evidence of its outcome.

3. Can you report the total billed cost from this trace?

No. Event 3 has unknown usage. Event 4 supplies token counts, but a dated model price and billing categories are still needed. Show missing cost evidence explicitly. Zero is not a substitute for unknown usage.

4. Does retrieval success establish permission at release time?

No. Event 2 records ACL revision 11 and source version v3 at retrieval. Recheck current access before exposing an answer or executing a tool, especially after a human wait. A document or membership could have changed.

5. What happens if the ticket service times out after accepting a write?

Record an uncertain outcome under the durable operation ID. Reconcile against the remote service before another create attempt. A transport timeout alone does not prove no effect. The current fixture never reaches that write.

Collect only useful evidence

Record safe tool names, validated argument structure, operation IDs, result status, policy revision, retry attempt and source IDs. Use synthetic or redacted arguments in shared debugging material. Full document text, credentials and unrestricted tool results do not belong in routine traces.

A model's short explanation can be another output to evaluate. It is not authoritative evidence of why a policy decision occurred. Use the deterministic policy result and state history. Do not request or store hidden chain-of-thought as a debugging requirement.

Acceptance for this exercise: identify the changed field and denial, distinguish model retry from tool retry, name the missing billing evidence and propose a new approval rather than an unchecked write.
