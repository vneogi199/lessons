Pandas: build a trustworthy analytical pipeline

Use Pandas for labeled, in-memory tabular transformations: inspect exports, clean records, join reference data and analyze evaluation results. A Series is a one-dimensional labeled array; a DataFrame is a collection of columns sharing a row index. Each column has a dtype. The index is an alignment mechanism, not an automatically unique database key.

Work through the following stages in order. All blocks marked Pandas share one Python session. From the repository root, run python3 scripts/check-data-preparation.py for syntax, links and the terminal fixture. Add --run-pandas only in an environment that already has Pandas; it will not install it. The tangible result is a validated, repeatable regional spending report with checks for common silent errors.

1. Inspect shape and schema before computing

Use head() to sample, shape for dimensions, dtypes and info() for types/null counts, and describe() for a first distribution check. A sample is not a whole-file validation. Check column names, key uniqueness, ranges and missingness explicitly. Business IDs such as “001” are strings even when they contain only digits.

from io import StringIO
import pandas as pd

orders = pd.read_csv(StringIO(
    "order_id,customer,amount_cents,created_at\n"
    "o1,001,125,2026-01-01T10:00:00Z\n"
    "o2,001,250,2026-01-02T10:00:00Z\n"
    "o3,002,,2026-01-02T11:00:00Z\n"
    "o4,003,500,2026-01-03T10:00:00Z\n"
), dtype={"order_id": "string", "customer": "string", "amount_cents": "Int64"})
assert orders.shape == (4, 4)
assert orders["customer"].iloc[0] == "001"
assert orders["order_id"].is_unique
assert str(orders["amount_cents"].dtype) == "Int64"
assert orders["amount_cents"].isna().sum() == 1

read_csv can select columns with usecols, enforce dtypes and iterate with chunksize. Define encoding, delimiters and missing-value conventions; default NA recognition may turn a legitimate code such as “NA” into missing data. Strict parsing rejects malformed integers; use a quarantine policy when partial acceptance is required. CSV has no durable schema. Parquet preserves more type information and supports column selection, but needs an available engine and still needs schema checks. See CSV input options.

Predict: should a missing amount become zero?

Not by default. Zero is a known amount; missing is unknown. Filling it with zero changes averages and can hide ingestion defects. This report will preserve the unknown, count it and show that its total includes only known amounts.

2. Select by label or position deliberately

loc selects labels and boolean masks; iloc selects integer positions. Label slices include their end label; position slices exclude the stop. A Series mask aligns by index labels. Use parentheses around comparisons with & and |, not Python's scalar and/or. Reduce a Series with any() or all() before using it as a single condition. See indexing.

expensive = orders.loc[orders["amount_cents"].ge(250).fillna(False), ["order_id", "amount_cents"]]
assert expensive["order_id"].tolist() == ["o2", "o4"]
assert orders.iloc[:2]["order_id"].tolist() == ["o1", "o2"]

# Assignment aligns by labels, not by the visible order of values.
aligned = pd.DataFrame(index=["a", "b"])
aligned["score"] = pd.Series([10, 20], index=["b", "a"])
assert aligned["score"].tolist() == [20, 10]

Using to_numpy() bypasses label alignment; do so only when positional correspondence is an explicit invariant. After joins and filtering, labels may be duplicated or nonconsecutive. reset_index(drop=True) changes labels; it does not repair a wrong relationship between rows.

3. Update the intended object

With Pandas 3.x Copy-on-Write, derived objects behave independently when modified. Do not rely on chained assignment such as df[mask]["amount"] = 0 to change the parent. Use one assignment: df.loc[mask, "amount"] = 0. Avoid silently mutating a caller's frame in reusable functions. See Copy-on-Write.

corrected = orders.copy()
corrected.loc[corrected["order_id"].eq("o1"), "amount_cents"] = 150
assert corrected.loc[0, "amount_cents"] == 150
assert orders.loc[0, "amount_cents"] == 125
Interview: why did the row count stay correct but the scores become wrong?

Inspect the indexes on both sides of the assignment. A correctly sized Series can still align to the wrong labels or introduce missing values. Compare keys and labels before converting to positional arrays. Length equality is not correspondence.

4. Clean values without hiding evidence

Nullable Int64 and boolean preserve missing values; their capitalization/type names matter. Missing markers depend on dtype: pd.NA, NaN and NaT are not interchangeable scalar values. Use isna(), not equality with a missing marker. Many reductions skip missing values; an all-missing sum can become zero unless you require observations with min_count=1. See missing-data semantics.

raw = pd.Series(["125", "bad", None], dtype="string")
parsed = pd.to_numeric(raw, errors="coerce")
invalid = raw.notna() & parsed.isna()
assert invalid.tolist() == [False, True, False]
assert pd.isna(pd.Series([pd.NA], dtype="Int64").sum(min_count=1))

names = pd.Series(["  ALICE ", None], dtype="string")
assert names.str.strip().str.casefold().iloc[0] == "alice"
assert names.str.contains("alice", case=False, regex=False, na=False).tolist() == [True, False]

Keep the original value, source row and rejection reason. errors="coerce" is useful only if coerced rows are counted or quarantined; otherwise it quietly converts corruption into missing data. Validate finite numbers, bounds and units after parsing. For currency, use validated integer minor units or an appropriate decimal representation—not binary floats plus rounding as a repair strategy.

Use duplicated(subset=...) to inspect repeated business keys. Dropping duplicates blindly can discard legitimate repeated events. For “latest version wins,” define a stable sort on effective time plus a deterministic tie-breaker and reject unresolved conflicts. Keep tenant keys in deduplication and joins. Do not log sensitive raw rows merely to debug them.

5. Join with a cardinality contract

Before merging, state whether the relationship is one-to-one, many-to-one or many-to-many. A duplicated lookup key multiplies rows and money without raising an error unless you validate it. Pandas can match null join keys to each other, unlike ordinary SQL equality joins. Reject or separate null keys when that would be incorrect. See merge validation and null behavior.

customers = pd.DataFrame({"customer": ["001", "002", "003"],
                          "region": ["east", "east", "west"]}).astype("string")
assert orders["customer"].notna().all()
enriched = orders.merge(customers, on="customer", how="left",
                        validate="many_to_one", indicator=True)
assert len(enriched) == len(orders)
assert enriched["_merge"].eq("both").all()
assert enriched["amount_cents"].sum() == 875
try:
    orders.merge(pd.concat([customers, customers.iloc[:1]], ignore_index=True),
                 on="customer", validate="many_to_one")
except pd.errors.MergeError:
    pass
else:
    raise AssertionError("duplicate lookup keys must fail")

An inner join can silently drop unmatched orders; a left join plus indicator=True makes the missing lookup visible. Compare row counts, key coverage and conserved totals, not just whether the join completed. concat appends/aligns objects rather than matching business relationships. Accumulate frames in a list and concatenate once instead of repeatedly copying a growing frame. See combining frames.

Predict: duplicate customer 001 without validation—what total appears?

Orders o1 and o2 each match twice. Their 375 cents are duplicated, raising the known total from 875 to 1,250. The missing amount remains missing. Aggregating afterward does not undo this relational error.

6. Aggregate or transform?

agg reduces a group to summaries; transform returns results aligned to the original rows. size counts rows, while column count counts nonmissing values. Set dropna deliberately for missing group keys and observed for categorical groups rather than relying on version defaults. See grouping.

report = enriched.groupby("region", dropna=False, observed=True).agg(
    rows=("order_id", "size"), known_amounts=("amount_cents", "count"),
    known_cents=("amount_cents", "sum"),
).sort_index()
assert report.loc["east", "rows"] == 3
assert report.loc["east", "known_amounts"] == 2
assert report.loc["east", "known_cents"] == 375
assert report.loc["west", "known_cents"] == 500
enriched["regional_known_cents"] = enriched.groupby("region")["amount_cents"].transform("sum")
assert enriched["regional_known_cents"].tolist() == [375, 375, 375, 500]

These totals describe known amounts, not complete revenue. If a group has no known amounts, explicitly select an all-missing policy; use a separate group sum with min_count=1 when unknown must remain unknown. Prefer built-in reductions to flexible groupby.apply callbacks when possible: their shape and performance are easier to reason about.

7. Reshape without accidental aggregation

melt converts wide measure columns to long variable/value rows. pivot requires a unique value for each index/column combination; pivot_table aggregates duplicates using a chosen function. Never use an aggregation merely to suppress a duplicate-key error. explode expands list cells and repeats surrounding values; totals can inflate if you sum repeated order amounts. See reshaping.

wide = pd.DataFrame({"model": ["baseline", "candidate"], "correct": [8, 9], "wrong": [2, 1]})
long = wide.melt(id_vars="model", var_name="outcome", value_name="count")
assert len(long) == 4
restored = long.pivot(index="model", columns="outcome", values="count")
assert restored.loc["candidate", "correct"] == 9
Interview: pivot fails after an event replay—use pivot_table?

First distinguish duplicate delivery from multiple valid observations. Deduplicate by event identity if it is a replay; aggregate only if the business measure requires it. A mean that makes the error disappear may hide a broken ingestion contract.

8. Dates, rolling windows and leakage

Parse known formats and choose a timezone policy. utc=True normalizes offset-aware timestamps; interpreting naive timestamps as UTC is correct only if the source contract says UTC. Local civil time needs explicit localization and a policy for ambiguous/nonexistent daylight-saving times. Sort before rolling, cumulative or as-of operations, and isolate entities/tenants before constructing temporal features. See time-series operations.

timed = orders.copy()
timed["created_at"] = pd.to_datetime(timed["created_at"], utc=True, errors="raise")
daily = timed.set_index("created_at")["amount_cents"].resample("D").sum(min_count=1)
assert daily.tolist() == [125, 250, 500]
rolling = daily.rolling(window=2, min_periods=2).sum()
assert pd.isna(rolling.iloc[0])
assert rolling.iloc[1:].tolist() == [375.0, 750.0]

A two-row window is not necessarily two calendar days; an offset window such as "2D" selects by elapsed time and boundary rules. resample changes time buckets; rolling computes overlapping summaries. In prediction tasks, exclude future information: sort, group, shift past values as needed, then compute features. Check exact timestamps and availability times, not only event dates.

9. Performance starts with less data

Read only necessary columns/rows, inspect memory_usage(deep=True), and estimate peak memory including join output, temporary arrays and copies. Categoricals can help repeated low-cardinality values but are not a universal saving. A vectorized numeric operation avoids many Python-level calls; apply(axis=1) is not automatically vectorized, and string operations still need profiling. Pandas is not an out-of-core engine. See scaling guidance.

Chunked CSV processing works well for mergeable summaries. Combine each chunk's sum and count to calculate a global mean; averaging chunk means gives unequal-sized chunks the wrong weight. Global deduplication, joins and exact quantiles may require state proportional to the dataset. Push filtering/aggregation into SQL or use DuckDB for larger analytical scans rather than loading everything into a DataFrame.

Example: chunk A has two observations totaling 100 and chunk B has eight totaling 800. The global mean is 900/10 = 90, not the mean of 50 and 100, which is 75. Save this as a regression case before implementing chunked reporting.

10. Make the result reproducible

Extract transformations into functions with explicit input/output schemas. Keep source revision, library version, rejected-row counts and processing parameters with the artifact. Tests should check values, dtypes, index/column names and ordering. Use tolerances intentionally for floating-point outputs; money in minor units should normally match exactly. See assert_frame_equal.

# Declare nullable integer output columns rather than inherit reduction dtypes.
report = report.astype({"rows": "Int64", "known_amounts": "Int64", "known_cents": "Int64"})
expected = pd.DataFrame({"rows": [3, 1], "known_amounts": [2, 1], "known_cents": [375, 500]},
                        index=pd.Index(["east", "west"], dtype="string", name="region"))
expected = expected.astype({"rows": "Int64", "known_amounts": "Int64", "known_cents": "Int64"})
pd.testing.assert_frame_equal(report, expected)

PDF processing: extract evidence, preserve its location

A PDF describes page layout, not necessarily a clean sequence of paragraphs. Digitally generated pages may contain extractable text; scanned pages may only contain images. OCR recognizes text from pixels and can introduce errors. Existing OCR layers can also be wrong. Neither an empty extraction nor a nonempty one proves the document was processed correctly. See pypdf's extraction limits.

For an AI ingestion workflow: validate the upload → isolate parsing → extract per page → flag weak extraction for OCR/review → normalize cautiously → chunk with page/source metadata → index. Preserve the original document, its content hash/version, page number and extraction method. Multi-column reading order, tables, headers and hyphenation need inspection; flattening a table can detach a price from its product.

from pypdf import PdfReader

def extract_pages(path, document_version):
    # Trusted local path supplied by upload storage, not a model-selected path.
    reader = PdfReader(path)
    if reader.is_encrypted:
        raise ValueError("encrypted document requires an approved password workflow")
    if len(reader.pages) > 100:
        raise ValueError("page limit exceeded")
    for page_number, page in enumerate(reader.pages, start=1):
        text = page.extract_text() or ""
        yield {"document_version": document_version, "page": page_number,
               "text": text, "method": "text-extraction",
               "needs_review": not text.strip()}

This adapter does not perform OCR or sandbox parsing. Limit upload bytes, parser time, memory and output size outside the worker; a page-count check occurs after opening the file and cannot prevent all resource exhaustion. Treat embedded URLs, attachments and extracted instructions as untrusted. Never execute them. Enforce tenant permissions before retrieval and remove derived chunks when a document is revoked.

Brief exercise: use an approved text PDF, a scan and a two-column/table PDF. Compare extracted text with each page, record missing text and reading-order errors, and verify a cited answer against the original page. OCR should be a routed fallback, not an assumption that every PDF is an image.

Check: a scan returns no text—did it contain no information?

No. It may contain only images. Mark it for OCR or manual review and keep the page provenance. A generated answer must not fill the gap from guesswork. Conversely, nonempty text still needs quality checks before it becomes evidence.

Quote paths and understand streams

Quote variable expansions: "$path" preserves spaces as part of one argument. Single quotes preserve literal text; double quotes allow variable expansion. A pipe passes standard output (descriptor 1) to the next program's standard input (0); standard error (2) is separate. > creates/truncates a file, >> appends, and 2> redirects errors. Redirection order matters. Never redirect output into the same file being read. See Bash redirections.

Exit status zero conventionally means success. Read $? immediately after the command. a && b runs b only after a succeeds; a || b runs b after a fails. Bash pipelines normally return the last command's status; set -o pipefail makes earlier failures visible. A no-match grep returns 1, which may be an expected result rather than an operational error. See pipeline semantics.

# Safe Bash exercise: no files written and no network calls.
set -o pipefail
label='customer export.csv'
test "$label" = 'customer export.csv' || exit 1
count=$(printf '%s\n' ERROR INFO ERROR | grep '^ERROR$' | wc -l)
test "$count" -eq 2 || exit 1
if false | true; then
    printf '%s\n' 'Unexpected pipeline success' >&2
    exit 1
fi
printf '%s\n' 'Terminal fixture passed'
Predict the output before running

The error count is two. Quoting preserves the filename as one value. With pipefail enabled, false piped into true reports failure, so the unexpected-success branch is not entered. The final line is “Terminal fixture passed.” Without pipefail, that branch would run and exit with status 1.

Change files and processes carefully

In a scratch directory, mkdir practice creates a directory, touch practice/notes.txt creates an empty file or updates its timestamps, cp -i source.txt copy.txt copies with an overwrite prompt, and mv -i old.txt new.txt moves/renames. Inspect exact targets first. rm -i practice/notes.txt asks before permanent removal; it is not a trash operation. rmdir practice removes only an empty directory. Avoid recursive deletion while learning.

chmod u+x script.sh gives the owner execute permission; it does not fix every permission problem. Directory execute permission means traversal. Do not solve permission errors with 777 or sudo by default. Ctrl-C usually interrupts a foreground process; kill -TERM 1234 requests termination of a specifically verified PID. Never copy an example PID without checking the actual process. SIGKILL prevents cleanup and is a last resort.

Environment example: APP_MODE=development python3 app.py sets a value for that command. Do not print the whole environment when it may contain credentials. An authorized ssh user@host opens a remote session; verify the host-key fingerprint through a trusted channel, use approved credentials and confirm the remote hostname/path before changing anything. These are optional command references, not actions performed during this lesson.

Integrate blocking work with asyncio

A synchronous SDK or file operation called directly inside async def still blocks the event-loop thread. Offload genuinely blocking I/O when no suitable async API exists. For a senior interview, explain where the work runs, who owns its lifetime and what happens when the caller times out—not just where to put await.

ChoiceSubmission and contextUse
await asyncio.to_thread(fn, arg)Returns a coroutine; work submits when it runs. Copies the current contextvars context into the worker.Simple blocking I/O using the loop's default executor.
loop.run_in_executor(pool, fn, arg)Submits immediately and returns an asyncio Future. Explicitly copy context when needed.Separate pool ownership/capacity for a particular dependency.
Native async clientCooperatively waits without allocating a thread per blocked call.Prefer when the dependency provides a suitable async interface.

See Python's to_thread, executor integration and ThreadPoolExecutor references. Pass the callable, not its result: run_in_executor(pool, fetch, url), not run_in_executor(pool, fetch(url)). Use functools.partial for keyword arguments. Do not call a concurrent Future's blocking result() on the loop; await the asyncio wrapper.

Predict context propagation, exceptions and cancellation

This standard-library example performs no network or filesystem work. It demonstrates an explicitly owned pool, request context, error propagation, and a worker that remains alive after its asyncio Future is cancelled. The synchronization handshakes avoid guessing execution order from sleeps.

import asyncio
from concurrent.futures import ThreadPoolExecutor
from contextvars import ContextVar, copy_context
import threading

request_id = ContextVar("request_id", default="unset")

def fail():
    raise ValueError("upstream rejected the request")

async def exercise(pool):
    loop = asyncio.get_running_loop()
    token = request_id.set("request-17")
    try:
        assert await asyncio.to_thread(request_id.get) == "request-17"
        context = copy_context()  # Fresh copy for each independent submission.
        assert await loop.run_in_executor(pool, context.run, request_id.get) == "request-17"
        try:
            await loop.run_in_executor(pool, fail)
        except ValueError as error:
            assert str(error) == "upstream rejected the request"
        else:
            raise AssertionError("worker exception was lost")

        release = threading.Event()
        finished = threading.Event()
        started = loop.create_future()
        effects = []

        def worker():
            loop.call_soon_threadsafe(started.set_result, None)
            try:
                if release.wait(timeout=5):
                    effects.append("worker completed")
            finally:
                finished.set()

        future = loop.run_in_executor(pool, worker)
        try:
            await asyncio.wait_for(asyncio.shield(started), timeout=2)
            future.cancel()
            try:
                await future
            except asyncio.CancelledError:
                pass
            else:
                raise AssertionError("expected cancellation")
            assert future.cancelled()
        finally:
            release.set()  # Cancellation did not release or kill the thread.
            assert await asyncio.to_thread(finished.wait, 6)
        assert effects == ["worker completed"]
    finally:
        request_id.reset(token)

# Pool shutdown waits outside the event loop, after the exercise drains its work.
with ThreadPoolExecutor(max_workers=2) as pool:
    asyncio.run(exercise(pool))
Compare your prediction

Both context-aware calls see request-17; the worker's ValueError is raised at await. Cancelling the asyncio Future changes what the caller observes, but the already-running thread still completes after release. call_soon_threadsafe hands the notification back to the loop rather than modifying an asyncio Future directly from a worker. No remote cancellation is demonstrated.

Bound admission, not only thread count

max_workers=8 limits executing threads, not all submitted jobs or waiting request objects. Bound admission before submission, use a finite queue or fixed set of consumer tasks, and define overload rejection. A semaphore around await is insufficient if cancellation releases the permit while its thread continues working. Track underlying completion when capacity represents actual running work. Do not submit an entire unbounded document corpus at once.

Give blocking libraries their own connection/read deadlines. Cooperative cancellation needs a stop signal that the worker checks; it cannot interrupt an arbitrary blocked library call. Shutdown should stop admission, drain or cancel queued work, then wait for running work within a documented operational policy. shutdown(cancel_futures=True) can cancel pending jobs, not already-running ones. Avoid nested waits on the same saturated pool and synchronous pool shutdown inside a live request handler.

Thread safety remains your responsibility: use per-call clients or documented thread-safe sharing. Context propagation is for correlation, not a substitute for authorization. For CPU-heavy pure Python under a conventional GIL-enabled build, consider a process pool or durable worker instead; native extensions that release the GIL and free-threaded builds change the performance tradeoff.

Interview drill: requests time out, but downstream traffic keeps growing. Why?

Cancelled callers may leave their threads running while retries admit more work. Measure queue depth, active jobs, actual completions, dependency deadlines and retry volume. Bound admission, preserve accounting until completion and use idempotency for effects. A shorter HTTP timeout alone does not solve the overload.

Linux users, groups and permissions in practice

A service runs with numeric user and group identities; names are directory-service mappings. Distinguish the primary group from supplementary groups. File access depends on the process's current credentials, not just what an administrator has most recently written into the account database. Read the maintained manuals for useradd, usermod and groupadd.

The following walkthrough is for an existing disposable Linux VM with authorized sudo access and these tools already present. It is not a script to run on this computer or a shared server. No users, groups, permissions or services were changed during authoring. If no lab exists, complete the predictions and offline exercise instead.

Inspect, create a scoped identity, then test

Start with id and groups for the current process identity. Use getent passwd lesson-reader, getent group lesson-docs and ls -ld /srv/lesson-access to check the proposed names/path. Confirm that they are unused and that lookup failures are not directory-service outages. Stop if a name or path already exists; do not adopt an unknown account or change its ownership.

Read echo $? immediately after each test: 0 means true, 1 means false. A sudo/setup error is not evidence of the intended denial; inspect diagnostics. The outsider supplies a negative control. A nologin shell prevents ordinary shell login, not an administrator from running an authorized test command as that identity.

-aG appends supplementary membership. Using -G without -a can replace the existing supplementary list. Existing sessions/services retain their process credentials: create a new authorized session or restart the affected service through its normal procedure, then check its actual groups. id username shows account lookup information; id inside a process shows that process's identity. Removing membership likewise does not instantly revoke old processes or already-open file descriptors.

Read the permission bits before reaching for sudo

Each owner/group/other digit combines read=4, write=2 and execute=1. Mode 0640 gives owner read/write and group read. For directories, read lists names, execute permits traversal, and write plus execute permits entry creation/removal subject to further restrictions. File write permission is not what controls deleting its directory entry. Mode 2750 also requests setgid group inheritance for newly created children; it does not grant group write access.

Diagnose every parent directory, effective ownership, supplementary membership, ACLs and mandatory-access controls such as SELinux/AppArmor. A read-only mount can also block writes. Never fix uncertainty with chmod 777 or recursive chown. A service-specific group is not the same as granting membership in a privileged administration group. See Linux's file-mode rules and path permission checks.

Without a default ACL, creation permissions follow requested mode AND NOT umask, not decimal subtraction. Umask affects new objects, not existing permissions; a default ACL changes the calculation. See the Linux creation-mask rules. Predict these results before running the purely arithmetic fixture:

# ponytail: mode-bit model only; verify real access under the target Linux identity.
def created_mode(requested, mask):
    assert 0 <= requested <= 0o777 and 0 <= mask <= 0o777
    return requested & (~mask & 0o777)

assert created_mode(0o666, 0o027) == 0o640
assert created_mode(0o777, 0o027) == 0o750
assert created_mode(0o600, 0o027) == 0o600  # A mask never adds permission.

def selected_bits(mode, is_owner, in_group):
    shift = 6 if is_owner else 3 if in_group else 0
    return (mode >> shift) & 0o7

assert selected_bits(0o640, False, True) == 4
assert selected_bits(0o640, False, False) == 0
assert selected_bits(0o047, True, True) == 0  # No fallback to more generous bits.
Worked feedback and interview failure case

A usual 0666 file request with umask 027 becomes 0640; a 0777 directory request becomes 0750. The selected owner/group/other class is not a union of all three. The fixture deliberately omits ACLs, capabilities, root privileges and path traversal, so it is not a security validator. If a new group member still cannot read, inspect the failing process's groups and every directory in the path before changing the file mode.

For offboarding, inventory running processes, credentials, sessions and owned data. Locking a password alone does not revoke SSH keys, other authentication methods or existing sessions. In this exercise, retain the lab for review or dispose of the VM through its approved lifecycle; do not practice destructive user/home deletion on a shared machine.
