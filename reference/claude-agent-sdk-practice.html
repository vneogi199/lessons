Claude Agent SDK production boundaries

The SDK runs an agent with a tool-capable runtime. A plain model API call returns a response; this runtime can perform several model and tool steps before it finishes. That difference changes how you handle permissions, workspaces, cancellation and billing.

A calculator returns a number. An assistant with a calculator, file access and a terminal can change its surroundings. First decide which capabilities the task actually needs. The first exercise only extracts fields from a synthetic sentence and has no tools.

Start with a text-only contract

The supplied configuration removes all tool definitions, disables project/user setting sources and sets a turn limit, a call budget and a structured output schema. It does not start the runtime. In an approved existing environment, pass those options to query() and consume its message stream. Record the installed SDK and CLI versions before running. See the Python reference.

Use query() for an isolated invocation. A stateful client or an explicitly resumed session suits a continuing conversation. Keep the session ID under server control and bind it to the authenticated tenant and workflow. Never accept an arbitrary client's session ID as permission to resume stored context. Consult session behavior.

Understand the permission order

allowed_tools pre-approves tools; it is not an exclusive list of available tools. A callback may not see a tool call already approved by an earlier rule. dontAsk denies calls that would prompt, not every unlisted capability. Use explicit tool removal and the documented permission flow. Checks that must run for every call belong in the appropriate pre-tool hook and in the executor itself. Read the permission rules before enabling any tool.

For phase two, expose one custom read-only tool, get_fixture_limit. It takes an account ID, while its server gets tenant identity from trusted context. Reject unknown fields and out-of-scope accounts. Return only the limit and source version. Keep Bash, arbitrary file access, writes and unrelated MCP servers unavailable. The new tool is a separately reviewed exercise; the supplied configuration remains text-only.

Put authority outside the workspace

A working directory is not an OS sandbox. A child process can inherit environment variables and reach permitted network destinations. Run any live exercise in a disposable workspace with no repository secrets, host socket or broad cloud credentials. Use a non-root identity, resource limits, read-only mounts where possible and restricted egress. Approve the minimum credential needed for the model connection. Consult secure deployment guidance.

Prompts such as “do not write files” are not enforcement. Verify the effective capability set at startup. Attempt a denied write against a disposable fixture and assert no file changed. Check subprocess exit and clean up the session on cancellation. A client timeout alone is not evidence that the child stopped.

Treat terminal results as data

Do not equate the last text message with successful completion. Inspect the final result, error indicators and terminal reason supported by your installed release. Handle turn exhaustion, budget exhaustion, transport errors, missing output and schema rejection separately. Validate business meaning after shape: a positive quantity can still exceed the risk limit.

The SDK's call budget is a client-side estimate, not a guaranteed account-wide invoice ceiling. Resumed and parallel work needs an application-owned budget ledger. Keep unknown spend visible. Never add the cumulative result cost to each per-attempt charge if both describe the same billing.

  2. Ask for a file write. Confirm it cannot execute and classify the terminal response.
  3. Supply malformed or missing structured output through a fake adapter. Expect rejection.
  4. Attempt cross-tenant session resume. Reject it before starting the SDK.
Interview: can allowed_tools=["Read"] guarantee read-only execution?

No. It controls pre-approval. Review available tools, deny rules, settings, permission mode and runtime isolation. An executor must check every requested resource, including calls made without model mediation.

MCQ: the SDK returns valid JSON with an excessive quantity. Choose: A) accept schema-valid data; B) reject the business violation.

B. Structural validation does not establish business authorization or current risk capacity.
