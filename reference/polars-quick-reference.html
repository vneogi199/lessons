Polars practice guide

Start after Python collections and basic SQL. Each lesson includes a small fixture, predicted results, assertions, a changed constraint and interview questions. Examples need an existing Polars environment. They have static syntax checks, not a claim of runtime verification. Record your installed version and check its documentation before using an API.

A practical study sequence

  1. 0645–0647: Typed columns, expressions and missing values. Preserve identifiers and separate rejected input from missing input.
  2. 0648–0650: Parse RFQs, normalize timestamps and select the latest record. Define a tie policy before deduplicating.
  3. 0651–0653: Aggregate, calculate windows and validate joins. Explain the output row grain after each operation.
  4. 0654–0657: Match historical quotes, form time windows, flatten nested data and reshape tables. Check that future information cannot enter a historical result.
  5. 0658–0661: Read files, inspect lazy plans and compare streaming with native expressions. Identify what must still fit in memory.
  6. 0662–0665: Test transformations, preserve financial units, compare SQL and build the risk-reporting capstone.

At 6–8 hours per week, aim for two or three lessons with practice. Repeat a failed exercise before adding more lessons. This is a suggested pace, not a completion guarantee.

Operations to recognize

  • select chooses output expressions. with_columns retains other columns. Chain calls when an expression needs a newly created alias.
  • filter retains rows whose predicate is true. A null predicate does not retain a row. Write the intended missing-value policy.
  • cast(..., strict=False) can turn invalid input into null. Preserve the original value so invalid and absent inputs remain distinguishable.
  • is_null and is_nan test different conditions. fill_null does not replace floating-point NaN.
  • group_by(...).agg(...) reduces groups. over(...) can map a group calculation back to input rows.
  • sort(...).unique(..., keep="last") needs a complete ordering rule to select a meaningful latest record. Sort the final result separately when display order matters.
  • join(..., validate="m:1") checks the intended right-key uniqueness. An anti join exposes missing reference keys.
  • join_asof(..., strategy="backward", tolerance=...) needs sorted time keys. Also define when the quote became available.
  • group_by_dynamic creates time buckets. It is not a durable event-stream processor with watermarks and replay.
  • explode changes row grain. Reconcile totals before and after expanding lists.
  • scan_parquet starts a lazy file query. read_parquet(...).lazy() cannot undo the preceding eager read.
  • explain shows a query plan. collect(engine="streaming") still returns a materialized result. A sink can avoid collecting that result into Python.
  • polars.testing.assert_frame_equal compares results. Assert schema, order and tolerances according to the contract rather than ignoring differences automatically.

Senior interview checks

For any transformation, state the row grain, key, schema, null policy and output ordering. Then identify one failure case and one invariant. A faster result is useful only if it satisfies the same contract.

Benchmark equivalent outputs on representative data. Report input size, file layout, library version, machine resources, elapsed time and peak memory. Separate cold and warm reads. Do not assume lazy execution, streaming or a Python UDF is always faster.

Polars computes a report; it does not provide transactional risk reservation. Two concurrent traders can both pass a stale limit check. Enforce an irreversible booking decision in an authoritative transactional system.

Primary documentation

  • Expressions and contexts: understand how an expression becomes a computation.
  • Joins: choose cardinality and missing-key behavior.
  • Lazy optimization: inspect pushdown and optimization boundaries.
  • Streaming: distinguish batch execution from bounded total memory.
  • Migration from Pandas: replace index and row-loop assumptions with explicit columns and expressions.
