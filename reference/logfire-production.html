Logfire for a private FastAPI service

Logfire lets you inspect application traces and related telemetry. A trace represents one operation across components. A span records one timed part of that operation. Start by tracing a synthetic RFQ request, then separate validation, retrieval and response preparation.

A parcel has one tracking number and several scans. The trace ID is the tracking number. A span records a stage such as sorting or delivery. A missing scan does not prove that a stage took zero time.

Add instrumentation deliberately

The supplied adapter configures Logfire with remote sending disabled and no console exporter. It adds FastAPI instrumentation and one manual span around deterministic work. It requires an existing compatible FastAPI, Pydantic and Logfire environment. No telemetry backend or package installation is supplied.

       └─ later: authorized database read or model attempt
HTTP response: synthetic review result

FastAPI instrumentation can record parsed arguments and validation errors. The adapter's request-attribute mapper drops both. Header capture is disabled. This does not remove every possible sensitive attribute: URLs, exception text and other instrumentors still need review. Use synthetic identifiers in the exercise. See the FastAPI integration.

Choose attributes before sending data

Use bounded fields such as workflow version, stage, outcome and model alias. Keep raw RFQs, documents, prompts, cookies, authorization headers and connection strings out of spans. An opaque user ID is still personal data if you can link it back to a person.

Logfire supports scrubbing sensitive data. Treat automatic scrubbing as one layer. Write an allowlist for exported fields and a test that inserts a synthetic secret into every input path. Inspect the resulting local export before enabling remote sending. Account for stack traces and validation errors as well as normal responses. Scrubbing documentation explains the built-in behavior.

Connect spans without duplicating them

Use one instrumentation owner for each library. Instrumenting the same FastAPI app through two integrations can create duplicate spans. Carry trusted trace context through your queue adapter; use a link when asynchronous work is related but not a direct synchronous child. Do not treat incoming trace baggage as authenticated identity. The OpenTelemetry trace model explains parent and link relationships.

Choose a project/environment boundary before enabling export. Load credentials through the deployment's secret mechanism. Never put a write token in a browser bundle. Record service name and deployment version so a slow trace can be tied to the release that produced it. Configure bounded queues and shutdown flushing; telemetry failure must not stall business requests indefinitely. Consult Logfire configuration for the installed release.

Read one slow request

Suppose a synthetic request takes 900 ms: admission wait 300, database 80, model attempt 450, validation and response 70. Inspect the trace for where time was spent before changing the prompt. If the model was retried, keep both attempts. A final success must not erase the first attempt's duration or billable usage.

Sampling reduces retained traces. It can bias a latency estimate if you retain slow traces preferentially. Use unsampled request metrics for service percentiles, and traces to investigate individual requests. Check sample count, error rate and unknown cost beside a latency chart.

  1. Send a valid synthetic request and one malformed request in an existing test environment.
  2. Capture spans with a local test exporter. Assert that neither input values nor the synthetic secret appear.
  3. Add a scripted delay. Identify its stage without opening request contents.
  4. Disable the exporter. Confirm the request still follows the defined availability policy.
Interview: can scrubbing guarantee that no personal data leaves the service?

No. Custom formats, exception messages and new instrumentors can introduce paths the rules miss. Minimize collection first, test exports, restrict access and set retention. Document remaining risks.

MCQ: sampled slow traces show p95=8 seconds. Choose: A) use it as fleet p95; B) inspect unsampled request histograms.

B. The sampling rule changes the observed population. The traces are useful for diagnosis, but they do not establish the service percentile.
