How image features reach a language model

Imagine cutting a picture into small squares. Each square becomes a list of numbers. A vision encoder lets squares exchange information, so a square can represent part of a larger object. A trained connector then makes those features usable by a language model.

This exercise uses an invented small architecture to make shapes easy to count. It is not a configuration for a real checkpoint. Real processors can resize, tile or crop images and add special tokens.

For one patch feature x, the projector computes xW + b. This changes feature width. It does not recover text that disappeared during image resizing. Training teaches the connector which image information helps the language task. Matching tensor dimensions alone does not make two independently trained models compatible.

Where attention operates

Vision self-attention relates image patches. In a decoder that inserts projected image features into its input sequence, generated text can attend to those image positions under the model's mask. Other designs keep visual features separate and use cross-attention, or compress them through learned queries. Do not assume all vision-language models concatenate the same number of patches.

LLaVA documentation illustrates a vision encoder, multimodal projector and autoregressive language model. Processor settings and feature-selection rules must match the checkpoint. Inspect actual image-feature shapes before estimating context use.

Retrieval and generation have different outputs

A CLIP-style dual encoder maps images and text into comparable embeddings. Similarity helps rank candidates; it does not produce a cited answer. A generative VLM produces output tokens conditioned on visual inputs. Its fluent answer may still misread a label or unit. See CLIP documentation.

For a scanned invoice, retrieve likely pages, then inspect the relevant crop with a model or extraction system that can read it. Keep page and box references. A crop that drops the currency header can make an amount ambiguous even if its digits are clear.

Practice: double image width and height, keeping patch size fixed. What changes?

The patch count becomes four times larger: sixteen instead of four. With six text positions, the toy sequence has twenty-two positions. Global attention's pairwise work grows quadratically with sequence length, though actual runtime also depends on kernels and model design.

Practice: is an image feature a vocabulary token ID?

No. It is a vector. The processor and model place visual features at designated positions or supply them through another supported interface. Arbitrarily casting image values to token IDs breaks that contract.

Senior interview: why can higher resolution hurt latency without fixing the answer?

More patches increase work. The failure may instead be the wrong page, missing header, poor evidence selection or an unsupported inference. Measure the failure before choosing a larger image.
