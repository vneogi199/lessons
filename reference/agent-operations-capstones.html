Parallel work without conflicting state

A router selects work; a supervisor coordinates specialists; a subgraph encapsulates a workflow. None automatically makes the result more accurate. Give each branch an owned result key and merge deltas, not entire stale state snapshots. A reducer must define what concurrent updates mean.

def merge(left, right):
    result = dict(left)
    for key, value in right.items():
        if key in result and result[key] != value:
            raise ValueError("conflicting branch result")
        result[key] = value
    return result

assert merge({"policy": "ok"}, {"evidence": "missing"}) == {
    "policy": "ok", "evidence": "missing"}
assert merge({"a": 1}, {"a": 1}) == {"a": 1}
try:
    merge({"a": 1}, {"a": 2})
except ValueError:
    pass
else:
    raise AssertionError("conflict accepted")

In the following integration recipe, reuse merge above. The child runs two async nodes concurrently; its join waits for both. The parent routes denied requests directly to END. Real nodes must enforce authorization themselves as well.

from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    allowed: bool
    findings: Annotated[dict, merge]

async def policy(state):
    return {"findings": {"policy": "reviewed"}}

async def evidence(state):
    return {"findings": {"evidence": "missing signature"}}

def joined(state):
    return {}

child = StateGraph(State)
child.add_node("policy", policy)
child.add_node("evidence", evidence)
child.add_node("joined", joined)
child.add_edge(START, "policy")
child.add_edge(START, "evidence")
child.add_edge(["policy", "evidence"], "joined")
child.add_edge("joined", END)
parent = StateGraph(State)
parent.add_node("review", child.compile())
parent.add_conditional_edges(START,
    lambda state: "review" if state["allowed"] else END)
parent.add_edge("review", END)
graph = parent.compile()
# In an async test: result = await graph.ainvoke(
#     {"allowed": True, "findings": {}})
# Assert both findings; repeat with allowed=False and expect none.

For dynamic map-reduce, send bounded work items to workers and reduce outputs by stable item ID. Cap concurrency and total work; async is not a rate limiter. Use a persistent checkpointer for recovery, tenant-scoped thread IDs and explicit approval interrupts. Resumed nodes may rerun: move effects behind durable idempotency records. A recursion limit stops graph transitions, not an already-running external request.

Attempt: one child times out after the other finishes. Specify partial-result policy, retry ownership and approval behavior.

Compare your answer

Do not silently call the missing evidence a pass. Persist branch outcomes, retry only safe failed work within a deadline, and mark the review incomplete. Approval must bind to the final evidence version. Last-writer-wins would conceal conflicting findings.

Managed agents and trustworthy memory

Short-term state belongs to a run; semantic memory stores reusable facts; episodic memory records a past event and outcome. Retrieval similarity is not truth or permission. Store tenant, owner, source, version, timestamp, expiry and deletion lineage alongside every memory. Verify access before ranking and again before returning evidence.

  1. Choose an approved Bedrock model and agent execution role. Restrict its permissions to required knowledge bases and action resources.
  2. Create the agent with explicit instructions. Define action groups with precise schemas; use Lambda or return-control execution with server-side validation.
  3. Attach a knowledge base only after reviewing source permissions, embedding/index configuration and ingestion outcomes. Test one allowed document and one forbidden document.
  4. Prepare the agent, create a reviewed version/alias, then invoke the alias in an isolated test client. Record model, agent and corpus versions with the result.
  5. Test missing evidence, stale memory, unavailable tools, approval denial and a malicious retrieved instruction. Inspect traces without exporting sensitive payloads.
  6. Remove disposable resources and verify retained storage/logs and billing. Do not run this provisioning exercise without account authorization.

Attempt: yesterday's memory says a customer is eligible, but today's policy changed. Compare keyword, semantic and recency filters on a fixed fixture.

Compare your answer

Recompute against the current authoritative policy. Keep the historical episode as an episode, not a current entitlement. Tombstones and version filters must also invalidate caches; a high vector score cannot revive deleted evidence.

Source: Bedrock agent creation. Continue with episodic-memory practice.

Provider gateways, retries and fallback policy

LiteLLM and Portkey can centralize provider credentials and routing. Applications receive scoped gateway credentials, not every provider key. Assign project/model permissions, quotas and rotation ownership. A fallback must satisfy the same data-region, tool and structured-output requirements; a cheaper model is not automatically a compatible replacement.

  1. Register two approved deployments under stable aliases. Keep provider keys in the gateway's secret store.
  2. Create a restricted client key and route a synthetic request. Confirm unauthorized aliases fail.
  3. Configure one fallback, bounded retries and a total request deadline. Avoid multiplying SDK, gateway and worker retries.
  4. Inject 429, timeout and invalid-schema responses. Honor Retry-After when feasible; use capped exponential backoff with jitter for retryable failures. Do not retry authorization errors.
  5. Track every billed attempt and which route served the answer. Test key revocation and gateway failure. Treat budget alerts as alerts unless an independently tested admission check enforces a cap.
def permitted_fallback(candidate, required_region, required_features):
    return (candidate["region"] == required_region
            and required_features <= candidate["features"])

primary_contract = {"tools", "json_schema"}
assert permitted_fallback({"region": "eu", "features": primary_contract},
                          "eu", primary_contract)
assert not permitted_fallback({"region": "us", "features": primary_contract},
                              "eu", primary_contract)
assert not permitted_fallback({"region": "eu", "features": {"tools"}},
                              "eu", primary_contract)

Attempt: the provider timed out after executing a charge tool. Should model fallback run the charge again?

Compare your answer

No. Recover the durable operation result using its idempotency key, or reconcile uncertain execution before resuming. Provider failover does not undo external effects. Preserve the approved payload hash across retries.

Sources: LiteLLM keys, fallbacks, Portkey fallbacks.

Evaluation that can block a bad release

Build a versioned dataset with question, permitted sources, reference answer, expected action or abstention, and slice labels. Generate candidate questions from source documents, then have a reviewer check answerability and citations. Split by document family before generation to avoid near-duplicate leakage. Include unanswerable, conflicting, stale and forbidden-document questions.

RAGAS faithfulness assesses whether response claims are supported by retrieved evidence; answer relevance assesses responsiveness. Context precision concerns relevant retrieval placement, while context recall concerns reference evidence coverage. These are different failure signals, not interchangeable accuracy percentages. Select the reference-based or reference-free variant deliberately and record judge/embedding versions.

  1. Run baseline and candidate on identical held-out questions and permissions. Save raw outcomes with dataset, prompt, index and model revision.
  2. Score deterministic constraints first: schema validity, exact normalized fields, tool arguments, authorization violations and citations.
  3. Apply a calibrated judge rubric to semantic quality. Blind model identity, define supported/partial/unsupported examples, review disagreements and repeat noisy scores.
  4. Compare paired differences, failure slices and uncertainty, not just averages. Set acceptance thresholds before inspecting candidate scores.
  5. Publish a CI artifact with counts, errors, latency and cost. A missing score is not a zero-quality answer or an invisible row: report evaluation coverage separately.
def release_gate(rows):
    if not rows or any(row["score"] is None for row in rows):
        return False
    return (all(not row["permission_leak"] for row in rows)
            and sum(row["score"] for row in rows) / len(rows) >= 0.8)

assert release_gate([{"score": 0.9, "permission_leak": False}])
assert not release_gate([{"score": None, "permission_leak": False}])
assert not release_gate([{"score": 1.0, "permission_leak": True}])
# Illustrative gate, not a statistically sufficient production release policy.

Attempt: relevance improves while faithfulness drops. Identify which pipeline stage to inspect first.

Compare your answer

Inspect retrieved evidence and generated claims together. Better topical retrieval can still supply contradictory or insufficient evidence; generation may also invent unsupported details. Add claim-level examples before changing the judge threshold.

Sources: RAGAS metrics, synthetic testsets. Use the RAGAS recipe in an approved environment.

Trace the request, not private reasoning

Create a root request span with children for retrieval, reranking, model attempts, tools and approvals. Record versions, safe operation IDs, outcomes and durations. Propagate trace context across queues and async work. Do not log hidden chain-of-thought, keys, raw PII or unrestricted tool payloads. Use redacted inputs and observable decisions to debug behavior.

from opentelemetry import trace
tracer = trace.get_tracer("curriculum.agent")

async def traced_lookup(lookup, query, scope):
    # Configure the SDK/exporter once in the service, not per request.
    with tracer.start_as_current_span("retrieval") as span:
        span.set_attribute("app.retrieval.version", "fixture-v1")
        rows = await lookup(query, scope)
        span.set_attribute("app.retrieval.count", len(rows))
        return rows

Build panels for request success, p50/p95 end-to-end latency, time to first token, retrieval latency, tool failures, evaluation drift, tokens and cost per successful task. Count retries and failed attempts. Calculate cost using provider-reported usage and a versioned rate table, distinguishing cached tokens and other billed modalities. Parallel span durations do not sum to wall-clock latency.

Use pseudonymous session IDs in access-controlled traces, not high-cardinality metric labels. Track completion and repeat failure by session with retention limits. Export redacted traces via an approved collector; turn reviewed failures into evaluation cases with consent and lineage. Sampling can hide rare failures, so reconcile dashboard totals against unsampled request counters.

Attempt: a cheap model halves per-call cost but doubles retries and increases abandonment.

Compare your answer

Compare cost per successful user task, including retries, tool work and human handling. Report abandonment separately; dividing only by completed calls hides the product regression. Alert on a service objective with a runbook, not every noisy span.

OmniGuard: secure AI integration capstone

Deliver a bounded internal assistant that answers policy questions with citations and retrieves approved financial totals through parameterized SQL Server templates. It must abstain when evidence or permission is missing. This is a build brief; no application or cloud deployment is supplied by the curriculum.

  1. Discovery: interview a business owner, security reviewer and operator. Record the current workflow, data owners, volume, pain points, prohibited actions and acceptance authority. Classify public/internal/confidential/restricted fields and allowed processing regions.
  2. Statement of work: specify one corpus, one SQL view, two user roles and a read-only MVP. Exclude arbitrary SQL, autonomous writes and unsupported formats. List dependencies, retention, deletion, availability assumptions and change control.
  3. Architecture: verified OAuth identity → server-side RBAC → Presidio/NeMo controls → permission-filtered hybrid retrieval or typed SQL intent → grounded response. Guardrails supplement authorization; they do not replace it. Use SQL boundaries and PII practice.
  4. Build: implement the FastAPI request lifecycle, replace the mock identity with verified identity, add approved source connectors and denial fixtures, then containerize. Use the delivery checklist only in an authorized account.
  5. UAT: the business reviewer submits an answerable policy question and verifies citations; a restricted user repeats it and must receive no restricted content; the data owner checks an exact SQL total; an operator injects provider failure and confirms safe error handling. Record expected/actual, evidence, owner and signoff for each case.
  6. Executive review: estimate annual benefit as eligible task volume × measured time saved × loaded hourly cost, minus operating/support/change costs. Show adoption assumptions and sensitivity. Present residual risk and incident ownership to the CISO rather than claiming zero leakage from a small test.

Deliver discovery notes, data-flow diagram, SOW, threat model, source inventory, reproducible test dataset, UAT runbook, Docker configuration, release/rollback checklist and a cost worksheet. Demonstrate a denied request and a failed dependency before the happy path.

Interview review

If asked why this is not an unrestricted agent, explain that the MVP's value is read-only verified answers. Measured demand and a separately approved control design would justify write capabilities. A signed UAT document does not certify regulatory compliance.

AuditMesh: multi-agent compliance workflow

Map five manual steps: gather evidence → map controls → assess gaps → obtain approval → create a ticket and report. Measure handling time and waiting time separately. A model suggests findings; an authorized reviewer owns the compliance decision.

  1. Build a LangGraph supervisor with separate evidence and policy workers, a deterministic join, an approval interrupt and a ticketing node. Use the conflict-safe graph; do not let the critic's opinion become proof.
  2. Define a custom MCP server exposing one narrow Jira action: create an approved gap ticket with project allowlist, bounded text and durable operation ID. The host owns user consent; its client connects to the server; the server verifies token audience/scopes and enforces resource permissions. Never accept arbitrary upstream URLs or pass client tokens blindly downstream.
  3. Persist the proposed payload and its hash before presenting approval. The server verifies reviewer role, tenant, expiry and unchanged payload, then atomically marks the operation approved. On retries, reuse the operation ID and reconcile uncertain Jira creation.
  4. Build a Streamlit or Gradio approval screen backed by this service. Display evidence, proposed action, destination and consequences. Browser state is not authorization. Reject stale approvals and changed payloads.
  5. Define an illustrative interactive p95 target of 8 seconds excluding human waiting; allocate retrieval/model/tool time and measure under load. Set token and dollar budgets per task, cap loops, and stop queued work through a tested kill switch.
  6. Hand off dashboards, on-call ownership, escalation rules, revoked-access procedure, retention policy and replay instructions. Train operators with duplicate-ticket, stale-approval, leaked-secret and unavailable-Jira tabletop drills.
import streamlit as st

def approval_ui(backend, operation_id):
    # backend uses the authenticated server session; no client-supplied actor.
    pending = backend.get_pending(operation_id)
    st.json(pending["display_payload"])
    with st.form("approve_operation"):
        confirmed = st.checkbox("I reviewed the evidence and destination")
        submitted = st.form_submit_button("Approve this exact operation")
    if submitted and confirmed:
        # Backend checks role, tenant, expiry, payload hash and replay atomically.
        backend.approve(operation_id, expected_hash=pending["payload_hash"])
        st.success("Approval recorded; check execution status separately.")

The backend methods above are a contract to implement, not a supplied secure service. Add authenticated session handling, CSRF protection appropriate to the hosting setup, authorization and durable operation storage before real use. Approval is distinct from successful Jira execution.

Deliver a five-step process map, graph/state diagram, MCP trust-boundary diagram, approval UI, failure tests, token/cost/trace dashboard and operator training script. UAT must include a denied reviewer, duplicate callback, changed payload, tool timeout and kill-switch activation.

Interview review

A supervisor reduces coordination work, not accountability. Separate evidence collection from decisions and external effects. If two agents disagree, preserve provenance and route for review instead of voting a compliance assertion into existence.
