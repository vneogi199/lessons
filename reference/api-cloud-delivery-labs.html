Python basics → a validated API → an LLM call

Connected project: RFQ CRUD with duplicate-request handling, tenant checks and stale-update protection. Includes source files and unexecuted tests. Read its limits before running it.

A variable binds a name to an object. Common types include int, float, bool, str, list, tuple, dict and set; None represents absence. A for loop visits items in an iterable, and if/elif/else chooses a branch. Indentation groups statements. Lists are mutable; assigning another name to one does not copy it. Start with a small deterministic function before involving HTTP or a model.

def classify_scores(scores):
    result = {"pass": [], "retry": []}
    for score in scores:
        if type(score) is not int or not 0 <= score <= 100:
            raise ValueError("integer score from 0 to 100 required")
        if score >= 70:
            result["pass"].append(score)
        else:
            result["retry"].append(score)
    return result

assert classify_scores([69, 70, 100]) == {"pass": [70, 100], "retry": [69]}
assert classify_scores([]) == {"pass": [], "retry": []}
try:
    classify_scores([True])
except ValueError:
    pass
else:
    raise AssertionError("bool is not a score in this contract")

Predict the result for [0, 70] and explain why bool needs deliberate handling in Python numeric checks. Compare mutating result with rebinding score. This is the same boundary discipline used in an API schema.

The following teaching application requires existing FastAPI, Pydantic v2, pydantic-settings and OpenAI SDK installations. It is a loopback-only lab without application authentication; never publish it as-is. The provider model and key are environment configuration, not source-code constants. A .env file is a local convenience, not a production secret store: exclude it from Git and images, restrict its permissions, and rotate any exposed key. In production use an approved secret manager/workload identity and startup validation.

from contextlib import asynccontextmanager
import logging
from uuid import uuid4
from fastapi import BackgroundTasks, Depends, FastAPI, HTTPException, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from pydantic import BaseModel, ConfigDict, Field, SecretStr, field_validator
from pydantic_settings import BaseSettings, SettingsConfigDict
from openai import AsyncOpenAI, APIError

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="APP_", env_file=".env", extra="ignore")
    llm_api_key: SecretStr
    llm_model: str = Field(min_length=1)

class Question(BaseModel):
    model_config = ConfigDict(extra="forbid")
    text: str = Field(min_length=1, max_length=2000)

    @field_validator("text")
    @classmethod
    def nonblank(cls, value):
        value = value.strip()
        if not value:
            raise ValueError("blank question")
        return value

class Ask(BaseModel):
    model_config = ConfigDict(extra="forbid")
    question: Question  # Nested validation applies to question.text.

class Answer(BaseModel):
    text: str
    request_id: str

class UpstreamFailure(Exception):
    pass

@asynccontextmanager
async def lifespan(app):
    settings = Settings()
    app.state.model = settings.llm_model
    async with AsyncOpenAI(api_key=settings.llm_api_key.get_secret_value(),
                           timeout=15.0, max_retries=0) as client:
        app.state.llm = client
        yield

app = FastAPI(lifespan=lifespan)

@app.middleware("http")
async def correlate(request: Request, call_next):
    request.state.request_id = uuid4().hex
    response = await call_next(request)
    response.headers["X-Request-ID"] = request.state.request_id
    return response

def error(request, status, code):
    return JSONResponse(status_code=status, content={"error": {
        "code": code, "request_id": getattr(request.state, "request_id", None)}})

@app.exception_handler(UpstreamFailure)
async def upstream_error(request: Request, exc: UpstreamFailure):
    return error(request, 502, "llm_unavailable")

@app.exception_handler(RequestValidationError)
async def invalid_input(request: Request, exc: RequestValidationError):
    return error(request, 422, "invalid_request")  # Do not echo raw input/secrets.

@app.exception_handler(HTTPException)
async def known_http_error(request: Request, exc: HTTPException):
    response = error(request, exc.status_code, "unsupported_operation")
    if exc.headers:
        response.headers.update(exc.headers)
    return response

async def generate(request: Request):
    async def call(text):
        try:
            response = await request.app.state.llm.responses.create(
                model=request.app.state.model,
                input=text, max_output_tokens=200,
            )
        except APIError as exc:
            raise UpstreamFailure() from exc
        if response.status != "completed" or not response.output_text.strip():
            raise UpstreamFailure()
        return response.output_text
    return call

def completion_metric(request_id):
    logging.getLogger("lesson").info("completed request_id=%s", request_id)

@app.post("/ask/{mode}", response_model=Answer)
async def ask(mode: str, payload: Ask, request: Request,
              background: BackgroundTasks, call=Depends(generate)):
    if mode != "brief":
        raise HTTPException(status_code=400, detail="unsupported mode")
    text = await call(payload.question.text)
    background.add_task(completion_metric, request.state.request_id)
    return Answer(text=text, request_id=request.state.request_id)

The route combines a path parameter, nested request validation, a filtered response contract, middleware, a dependency and a small post-response task. BackgroundTasks is not a durable queue; process loss can discard the metric and its failure cannot change an already-sent response. Critical audit/job work needs durable storage. Provider timeouts do not undo remote effects; refusal and unsupported structured content need an explicit product policy. This text-only example treats an empty/incomplete turn as unavailable.

In a provisioned environment, test with FastAPI TestClient and a lifespan-aware fixture. Override generate with an async fake returning a deterministic string; use a dummy test key so no provider call is made. Assert success for a nested question, 422 for blank/extra fields, 400 for the wrong mode, 502 for UpstreamFailure, and matching request IDs in body/header. Verify the background callback receives only the ID, not the question/key. For production add authentication, authorization, request limits, rate/spend control and a consistent handler for other Starlette HTTP errors.

Primary references: background tasks, error handling and Python model calls. No server/model call was executed here. Tomorrow, trace one invalid request and one upstream error through different boundaries.

GraphQL schemas, resolvers and N+1 queries

Supplied implementation: tenant-scoped SQLite repository, loader ordering and schema tests. Tests are authored, not executed.

A schema describes fields, object relationships and input types; a resolver supplies each field's value. Queries read data; mutations express changes. Top-level mutation fields execute serially under GraphQL semantics, but that does not make the entire operation a database transaction or serialize other requests. Keep authorization and transaction boundaries inside the application service.

Strawberry derives schema types from Python annotations; Graphene uses explicit ObjectType/InputObjectType declarations. Choose one rather than mixing frameworks. This recipe uses Strawberry mutations and DataLoader batching. The repository interface is deliberately supplied by your application; it must enforce tenant filtering and use bounded parameterized SQL.

import strawberry
from strawberry.dataloader import DataLoader
from strawberry.types import Info

@strawberry.type
class Customer:
    id: strawberry.ID
    name: str

@strawberry.type
class Order:
    id: strawberry.ID
    customer_id: strawberry.Private[str]

    @strawberry.field
    async def customer(self, info: Info) -> Customer | None:
        return await info.context["customers"].load(self.customer_id)

@strawberry.input
class RenameCustomer:
    id: strawberry.ID
    name: str

@strawberry.type
class Query:
    @strawberry.field
    async def orders(self, info: Info, first: int = 20) -> list[Order]:
        if not 1 <= first <= 100:
            raise ValueError("first must be between 1 and 100")
        return await info.context["repo"].orders(info.context["actor"], first)

@strawberry.type
class Mutation:
    @strawberry.mutation
    async def rename_customer(self, info: Info, input: RenameCustomer) -> Customer:
        name = input.name.strip()
        if not 1 <= len(name) <= 100:
            raise ValueError("invalid name")
        # Service checks object-level write authority and commits atomically.
        result = await info.context["repo"].rename(info.context["actor"], str(input.id), name)
        info.context["customers"].clear(str(input.id))
        return result

def context_for(actor, repo):
    async def batch(ids):
        rows = await repo.customers_by_ids(actor, ids)
        return [rows.get(key) for key in ids]  # Preserve order and missing entries.
    return {"actor": actor, "repo": repo, "customers": DataLoader(load_fn=batch)}

schema = strawberry.Schema(query=Query, mutation=Mutation)

For { orders { id customer { name } } }, fetching customers individually can produce one order query plus N customer queries. Request-scoped loaders batch sibling loads and cache repeated keys. Awaiting unrelated calls sequentially can prevent batching; a loader does not optimize arbitrary SQL. Use eager loading when a predictable join is simpler. Never share a user-specific loader across requests, and invalidate cached entities after a mutation.

Practice with a fake repository that returns three orders belonging to two customers. Execute the query through schema.execute with context_value, count repository calls and assert the response shape. Then swap customer row order, omit one row, deny one actor and rename a customer. For a real database, record SQL counts and query plans, not only resolver counts. Add depth/complexity limits, pagination and timeouts; a small HTTP body can still request expensive nested work.

Interview: the response is correct, but one customer is shown to the wrong tenant. What failed?

Batching is not authorization. Verify actor-derived scope in the repository and the loader's lifetime/cache keys. Returning rows in database order rather than requested-key order is another possible misassociation. Test both tenant separation and ordering explicitly.

URL versus header versioning

Supplied project: version routes, cache-isolation tests and matched debugger configuration.

URL versioning makes the contract visible, for example /v1/orders versus /v2/orders. Header versioning keeps the URL stable but adds routing and caching obligations. Pick a documented default, reject unsupported versions and define conflict handling when both mechanisms appear. Version the external representation, not every internal refactor.

def choose_version(path_version=None, header_version=None):
    supported = {"1", "2"}
    for value in (path_version, header_version):
        if value is not None and value not in supported:
            raise ValueError("unsupported API version")
    if path_version and header_version and path_version != header_version:
        raise ValueError("conflicting API versions")
    return path_version or header_version or "1"

assert choose_version() == "1"
assert choose_version(None, "2") == "2"
assert choose_version("2", "2") == "2"
for values in [("1", "2"), (None, "3"), (None, "")]:
    try:
        choose_version(*values)
    except ValueError:
        pass
    else:
        raise AssertionError(values)

In FastAPI, read an explicit Header(alias="X-API-Version") dependency, call this selector and map ValueError to your documented 400 error. Reuse a domain service but serialize with the selected response model; do not let an ORM object silently define both contracts. For header-varying cacheable responses, configure the cache key and merge X-API-Version into Vary without overwriting other dimensions. Browser clients may need a CORS preflight for a custom request header. See FastAPI header parameters.

Test the same resource ID through both versions, including missing/invalid headers, mismatched URL/header values and a warmed cache. Assert that v1 never receives a v2 field/type by accident. Keep consumer contract tests and usage telemetry during deprecation; a Sunset announcement is not evidence all clients migrated.

Worked feedback: header-based v2 returns v1 after a successful first request. Why?

A shared cache may key only on the URL. Check both origin Vary and the actual proxy/CDN cache configuration. Also check that response validation uses the selected version rather than a single incompatible model.

Tests, coverage and a reproducible IDE setup

Unit tests exercise a small boundary with controlled dependencies; integration tests verify a real boundary such as database uniqueness or an ASGI lifecycle. Use fixtures for owned setup/teardown and patch the name where it is looked up. Mock external time/network behavior, not the business rule you want to verify. Coverage reports executed lines/branches, not assertion quality.

In an existing environment with pytest and coverage support, run python -m pytest first outside the IDE. If pytest-cov already exists, use python -m pytest --cov=app --cov-branch --cov-report=term-missing. Never install it merely to read this lesson. Inspect untested denial, timeout, rollback and empty-result branches, then intentionally break one assertion-relevant behavior and verify a test fails. See VS Code testing and coverage.

Provision a small isolated AWS application

Provisioning is a dependency graph: identity and budget → network → data services → compute → evidence and teardown. Use a disposable account/project, one selected region, explicit names/tags and an approved cost ceiling. This walkthrough is not authorization to create resources. Record every created resource ID; snapshots, NAT gateways, public IPv4 addresses and logs can cost money after compute stops.

  1. Confirm the account/role with STS caller identity. Design a VPC with non-overlapping CIDRs and two AZs. Public subnet route tables point to an internet gateway; private application subnets use approved NAT egress or service endpoints. Database subnets need not have general internet egress. Use the AWS private-subnet walkthrough, adapting cost/resilience choices explicitly.
  2. Create security groups around traffic relationships: client → HTTPS load balancer; load-balancer group → application port; application group → database port. Do not expose SSH/database ports to the world. Verify DNS, routes and return paths independently of group rules. NAT permits outbound flows; it is not an application firewall.
  3. Launch an approved EC2 image with an instance profile, encrypted storage and IMDSv2 required. Use an approved management path rather than copying long-lived keys into user data. Record startup logs and verify the instance cannot reach a forbidden test destination.
  4. Create a private RDS instance using a subnet group, engine/version pin, backup retention, encryption and an application-specific credential. Test connectivity from the application identity and denial from another group. Restore a synthetic backup into a separate test target before claiming recoverability.
  5. Create a private encrypted S3 bucket with public access blocked. Scope a lifecycle rule to a lab prefix/tag, distinguish current/noncurrent versions, and expire incomplete multipart uploads under a separate rule. Use synthetic objects; versioned delete markers are not immediate deletion of all versions.
  6. Connect a test S3 event or queue to a bounded Lambda function. Validate event shape and object scope, process duplicate deliveries idempotently and route repeated failures to a reviewed recovery path. Event arrival is not exactly-once execution.

For a cross-account role, the target role's trust policy names the approved caller and the caller needs permission to assume that role. The target permission policy limits actual actions/resources; use appropriate external-ID conditions for third-party delegation. Session policies and organization controls can further restrict effective authority. Never copy a broad administrator policy to make the lab pass.

Primary build references: EC2, RDS PostgreSQL, S3 lifecycle, and cross-account roles.

Acceptance exercise: the API works publicly; is the lab complete?

No. Show denied database ingress, least-privilege access failures, duplicate-event behavior, a restore result and the inventory/cost cleanup plan. Positive reachability alone says nothing about isolation or recovery. Inspect dependencies before disposing of only the lab's exact resources.

Billing visibility and budget thresholds

Open Billing and Cost Management with an authorized billing role. Use Bills for billed service/region breakdowns, Cost Explorer for trends and filters, and Budgets for thresholds. Confirm the account/billing-view scope, currency, time period and whether the metric is actual or forecast cost. Billing data can lag; a quiet graph is not proof of zero spend.

  1. From Budgets, create a monthly cost budget with an explicitly approved amount and named owner.
  2. Choose account/service/tag filters deliberately; check that required cost-allocation tags are active and historical data is not assumed to be retroactively complete.
  3. Add example actual-spend alerts at 50%, 80% and 100%, plus a forecast alert, with verified notification recipients. These percentages are a lab policy, not universal recommendations.
  4. Record where alerts arrive and who acknowledges them. If using SNS, verify subscription/policy configuration and test the notification path separately.
  5. Define an operational response: investigate unexpected service spend, stop new lab creation, and review exact resources for safe disposal. Never attach an unreviewed destructive budget action.

Follow AWS budget creation. Alerts are not a hard spending cap. Auto-actions require their own permission, delay and blast-radius review. Keep an independent inventory of idle NAT, databases, snapshots, logs and unattached storage.

from decimal import Decimal
budget = Decimal("100")  # Fictional accounting units, not an AWS price quote.
actual, forecast = Decimal("81"), Decimal("120")
crossed = [p for p in (50, 80, 100) if actual >= budget * Decimal(p) / 100]
assert crossed == [50, 80]
assert forecast > budget
assert actual < budget  # Forecast alarm does not mean already overspent.
Interview: the alert arrived after the budget was exceeded. Was it necessarily broken?

No. Usage ingestion, billing updates and delivery have latency. Compare timestamps and configured scope. Budgeting informs decisions; enforce workload quotas/admission limits separately when you need a technical bound.

FastAPI → image → ECS/Fargate → verified release

Use one artifact across test, staging and production. A container image contains the runtime; an ECS task definition describes how it runs; a service maintains tasks and attaches them to a load balancer. Fargate removes host management, not IAM, networking, capacity or operational responsibility. Start from lesson 0491's task-definition contract.

Dockerfile design: pin a reviewed Python base digest, copy the dependency lock before frequently changing source, keep build tools out of the runtime stage, run as a non-root UID and use an exec-form Uvicorn command. Exclude .git, credentials, caches and test exports with .dockerignore. For local Compose, use service DNS names rather than localhost, a named database volume and a health-aware startup policy. Do not publish the database port merely to allow another container to connect.

Provision an ECR repository, ECS cluster/service, two private subnets, an HTTPS ALB and an IP target group for awsvpc tasks. Separate task execution role (image/log/secret startup access) from application task role. Inject secrets from the approved store, not image layers. Set readiness/health checks, log retention, memory/CPU and graceful-stop limits.

name: release-api
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: production-api
  cancel-in-progress: false
jobs:
  release:
    runs-on: ubuntu-latest
    environment: production
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@REVIEWED_COMMIT_SHA
      - name: Test with the project's provisioned CI environment
        run: ./ci/test.sh
      - uses: aws-actions/configure-aws-credentials@REVIEWED_COMMIT_SHA
        with:
          role-to-assume: ${{ vars.DEPLOY_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}
      - uses: aws-actions/amazon-ecr-login@REVIEWED_COMMIT_SHA
        id: ecr
      - name: Build and push candidate
        id: image
        env:
          REGISTRY: ${{ steps.ecr.outputs.registry }}
          REPOSITORY: ${{ vars.ECR_REPOSITORY }}
        run: |
          set -euo pipefail
          image="$REGISTRY/$REPOSITORY:$GITHUB_SHA"
          docker build -t "$image" .
          docker push "$image"
          echo "image=$image" >> "$GITHUB_OUTPUT"
      - uses: aws-actions/amazon-ecs-render-task-definition@REVIEWED_COMMIT_SHA
        id: task
        with:
          task-definition: deploy/task-definition.json
          container-name: api
          image: ${{ steps.image.outputs.image }}
      - uses: aws-actions/amazon-ecs-deploy-task-definition@REVIEWED_COMMIT_SHA
        with:
          task-definition: ${{ steps.task.outputs.task-definition }}
          service: ${{ vars.ECS_SERVICE }}
          cluster: ${{ vars.ECS_CLUSTER }}
          wait-for-service-stability: true
      - name: Verify the released behavior
        run: ./ci/smoke.sh

This is a configuration recipe, not a committed workflow. Replace every reviewed-SHA marker, supply the Dockerfile/task definition and implement test.sh/smoke.sh before use. The CI test environment must already provide locked dependencies. Require ECR tag immutability for the commit tag or resolve and deploy the pushed digest. Bind GitHub OIDC trust to the specific repository/environment and audience; restrict iam:PassRole to the task roles. GitHub environment approvals protect the deployment boundary. Long-lived AWS keys are unnecessary; provider secrets remain in the service's secret store. See GitHub's ECS workflow.

Register the service as an Application Auto Scaling target with a tested minimum/maximum. Choose CPU or ALB request-count-per-target based on measured saturation; use cooldowns and observe scale-in draining. See target tracking. More tasks can overwhelm a fixed database pool or provider quota. Ensure private tasks can reach ECR, logs, secrets and required providers through approved endpoints/egress.

Release drill

Introduce a readiness failure: new tasks must not receive traffic, and recovery must use the previous immutable image/task revision. Then introduce a business-response regression that readiness cannot detect: smoke tests and error/latency telemetry must catch it. Container rollback does not undo incompatible schema migrations; use expand/contract changes and a separate migration owner.
