Production AI practice sequence

Build a synthetic RFQ review service that can explain its failures. An RFQ is a request for a price. These exercises parse and review requests; they never price real instruments, submit trades or send client data to a provider.

Work through the pages in order. Give each page a 30-minute reading session, then a separate 60–90 minute practice session. Repeat its interview question the next day without notes. The full sequence can span several weeks at six to eight hours per week.

  1. Harness engineering: state, policy, budgets and test boundaries.
  2. FastAPI production practice: concurrency, database ownership, overload and deployment incidents.
  3. Logfire: instrument a request without exporting private payloads.
  4. Replayable traces: reproduce application decisions without repeating side effects.
  5. Claude Agent SDK: runtime controls, sessions, permissions and results.
  6. Trajectory and multi-turn evaluation: score behavior across a conversation.
  7. Stage latency: p50, p95 and p99 with correct denominators.

The offline lab supplies deterministic replay and evaluation fixtures. The Logfire/FastAPI adapter and Claude configuration require compatible existing packages; no installation or live provider call is part of this task. Read each file's limits before using it.

Completion produces practice evidence. Production experience requires operating a deployed service, observing real failures and owning recovery. Keep those claims separate in interviews. Ask your teacher to review a failed case or your incident explanation before moving on.
