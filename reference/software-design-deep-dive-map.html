Software Design, Clean Code, and Patterns

Software design from readable code and pragmatic DRY, KISS, and YAGNI decisions through cohesion, coupling, SOLID, composition, pattern families, safe refactoring, and application architecture boundaries. This map links all 12 lessons in their recommended sequence.

  1. 01Clean code, naming, functions, control flow, comments, formatting, and local reasoning
  2. 02DRY, knowledge duplication, accidental duplication, KISS, YAGNI, simplicity, and premature abstraction
  3. 03Cohesion, coupling, encapsulation, information hiding, dependency direction, boundaries, and change cost
  4. 04Single Responsibility Principle, Open-Closed Principle, reasons to change, extension points, and plugin boundaries
  5. 05Liskov Substitution Principle, Interface Segregation Principle, Dependency Inversion Principle, contracts, substitutability, and capability interfaces
  6. 06Composition, inheritance, delegation, polymorphism, data-oriented design, and functional cores
  7. 07Design pattern literacy, context, forces, intent, consequences, implementation variants, and anti-patterns
  8. 08Creational patterns, Factory Method, Abstract Factory, Builder, Prototype, Singleton, and dependency injection
  9. 09Structural patterns, Adapter, Facade, Decorator, Composite, Proxy, Bridge, and Flyweight
  10. 10Behavioral patterns, Strategy, Observer, Command, State, Chain of Responsibility, Template Method, Iterator, Mediator, Memento, and Visitor
  11. 11Code smells, characterization tests, refactoring, seams, small steps, behavior preservation, and review evidence
  12. 12Architecture patterns, layered architecture, hexagonal architecture, clean architecture, vertical slices, repository, unit of work, and modular monoliths
