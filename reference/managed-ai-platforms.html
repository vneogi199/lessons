A simple way to compare the choices

A managed model API is like ordering a prepared meal. A dedicated endpoint is like renting a kitchen with equipment. Self-hosting means operating the kitchen yourself. A model router selects which kitchen receives an order; it does not remove responsibility for allergies, delivery failures or the bill.

These are responsibility models, not claims that every product has identical features. Verify the exact service, model, region, account and edition. AWS describes its shared data-protection responsibilities. Dedicated endpoints have their own scaling behaviour; for example, Hugging Face documents cold starts when scaling from zero.

Apply hard constraints before scoring preferences

Write the required data location, retention, private network path, model licence, output schema, tool permissions, latency and maximum spend. Unknown compliance evidence is an unresolved gate, not a passing score. A cheap option that cannot meet a hard requirement is excluded before weighted comparison.

Check request and token quotas separately, concurrency, regional availability, streaming cancellation and error semantics. Routing to a backup can change model behaviour, supported fields, token accounting and data location. An API-compatible endpoint is not proof of equivalent tool or structured-output behaviour.

Draw the full data path: client, app, gateway, provider, logs, backups and support access. Check inference routing and telemetry separately from stored data. A selected region alone does not prove that every request stays there. Verify contracts and current official service settings before sensitive use.

A worked fictional decision

A team has 10,000 requests per month, no GPU operator and an approved regional managed API. Its target is an interactive support assistant. These assumptions are invented for practice, not vendor prices or measured benchmarks.

Managed route: 10,000 × $0.004/request = $40/month
Dedicated host: 730 hours × $0.50/hour = $365/month
Both also need app hosting, logs, storage, network and support.
Training and engineering effort are extra.

The managed route is the initial candidate because the workload is small and the team lacks serving capacity. It still needs quality, tail-latency and security checks. If demand becomes steady and much larger, compare dedicated capacity using measured throughput. Dividing GPU hourly price by peak benchmark throughput hides idle time and queueing.

Changing the requirement to an isolated network with no approved external inference rules out that initial route. Evaluate an approved private deployment, or stop until one exists. A weighted cost advantage cannot override the requirement.

Write the decision and test it

  1. Record the task, data classification, expected load, response-time target, region, budget and operational owner.
  2. List two feasible candidates. Attach dated official evidence for retention, routing, quotas, networking, model access and licence. Do not copy pricing numbers from this lesson.
  3. Run the same versioned synthetic query set through both in an approved environment. Record quality, invalid outputs, p50/p95/p99, cold starts, tokens and known costs. Separate errors and retries from successful latency.
  4. Test denied identity, disallowed model, timeout, cancellation, quota exhaustion and backup routing. A fallback must satisfy the same data policy. Use a manual or deterministic path if none does.
  5. Specify a release artifact, health check, budget alarm, rollback and cleanup owner. Confirm a real authenticated workflow rather than only a healthy container.
  6. Write an ADR: decision, rejected alternative, accepted cost and the observation that would cause a review.

The existing Bedrock package supplies a provisioning recipe with readiness and allow/deny checks. The gateway package covers bounded routing and key handling. Neither is evidence of a live deployment here.

Finish the roadmap with evidence

Use three existing projects rather than creating five unfinished demos: Support Copilot, AuditMesh, and your RFQ/risk workflow. For each, collect setup steps, architecture decisions, reproducible offline checks, measured integration results when authorized, a failure demonstration and limitations. Mark each claim as authored, locally tested, integration-tested or deployed.

Complete the roadmap's remaining experiments in one evidence log: two-model comparison; two prompt versions; full versus selected/summarized context; actual deployment/load/rollback. Fix datasets, versions and measurement rules first. Do not replace missing observations with invented results. These are learner practice and previously waived external checks, not newly required cloud actions.

Interview rehearsal

Does managed hosting remove the need for evaluation?

No. The provider operates parts of the platform. You still own application correctness, permissions, data handling and the decision to release.

Why can scale-to-zero violate an interactive SLA?

A cold replica takes time to become ready. Measure cold and warm requests separately, keep capacity warm where needed, or use an asynchronous user flow.

MCQ: a cheap backup violates residency. Choose “route anyway” or “stop routing”?

Stop routing. Use an approved fallback or explain unavailability. Cost does not override the data boundary.
