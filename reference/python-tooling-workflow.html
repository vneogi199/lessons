uv, Ruff and pytest in one project

Start with a small function that cleans an incoming quantity. First read its contract, then follow the tests, then try changing one rule. This is the same workflow you can use for an RFQ parser or a FastAPI service.

Think of a workshop: uv supplies a consistent set of tools, Ruff checks the work against coding rules, and pytest checks whether the result behaves as promised. None replaces your review of the business requirement.

Keep the environment reproducible with uv

pyproject.toml declares project metadata, dependency constraints and tool settings. uv.lock records resolved dependencies. .venv is the local environment that contains installed packages. Commit the project file and the generated lockfile for an application; do not commit the environment, caches or secrets.

Locking resolves dependencies. Syncing installs the selected locked packages into the project environment. uv run normally checks the lock and syncs before running a command. Thus “run tests” can install packages unless you explicitly prevent it. --locked rejects a stale lock; --frozen uses the lock without checking freshness. Neither means “do not install.” --no-sync skips environment synchronization. Read uv's locking and syncing guide.

In an approved setup session, a developer can use uv init, uv add --dev pytest ruff, uv lock and uv sync --locked. These are explanations, not commands to run under the current no-install constraint. Review changes to both metadata and lockfile. A lockfile does not prove packages are safe, nor pin the operating system or every native build input.

For a prepared environment, check uv lock --check --offline, then use uv run --no-sync --offline --no-python-downloads python -m pytest. An offline command may still use cached artifacts; do not use offline mode alone as an installation prohibition. Our exercise deliberately supplies no invented lockfile. Until an authorized resolution generates it, the project is a teaching recipe, not a reproducible locked build.

Interview: CI passes but a developer's machine fails. Where do you look?

Compare Python and uv versions, selected dependency groups, lock revision, interpreter path, OS/native libraries and environment variables. Check whether the developer ran a different pytest executable or skipped synchronization. Avoid deleting the lockfile as the first fix.

Separate linting from formatting

A linter detects selected code patterns, such as an unused import or undefined name. A formatter normalizes layout. ruff check . and ruff format --check . serve different purposes. Passing either does not prove correct business logic or complete type safety.

[tool.ruff]
target-version = "py39"
line-length = 88

[tool.ruff.lint]
select = ["E4", "E7", "E9", "F", "I"]

[tool.ruff.format]
quote-style = "double"

This small ruleset includes common errors, Pyflakes checks and import sorting. Keep the target Python version aligned with supported runtimes. Add stricter rules after reviewing their impact. Avoid suppressing an entire file just to silence one warning; if a suppression is justified, record its reason near the code. See Ruff configuration.

Locally, ruff check --fix . changes code, and ruff format . changes formatting. Review the diff and run tests afterwards. Do not enable unsafe fixes automatically. In CI, use check-only commands so the job reports a failure rather than quietly altering the candidate. Ruff is not a full static type checker or a security audit.

Predict: Ruff passes a function that returns quantity minus one. Does the function work?

Not necessarily. The expression can be valid, well-formatted Python and still violate the contract. A behavioral test must compare the expected quantity with the actual result.

Write a test that can catch the mistake

The supplied parse_quantity accepts a positive integer or an integer string with surrounding whitespace. It rejects booleans, zero, negatives, decimals, missing values and other types. It returns an integer and does not modify external state. Start with " 12 " → 12, then test the boundaries.

@pytest.mark.parametrize("raw, expected", [(" 12 ", 12), (3, 3)])
def test_quantity(raw, expected):
    assert parse_quantity(raw) == expected

@pytest.mark.parametrize("raw", [None, True, "", "1.5", 0, -1])
def test_invalid_quantity(raw):
    with pytest.raises(ValueError):
        parse_quantity(raw)

Parametrization runs the same contract against several inputs. A fixture supplies setup with a defined lifetime. Use function scope for independent mutable state; broader scope can save time but can leak changes between tests. A yield fixture supports teardown after the test. tmp_path gives a test-specific temporary path, and monkeypatch restores patched values after the test. Read pytest fixtures.

The exercise includes a file fixture and an environment override. For API tests, replace the external provider or data dependency, not the validation rule under test. Mock the symbol where the application looks it up. A mock returning success cannot prove a real transaction committed. Add an integration test for that boundary in an approved environment.

Use python -m pytest -q for the suite, -k quantity to select matching names, and -x to stop on the first failure. Markers organize tests; register custom markers to catch typos. Avoid sleeps in tests: inject a clock or wait for an observable event with a deadline. Async tests need an explicitly configured async runner/plugin; do not assume pytest awaits every coroutine.

Coverage reports show executed lines or branches, not requirement correctness. Coverage collection normally needs an additional tool such as coverage.py or pytest-cov. This exercise does not install one. A test that executes the invalid-input branch without asserting rejection provides weak protection even if reported coverage is high.

Use one local and CI sequence

# Recipe for a PREPARED, reviewed environment; not executed here.
uv lock --check --offline
uv run --no-sync --offline --no-python-downloads ruff check .
uv run --no-sync --offline --no-python-downloads ruff format --check .
uv run --no-sync --offline --no-python-downloads python -m pytest -q

Run these from the example project directory. A real CI setup first provisions a reviewed interpreter and uv version, restores or creates the locked environment, and then runs checks. That installation step needs separate approval here. Cache keys should include lockfile, Python and platform information. A cache is an optimization, not the authoritative dependency declaration. Keep deployment credentials away from untrusted pull requests.

  1. Read the function and predict six inputs.
  2. Read the pytest cases. Explain which bug each catches.
  3. Use the standard-library smoke check now; run the real pytest/Ruff commands only in an already prepared environment.
  4. Temporarily change the function to return zero for invalid input in a disposable copy. The rejection tests must fail.
  5. Restore it, review the diff and rehearse why lint, formatting and behavioral tests are separate gates.
MCQ: Which gate checks the declared business behavior? A) Ruff formatting. B) pytest assertions.

B. Formatting checks layout. Assertions check the behaviors you actually encoded; they do not cover requirements you forgot to test.
