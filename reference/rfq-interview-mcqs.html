Python: records and transformations

1. Several RFQs share a desk. Which structure retains every RFQ while grouping by desk?

  1. Dictionary containing counts
  2. Dictionary containing lists
  3. Set containing desks
  4. Tuple containing totals
Answer and explanation

B. Map each desk to a list and append records. Counts/totals lose individual records; a set only preserves unique desk values. Follow-up: add currency to the grouping key.

2. You only need to detect whether an upstream event ID was already seen. Which structure fits a small in-memory exercise?

  1. Sorted timestamp list
  2. Repeated event list
  3. Concatenated event string
  4. Unique identifier set
Answer and explanation

D. A set supports membership checks without retaining duplicate IDs. It is not durable deduplication across restarts or processes. Follow-up: use a database uniqueness constraint scoped by source and event identity.

3. Sorting RFQs by descending notional produces ties. How do you get repeatable results independent of input order?

  1. Add unique tie-breaker
  2. Reverse original input
  3. Convert into sets
  4. Remove equal notionals
Answer and explanation

A. Sort by a composite key such as (-notional, rfq_id). Stable sorting preserves input order for equal keys but does not make differently ordered inputs equivalent. Equal notionals do not imply duplicate RFQs.

4. An amount may legitimately be zero, while None means missing. Which check identifies missing values without treating zero as absent?

  1. Check numeric truthiness
  2. Check string length
  3. Check None identity
  4. Check positive magnitude
Answer and explanation

C. Use value is None for this contract. A truthiness check conflates None and zero. Field-specific validation can subsequently reject zero where positive notional is required.

5. Two valid timestamps use different UTC offsets. What should happen before comparing their chronological order?

  1. Compare original strings
  2. Normalize aware instants
  3. Remove timezone information
  4. Compare displayed hours
Answer and explanation

B. Parse aware datetimes and normalize to UTC or compare aware instants directly. Lexical order of mixed-offset strings can disagree with time order. Naive timestamps require an explicit source timezone, not a guess.

6. A reference feed supplies exactly one instrument record per ID. What efficiently enriches a list of RFQs?

  1. Rescan every instrument
  2. Join using position
  3. Sort without matching
  4. Index instrument identifiers
Answer and explanation

D. Validate reference-key uniqueness, build an ID-to-record dictionary, then perform lookups. With ordinary hash behavior this avoids repeated full scans. Missing IDs must remain explicit; dictionary construction must not silently hide conflicting duplicates.

7. An older amendment arrives after a newer RFQ version. Which rule avoids reverting the blotter?

  1. Compare source versions
  2. Prefer arrival order
  3. Prefer larger notional
  4. Discard every amendment
Answer and explanation

A. Use the upstream contract's sequence/version rules and detect conflicting equal versions. Arrival time does not establish business freshness. If no authoritative ordering exists, route ambiguity for review rather than inventing a rule.

SQL and PostgreSQL

8. Which join keeps every RFQ even when instrument reference data is missing?

  1. Use INNER JOIN
  2. Use CROSS JOIN
  3. Use LEFT JOIN
  4. Use SELF JOIN
Answer and explanation

C. Put RFQs on the left. Unmatched reference columns become NULL. An inner join drops unmatched RFQs; a cross join multiplies combinations. A later WHERE filter on right-side values can accidentally remove the unmatched rows.

9. You need desk/currency groups containing more than five parsed RFQs. Which clause filters the aggregate count?

  1. WHERE filters groups
  2. HAVING filters groups
  3. LIMIT filters groups
  4. ORDER filters groups
Answer and explanation

B. Filter parsed rows with WHERE, group by desk/currency, then use HAVING COUNT(*) > 5. LIMIT restricts returned row count; ORDER BY controls ordering.

10. Three rows have amount values 10, NULL and 20. What does COUNT(amount) return?

  1. Exactly zero rows
  2. Exactly three rows
  3. Exactly one row
  4. Exactly two rows
Answer and explanation

D. COUNT(amount) counts non-NULL values. COUNT(*) returns three. SUM(amount) is 30 here; a group containing only NULL amounts requires a deliberate unknown-versus-zero policy.

11. You need the latest rate known by a cutoff. Where should future observations be removed relative to ROW_NUMBER?

  1. Before ranking rows
  2. After selecting winners
  3. After calculating averages
  4. Before validating currencies
Answer and explanation

A. Apply the as-of condition inside the ranked input. Otherwise a future tick can rank first, and filtering that winner later loses the valid previous tick. Partition by currency and tenor.

12. A window orders only by timestamp, and two rows share that timestamp. What ensures a deterministic ROW_NUMBER winner?

  1. Add another CTE
  2. Increase query timeout
  3. Add unique tie-breaker
  4. Remove window partition
Answer and explanation

C. Add a stable unique key to the order. A deterministic tie-breaker is not necessarily business precedence; source sequence rules still matter. A CTE alone does not order tied rows.

13. Each RFQ joins to several quotes and several audit events, inflating SUM(notional). What addresses the grain mismatch?

  1. Increase numeric precision
  2. Aggregate children separately
  3. Replace SUM blindly
  4. Sort joined rows
Answer and explanation

B. Aggregate each child to the intended RFQ grain before joining, or use existence checks when only presence matters. DISTINCT on notional can incorrectly collapse different RFQs with equal amounts.

14. Which window frame computes a row-by-row cumulative sum under a unique order, rather than grouping timestamp peers together?

  1. RANGE CURRENT ROW
  2. ROWS CURRENT ROW
  3. RANGE UNBOUNDED FOLLOWING
  4. ROWS UNBOUNDED PRECEDING
Answer and explanation

D. Use ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW with a deterministic order. The shorthand ROWS UNBOUNDED PRECEDING ends at the current row. CURRENT ROW alone is not cumulative.

Pandas and NumPy

15. Many RFQs should match one reference row per instrument. Which Pandas merge validation checks the intended cardinality?

  1. Use validate='many_to_one' explicitly
  2. Use validate='one_to_many' explicitly
  3. Use validate='many_to_many' explicitly
  4. Use validate='one_to_one' explicitly
Answer and explanation

A. With RFQs on the left, reference keys on the right must be unique. many_to_many does not enforce that uniqueness; one_to_one is stricter than the stated relationship.

16. A Pandas merge uses null keys on both sides. How does this differ from ordinary SQL equality joins?

  1. Nulls always disappear
  2. Nulls always raise
  3. Nulls can match
  4. Nulls become strings
Answer and explanation

C. Pandas can match null join keys to each other. Validate or separate missing keys when that relationship is invalid; do not assume SQL NULL equality behavior.

17. Which grouped operation returns a desk total aligned to each original RFQ row?

  1. Use groupby aggregation
  2. Use groupby transformation
  3. Use global reduction
  4. Use index reset
Answer and explanation

B. transform maps the group result back to original rows. Aggregation reduces groups to summaries. Index reset changes labels, not the requested computation.

18. Two position sensitivities must be evaluated against three shocks. Which shapes produce a 2×3 grid through broadcasting?

  1. (2,) times (3,)
  2. (1,2) times (3,1)
  3. (2,1) times (3,1)
  4. (2,1) times (1,3)
Answer and explanation

D. Use sensitivities[:, None] * shocks[None, :]. The second option produces a 3×2 grid, not the specified orientation; the other shapes are incompatible. Then sum axis 0 for scenario totals across positions.

19. Wrapping a Python function with np.vectorize generally provides what?

  1. Convenient Python iteration
  2. Guaranteed SIMD execution
  3. Automatic GPU compilation
  4. Guaranteed memory reduction
Answer and explanation

A. It is a convenience wrapper, not an automatic native-kernel speedup. Prefer appropriate ufuncs/broadcasting and measure conversion costs, runtime and peak memory. A concise expression can still allocate an enormous intermediate.

FastAPI, validation and pytest

20. An RFQ JSON body is structurally valid but contains another desk's identifier. What establishes authority?

  1. Trust parsed JSON
  2. Trust request headers
  3. Enforce authenticated scope
  4. Trust model output
Answer and explanation

C. Resolve desk permissions from verified identity and enforce them at data access. Schema validation establishes shape, not permission. Arbitrary request headers are not authenticated claims.

21. A risk endpoint uses a database that fails. What should an API test verify besides an error status?

  1. Full exception disclosure
  2. Safe error contract
  3. Automatic trade approval
  4. Empty successful response
Answer and explanation

B. Assert a stable sanitized error body and that no successful decision/effect is claimed. Test actual database behavior separately from a mocked outage.

22. The same parser must reject five malformed RFQs. Which pytest feature expresses those cases clearly?

  1. Shared mutable globals
  2. Nested production mocks
  3. Repeated manual runs
  4. Parameterized input cases
Answer and explanation

D. Parametrize the bad inputs and assert the expected failure. Fixtures handle reusable setup/cleanup; they do not replace input-specific assertions.

23. A module imported a provider function into its own namespace. Where should a test normally patch it?

  1. Its lookup namespace
  2. Every installed package
  3. The operating system
  4. The business invariant
Answer and explanation

A. Patch the name where the application looks it up. Mock the provider boundary, not the validation rule being tested. A mock can conceal a nonexistent provider API, so contract verification remains necessary.

RFQ workflow, rates and risk judgment

24. A rate rises from 0.0400 to 0.0407. What is the change?

  1. Positive seventy bp
  2. Negative seven bp
  3. Positive seven bp
  4. Negative seventy bp
Answer and explanation

C. (0.0407 − 0.0400) × 10,000 = +7 bp. These inputs are decimal rates, not percentage numbers. One bp equals 0.0001 in decimal-rate units.

25. The teaching gross-DV01 limit is 5,000/bp. Existing exposure is 1,500/bp and the proposal adds 3,500/bp. Under an inclusive limit, what happens?

  1. Reject equality automatically
  2. Pass with zero-headroom
  3. Ignore existing exposure
  4. Double available headroom
Answer and explanation

B. Projected exposure equals the limit, so it passes this stated policy with zero remaining headroom. Other limits still need checking. This is a synthetic policy, not a universal trading rule.

26. Two concurrent requests each pass a snapshot limit check, but their combined exposure exceeds the limit. What is missing?

  1. More decimal places
  2. Faster JSON parsing
  3. Larger response cache
  4. Atomic capacity reservation
Answer and explanation

D. Checking is not reserving. Serialize the relevant reservation/booking decision transactionally and reconcile retries. The current project explicitly implements only a nonbinding check, not this production control.

27. A downstream booking request times out after transmission. What is the safest next step?

  1. Reconcile operation identity
  2. Submit another trade
  3. Mark booking successful
  4. Delete RFQ history
Answer and explanation

A. The outcome is uncertain: the downstream system may have booked it. Recover status using the agreed operation identity/idempotency contract before retrying. A timeout proves neither success nor failure.

28. A trader's blotter consumes RFQs from an upstream Bloomberg-integrated service and links to existing pricers. Which ownership description is supported?

  1. Built Bloomberg connectivity
  2. Implemented pricing mathematics
  3. Integrated downstream workflows
  4. Executed autonomous trading
Answer and explanation

C. Describe the actual blotter integration, routing and handoff you owned. Do not claim direct Bloomberg connectivity, pricer implementation or autonomous execution without having done that work. Discuss event ordering, missing reference data and booking acknowledgments as boundaries.
