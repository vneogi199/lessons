Read enterprise data without changing its meaning

Read the example first, then draft the integration contract. The sandbox steps are an exercise for an authorized account. No SAP system, credentials or live results are supplied.

Which system owns the answer?

Think of an ERP as a set of connected business ledgers. The equipment register describes a pump. A maintenance order records work on that pump. The register is master data; the order is transactional data. A copied search index is not automatically the system of record.

SAP, Oracle NetSuite, Microsoft Dynamics and Tally are product families used for business operations. Their editions, customizations and interfaces differ. Ask which installation owns each record; do not infer an integration contract from a vendor name.

For SAP discovery, use this starting vocabulary: PM covers plant maintenance; CS covers customer service; MM covers materials management; SD covers sales and distribution; HR covers workforce-related data. Confirm current product terminology and ownership with the client. Employee access does not imply permission to read HR records.

Request a data dictionary, API catalogue, service owner, authorization matrix, sandbox, change policy and sample errors. Ask about duplicate equipment IDs, lookup codes, units, time zones, deleted records and freshness. Preserve source IDs as strings when leading zeros matter.

Try: two systems each contain equipment 0012. Can you join on that ID?

Not without an ownership rule. Use source/tenant plus ID, or an approved crosswalk. Record uncertain matches for review. A model's similarity guess cannot establish asset identity.

Read equipment through a versioned contract

SAP's Equipment API exposes equipment data through OData. The exact schema and operations depend on the release. Start from API_EQUIPMENT and inspect its metadata rather than inventing property names.

  1. Select the edition and API version. Check current sandbox availability and access conditions. Use only synthetic sandbox data; do not assume free access or permanent availability.
  2. Copy the documented sandbox base URL and authentication method into private configuration. Keep credentials out of source, URLs, screenshots and logs.
  3. Inspect $metadata. Record the equipment key, functional-location and maintenance-plant fields actually exposed. Read a small page using the documented entity set and supported query options.
  4. Normalize to your own equipment response: source ID, source timestamp, allowed display fields and freshness. Last maintenance date and assigned technician may need separate sources. Return null plus provenance when absent; do not fabricate them.
  5. Handle paging, empty results, permission failures, throttling and timeouts. Bound page count, response size and total duration. Only follow continuation URLs on approved origins and paths.
  6. Expose a read-only FastAPI tool with tenant authorization and a fixed upstream destination. The model supplies a validated equipment ID, not an arbitrary URL or raw OData expression.

For writes, independently verify permissions, concurrency controls, transaction behavior and retry safety. A timeout can leave the outcome unknown. Reconcile by a stable business key before retrying. A successful HTTP response can still require inspection of application-level results.

Try: the equipment API lacks technician assignment. Should your wrapper infer it?

No. Identify the authoritative scheduling source and document the join and freshness policy. Until then, mark the field unavailable. This is a contract gap, not a prompting problem.

Choose an integration boundary

REST/OData can expose a versioned service boundary. RFC is a remote-call mechanism; a BAPI exposes business operations through a defined interface. IDocs carry structured business messages, often asynchronously. None makes retries or authorization safe automatically. Confirm released interfaces and transaction rules for the client's system.

Cloud Integration in SAP Integration Suite, often called CPI, handles process messages through transformation and routing. Datasphere focuses on analytical data integration and modeling. A read-layer view can support reporting without becoming the write authority. See SAP's comparison.

A connector in Airbyte, Databricks or Foundry can reduce adapter work, but inspect extraction mode, deletion handling, permissions, lag, licensing and schema changes. MCP can wrap a narrow authorized tool; it does not discover business ownership or replace ERP access controls.

Optional SAP and field-service depth

Build an integration catalogue for five capabilities: create a maintenance order, read equipment, confirm an operation, create a notification and check material availability. For each, record the released API/BAPI identifier, version, input/output schema, return errors, permissions, commit behavior, idempotency strategy and reconciliation query. Have the SAP owner validate every row.

BAPI_ALM_ORDER_MAINTAIN appears in SAP integration material, but its availability is not proof that your tenant permits it. Do not guess four more function names to fill a table. Verify the catalogue against the installed release. See SAP's maintenance integration material.

Follow the domain chain: equipment sits at a functional location; a fault notification can lead to an order; operations require skills, time and parts; confirmations record performed work. A part reservation is not a goods issue. An available-stock reading is not a reservation. Service contracts, warranty and billing need separate ownership and checks.

For classic transaction codes such as IE01/IE03, IL01, IW31/IW32/IW33, IW51, MB21, MB1A and MMBE, ask the client to demonstrate the relevant workflow in its release. These are recognition aids, not instructions to run changes. Modern apps and supported replacements vary.

Separate response-time and resolution-time SLAs. Specify working calendars, pause conditions and priority rules. Technician dispatch needs skill validity, geography and availability. A nearest technician may be unqualified. Sensor-triggered maintenance needs unit validation, event timestamps, duplicate detection, sustained-condition rules and human review before consequential action.

For warranty, safety inspections and manufacturing compliance, identify the accountable domain reviewer and evidence-retention requirements. Do not infer legal applicability from a roadmap or let a model certify compliance.

Interview: why not query an analytical replica before dispatching a technician?

It may be too stale to establish current availability. Use it for trends if the freshness contract allows that. Confirm current operational state through its authoritative service before reserving or dispatching.

Practice: complete one catalogue row with an SAP owner, including a failed-call example. Rehearse how to handle an unknown write outcome. Ask your teaching assistant to review the contract before connecting a model.
