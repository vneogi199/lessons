Fiber nodes, reconciliation, render work, commit work, lanes, and scheduling

React converts component data into a user interface. React updates the interface when relevant data changes.

Senior practice for this track ↗ · The reading estimate excludes the lab and interview rehearsal.

A fiber records React's work for a component or host element. Render work calculates a candidate tree and can pause, restart or be abandoned. Commit applies the accepted host changes without time-slicing that commit. Keep render free of external effects because a proposed tree may never reach the screen. Fiber fields and lane numbers explain an implementation; they are not stable application APIs or database rollback guarantees.

01

Fiber nodes

A fiber is React's internal work record for a component or host element. Fiber trees let React pause and resume render work while keeping DOM mutations inside an atomic commit.

02

reconciliation

Reconciliation compares the previous and next element descriptions and decides which fibers can be reused. Element type, position, and key guide preservation or replacement.

03

render work

Render work computes desired UI and may be repeated or abandoned; keep it free of external side effects.

04

commit work

Commit work applies accepted changes to the host environment and coordinates relevant lifecycle work.

05

lanes

Lanes are internal priority buckets for pending React updates. They help the scheduler work on urgent updates first and defer or restart less urgent rendering.

06

scheduling

Scheduling decides which ready work gets execution resources and when. Queuing and priorities affect latency and fairness.
