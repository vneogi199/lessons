06 · Practical lab

Run timed problems using one repeatable loop from clarification through working code, edge tests, complexity, and a measured improvement note.

  1. Predict the state changes and one likely failure.
  2. Run the smallest working example and save the result.
  3. Change one condition, then run the same check again.
  4. Compare the evidence and explain the tradeoff.
function interviewLoop(problem) {
  const contract = clarify(problem, ["inputs", "outputs", "constraints", "invalid cases"]);
  const examples = testExamples(contract, ["normal", "empty", "boundary", "duplicate"]);
  const bruteForce = describeCorrectBaseline(contract);
  const invariant = stateInvariant(bruteForce);
  const optimized = improveBottleneck(bruteForce, contract.constraints);
  const code = implement(optimized, { communicate: true });
  const tests = runByHand(code, examples);
  return { code, tests, complexity: deriveComplexity(optimized), improvements: review(code) };
}

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace an interview scenario from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Solve one problem under time, then replay the recording and locate the first reasoning error.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Clarifications, invariant, examples, executable code, failing case, fix, and complexity.
