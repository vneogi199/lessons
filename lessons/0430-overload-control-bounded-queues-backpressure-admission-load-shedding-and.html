Overload control, bounded queues, backpressure, admission, load shedding, and degradation

An API defines communication rules. A distributed system coordinates work across processes and computers.

When arrivals exceed service capacity, unfinished work accumulates. Bound admission and queues before memory or latency becomes unbounded. The example limits active operations in one local object; it is neither a request-rate limit nor a fleet-wide bound. A hung operation keeps its slot. Define what callers receive when work is rejected and how upstream queues remain bounded too.

01

Overload control

Overload control bounds admission, queues, and concurrency so excess demand fails predictably instead of collapsing capacity.

02

bounded queues

Bounded queues cap waiting work by items, bytes or another explicit resource budget. When full, producers must wait, reject, shed or use an explicitly safe alternative; a queue bound does not itself bound active work or total upstream memory.

03

backpressure

Backpressure makes a fast producer slow, wait, shed, or reject when a consumer cannot safely keep up.

04

admission

Admission control decides whether new work may consume limited capacity using concurrency, queue, priority, quota, or resource budgets.

05

load shedding

Load shedding rejects selected work early when serving it would push the system beyond safe capacity and harm more requests.

06

degradation

Degradation deliberately reduces features or freshness to preserve essential service under pressure.

import assert from "node:assert/strict";
class Admission {
  #active = 0;
  #limit;
  constructor(limit) {
    if (!Number.isSafeInteger(limit) || limit < 1) throw new RangeError("positive integer limit required");
    this.#limit = limit;
  }
  async run(operation) {
    if (this.#active >= this.#limit) throw Object.assign(new Error("overloaded"), { status: 503, retryAfter: 1 });
    this.#active += 1;
    try { return await operation(); }
    finally { this.#active -= 1; }
  }
}

const admission = new Admission(1);
let release;
const active = admission.run(() => new Promise(resolve => { release = resolve; }));
let rejectedWorkRan = false;
await assert.rejects(admission.run(() => { rejectedWorkRan = true; }), { status: 503 });
assert.equal(rejectedWorkRan, false);
release("done");
assert.equal(await active, "done");
await assert.rejects(admission.run(() => { throw new Error("sync failure"); }), /sync failure/);
await assert.rejects(admission.run(async () => { throw new Error("async failure"); }), /async failure/);
assert.equal(await admission.run(async () => "slot restored"), "slot restored");
assert.throws(() => new Admission(NaN), RangeError);
// ponytail: per-instance, single-JS-isolate gate, not a fleet-wide rate limiter.
// No waiting queue is created. A hung operation holds its slot until it settles;
// release on actual completion, not merely when the caller stops waiting.
// Keep ingress and internal queues bounded. Shed before expensive parsing or
// fan-out, reserve capacity for health/control work, and offer a cheaper result
// only when its product semantics are explicit. Retry-After is illustrative,
// not a guarantee that capacity will be available one second later.
