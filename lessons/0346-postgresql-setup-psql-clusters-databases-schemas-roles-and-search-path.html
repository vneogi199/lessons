01

PostgreSQL setup

PostgreSQL setup establishes one reproducible server environment, a known client identity, and a safe namespace before experiments begin.

02

psql

psql is PostgreSQL's command-line client. It sends SQL and meta-commands, exposes connection state, and can stop scripts on the first error.

03

clusters

A PostgreSQL database cluster is a collection of databases managed by one server instance with shared cluster-level objects and a data directory. It does not mean a distributed deployment, and its stored data still exists when the server is stopped.

04

databases

A database is an isolated catalog and object namespace inside a PostgreSQL cluster. Normal SQL connections operate inside exactly one database.

05

schemas

A schema is a namespace inside a database. It groups objects and participates in name lookup, but it is not a separate storage or compute server.

06

roles

A role is PostgreSQL's unified identity and privilege object. A role may log in, own objects, inherit memberships, or act as a permission group.

07

search_path

search_path is the ordered list of schemas used to resolve unqualified object names. Writable schemas early in the path can turn name lookup into a security boundary.

-- psql script for an authorized disposable instance, not a shell script.
-- Start separately: psql -X --set ON_ERROR_STOP=1 postgres

CREATE ROLE app_owner NOLOGIN;
CREATE ROLE app_runtime LOGIN;
-- Provision credentials through the approved secret channel; no shared password.
CREATE DATABASE lessons OWNER app_owner;
\connect lessons
CREATE SCHEMA app AUTHORIZATION app_owner;
GRANT USAGE ON SCHEMA app TO app_runtime;
ALTER ROLE app_runtime IN DATABASE lessons SET search_path = app, pg_catalog;

       current_setting('search_path');
