Elastic Load Balancing

Elastic Load Balancing distributes traffic to registered targets using a selected balancer type, listeners, health rules and availability configuration. Application readiness and capacity remain explicit design inputs.

ALB

An Application Load Balancer routes supported HTTP-family requests using application information such as host and path. It owns client-facing protocol handling and separate target connections.

NLB

A Network Load Balancer routes supported transport flows to targets. Protocol, TLS termination, client-address preservation and connection lifetime determine its behavior; it does not provide ALB-style HTTP path rules.

listeners

A load-balancer listener accepts a configured protocol and port and applies forwarding or other supported actions. TLS listeners also need certificates and protocol policy.

target groups

Target groups define eligible backends, protocol/port and health behavior for forwarding. Registration, deregistration delay and health state affect new and in-flight traffic differently.

health checks

Health checks report a specific capability. Separate process liveness, readiness for traffic, and deeper dependency or business checks.

TLS

TLS protects a connection's confidentiality and integrity and authenticates peers according to its configuration. It does not replace application-level authorization.

connection behavior

Balancer connection behavior includes reuse, idle timeouts, source identity, draining and reset semantics. One long-lived connection can carry many requests, so connection counts need not measure request load.
