01

Relational modeling

Relational modeling organizes facts into relations with keys and constraints that preserve meaning under updates.

02

entities

Entities retain identity across changing attributes. Two records with identical fields need not represent the same entity.

03

relationships

Database relationships connect entities through keys and cardinality constraints rather than duplicated informal identifiers.

04

keys

Keys identify rows or connect them to other rows; uniqueness and nullability determine their guarantees.

05

functional dependencies

A functional dependency means one set of attributes determines another, guiding normalization and anomaly prevention.

06

normalization

Normalization separates facts according to keys and dependencies so one fact has one authoritative update location, reducing insertion, update, and deletion anomalies.

CREATE TABLE tenants (
  tenant_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name text NOT NULL UNIQUE
);
CREATE TABLE products (
  tenant_id bigint NOT NULL REFERENCES tenants,
  product_id bigint GENERATED ALWAYS AS IDENTITY,
  sku text NOT NULL,
  name text NOT NULL,
  PRIMARY KEY (tenant_id, product_id),
  UNIQUE (tenant_id, sku)
);
CREATE TABLE orders (
  tenant_id bigint NOT NULL,
  order_id bigint GENERATED ALWAYS AS IDENTITY,
  status text NOT NULL CHECK (status IN ('draft', 'placed', 'paid')),
  PRIMARY KEY (tenant_id, order_id),
  FOREIGN KEY (tenant_id) REFERENCES tenants
);
