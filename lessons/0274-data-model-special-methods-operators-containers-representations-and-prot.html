Data model, special methods, operators, containers, representations, and protocols

ELI5 example

Python can ask a list for its length with len. Your own container can support the same operation by implementing the corresponding special method, __len__.

This is a protocol: code relies on supported behavior. A special method must obey its operation's rules; giving a method the right name is not enough if its result is invalid.

Does a custom container need to inherit from list just to support len?

No. It can implement the length protocol itself.

Python operations use protocols implemented by special methods. A collection can support iteration or length, and a value can define comparison or arithmetic. These methods must agree with each other: ordering should remain consistent with equality, for example. Returning NotImplemented from an unsupported binary operation lets Python try the other operand's protocol. It is a return value, not an exception to raise.

Data model

Python's data model specifies protocols connecting objects to operations such as iteration, arithmetic, comparison, and context management.

special methods

Special methods connect Python syntax and built-ins to type-defined behavior. For implicit operations, Python generally looks them up on the type rather than the instance.

operators

Operators dispatch through type-specific methods and may return NotImplemented to allow another operand's protocol handling.

containers

Python containers hold objects and expose operations such as membership, iteration or indexed lookup. A list, set and dictionary have different protocols and costs; this is unrelated to operating-system containers.

representations

repr targets an informative developer representation; str targets readable display. Neither should accidentally expose secrets.

protocols

A protocol is a set of supported operations rather than a requirement to inherit one concrete implementation. Python's iteration, context-manager, numeric, and container behavior is protocol-driven.

from dataclasses import dataclass
from functools import total_ordering

@total_ordering
@dataclass(frozen=True)
class ScoreBoard:
    scores: tuple[int, ...]

    def __iter__(self):
        return iter(self.scores)
    def __len__(self):
        return len(self.scores)
    def __contains__(self, value):
        return value in self.scores
    def __lt__(self, other):
        if not isinstance(other, ScoreBoard):
            return NotImplemented
        return (sum(self), self.scores) < (sum(other), other.scores)
    def __repr__(self):
        return f"ScoreBoard(scores={self.scores!r})"

board = ScoreBoard((8, 13, 21))
assert len(board) == 3 and 13 in board and list(board) == [8, 13, 21]
a, b = ScoreBoard((1, 2)), ScoreBoard((3,))
assert a != b and a < b and not b < a
# Tuple tie-break keeps ordering consistent with dataclass structural equality.
# Comparing only sums while equality compares tuples would violate total ordering.
# https://docs.python.org/3/library/functools.html#functools.total_ordering
