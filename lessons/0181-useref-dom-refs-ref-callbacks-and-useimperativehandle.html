useRef, DOM refs, ref callbacks, and useImperativeHandle

React converts component data into a user interface. React updates the interface when relevant data changes.

Senior practice for this track ↗ · The reading estimate excludes the lab and interview rehearsal.

A ref holds a mutable value across renders. Changing it does not request a render, so displayed information usually belongs in state. DOM refs become available during commit and support actions such as focus. An imperative handle can expose only the few operations a parent needs instead of the entire node. Check the resulting focus behavior in a browser; a declared handle alone does not prove the interaction works.

useRef

useRef keeps a mutable value across renders without scheduling a render when it changes. It is suitable for DOM nodes and operational handles, not information that should appear on screen.

DOM refs

DOM refs expose committed nodes for imperative operations such as focus; they are not render-time data sources.

ref callbacks

Ref callbacks observe attachment and detachment and must manage any associated resources correctly.

useImperativeHandle

useImperativeHandle controls the small imperative API exposed through a ref. Use it sparingly when a parent truly needs actions such as focus or scroll, not as a replacement for props.
