Audit logs

An audit log is structured security evidence about an attempted important action. It records who did what to which target, when, from where, and with what outcome.

actors

An audit actor is the authenticated human, service, or delegated identity that attempted an action, including impersonator and effective user when both exist.

actions

An audit action is a stable machine-readable operation name such as user.disable, not only a free-form sentence.

targets

An audit target identifies the resource type and stable identifier affected or inspected by an action.

outcomes

An audit outcome records whether an attempt was allowed, denied, failed, or partially completed; denied attempts are important evidence too.

correlation

Correlation links audit events with the request, trace, job, approval, or provider event that caused them so an investigation can reconstruct one chain of work.

tamper evidence

Tamper evidence helps detect changed or missing records relative to a trusted reference. A hash chain alone can be rewritten or truncated by an attacker controlling the log; protect independent checkpoints and access. Detection is not prevention.

retention

Retention policy defines how long evidence remains searchable or archived, when it is deleted, and which legal, security, privacy, and cost rules govern that time.

privacy

Audit privacy minimizes or redacts secrets and personal data, restricts readers, logs access to evidence, and applies approved retention and deletion rules.

investigation

An investigation uses filtered, time-ordered, correlated evidence to answer which identity attempted which changes and what system state resulted.

An audit event records who attempted an action, its target and the outcome. Correlation lets an investigator follow related work across services. Hash linkage can reveal changed records only relative to trusted retained evidence; an attacker controlling the whole chain can rewrite it. The digest fixture demonstrates hashing. Durable append, protected checkpoints, redaction and access policy make it usable evidence.

import assert from "node:assert/strict";
import { createHash } from "node:crypto";

function auditDigest(previousHash, payload) {
  if (previousHash !== "GENESIS" && (typeof previousHash !== "string" || /^[0-9a-f]{64}$/.exec(previousHash)?.[0] !== previousHash)) throw new Error("invalid predecessor");
  if (typeof payload !== "string" || Buffer.byteLength(payload, "utf8") > 65_536) throw new Error("bounded payload required");
  return createHash("sha256").update(JSON.stringify(["audit-v1", previousHash, payload])).digest("hex");
}

async function appendAudit(event, auditStore, redactAndValidate) {
  // Adapter returns a bounded JSON-only schema: actor, action, target, outcome,
  // time, request ID and explicitly allowed changes. Never include raw secrets.
  const payload = JSON.stringify(redactAndValidate(event));
  await auditStore.transaction(async tx => {
    const previous = await tx.lockTail();
    const previousHash = previous?.hash ?? "GENESIS";
    const hash = auditDigest(previousHash, payload);
    await tx.insert({ payload, previousHash, hash });
  });
}

const payload = JSON.stringify({ actor: "user-1", action: "disable", outcome: "allowed" });
const hash = auditDigest("GENESIS", payload);
assert.equal(auditDigest("GENESIS", payload), hash);
assert.notEqual(auditDigest("GENESIS", payload.replace("allowed", "denied")), hash);
assert.notEqual(auditDigest(hash, payload), hash);
assert.throws(() => auditDigest("bad", payload));
assert.throws(() => auditDigest(hash + "\n", payload));
assert.throws(() => auditDigest("GENESIS", undefined));
assert.throws(() => auditDigest("GENESIS", "x".repeat(65_537)));

// Store and verify the EXACT payload string, not parsed/reserialized JSONB.
// This avoids inventing a JSON canonicalizer; it is not RFC 8785/JCS.
// lockTail must serialize even the empty-chain case, e.g. a dedicated chain row.
// Append-only DB role, separate immutable checkpoints and continuity verification
// are integration requirements. A local chain cannot detect an administrator who
// rewrites the entire chain or removes an unanchored tail. Redaction happens before
// hashing; retention/deletion needs an explicit checkpoint and privacy policy.
