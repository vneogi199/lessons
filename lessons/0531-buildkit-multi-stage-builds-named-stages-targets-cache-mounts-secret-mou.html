BuildKit, multi-stage builds, named stages, targets, cache mounts, secret mounts, SSH mounts, and outputs

Docker packages a program and its files in an image. A container runtime starts an isolated process from that image.

Senior practice for this track ↗ · The reading estimate excludes the lab and interview rehearsal.

Multi-stage builds let a runtime image copy only the outputs it needs from a build stage. BuildKit can evaluate independent parts of that graph and use temporary mounts. The wheel example still retains its wheel directory and depends on suitable ignore rules. Match runtime architecture and ABI, and check that a supposedly complete wheel set does not require unintended network downloads.

01

BuildKit

BuildKit evaluates a build dependency graph, parallelizes independent work, and supports ephemeral cache, secret, SSH, and bind mounts.

02

multi-stage builds

A multi-stage Dockerfile uses multiple FROM stages, optionally named, and copies selected artifacts between them. Keeping build tools out of the final stage can reduce its size and attack surface.

03

named stages

Named stages let later build steps reference an earlier stage explicitly in a multi-stage build.

04

targets

A build target chooses which stage to produce, useful for separate development, test, and runtime outputs.

05

cache mounts

Cache mounts retain reusable build data without making it part of the final image layer by default.

06

secret mounts

Secret mounts expose build secrets temporarily without intentionally baking them into layers; commands must still avoid copying or logging them.

07

SSH mounts

SSH mounts let build steps use forwarded authentication facilities without copying private keys into the image.

08

outputs

Build outputs select how results are exported, such as an image, local files, or registry content.

# syntax=docker/dockerfile:1
FROM python:3.13-slim AS build
WORKDIR /src
RUN --mount=type=cache,target=/root/.cache/pip     --mount=type=bind,source=requirements.txt,target=requirements.txt     pip wheel --wheel-dir /wheels -r requirements.txt

FROM python:3.13-slim AS runtime
WORKDIR /app
RUN useradd --uid 10001 --create-home app
COPY --from=build /wheels /wheels
RUN pip install --no-cache-dir /wheels/*
COPY --chown=app:app . /app
USER 10001
ENTRYPOINT ["python", "-m", "app"]
