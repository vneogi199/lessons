04 · Detailed term guide

How they connect: Follow one HTTP connection through ASGI scope creation, request events, middleware, routing, dependency solving, endpoint execution, response events, and disconnect.

01

ASGI scope

What it means: ASGI is the async server-to-application protocol. The server provides a connection scope and two callables: receive brings events in, and send emits response or WebSocket events.

02

receive

What it means: receive is the ASGI callable an application awaits for incoming body, WebSocket, lifespan, or disconnect events. It makes the protocol event-driven instead of hiding the connection.

03

send

What it means: send is the ASGI callable used to emit response-start, response-body, WebSocket, and lifespan events. Correct event order is part of the protocol contract.

04

Uvicorn

What it means: Uvicorn is the ASGI server process that owns sockets, parses protocol traffic, creates scopes and events, and calls the FastAPI application.

05

Starlette

What it means: Starlette supplies the ASGI web layer beneath FastAPI: routing, requests, responses, middleware, WebSockets, static files, and test infrastructure.

06

request lifecycle

What it means: The request lifecycle is the ordered path from accepted network data through routing, validation, dependencies, endpoint work, response sending, and cleanup.

# A complete minimal ASGI HTTP application.
async def app(scope, receive, send):
    assert scope["type"] == "http"
    event = await receive()
    assert event["type"] == "http.request"

    body = b'{"status":"ok"}'
    await send({
        "type": "http.response.start",
        "status": 200,
        "headers": [(b"content-type", b"application/json")],
    })
    await send({"type": "http.response.body", "body": body})

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace an HTTP request from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Trace one valid request and one failure while recording every ASGI event.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Scope fields, middleware order, dependency calls, send events, and client response.
