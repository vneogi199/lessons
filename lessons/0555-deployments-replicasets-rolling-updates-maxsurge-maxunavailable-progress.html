Deployments, ReplicaSets, rolling updates, maxSurge, maxUnavailable, progress, pause, and rollback

Kubernetes stores desired state in API objects. Controllers work continuously to make actual state match desired state.

Senior practice for this track ↗ · The reading estimate excludes the lab and interview rehearsal.

A Deployment creates a new ReplicaSet when its Pod template changes and adjusts old and new replica counts. Surge and unavailability settings constrain that process, provided capacity and readiness allow progress. Terminating Pods can still consume resources. A progress deadline reports a stalled rollout; it does not automatically supply a rollback policy or reverse committed application data.

Deployments

A Deployment manages ReplicaSets and performs declarative stateless rollouts while respecting availability and surge settings.

ReplicaSets

ReplicaSets maintain a desired count of matching Pods and commonly sit beneath Deployments.

rolling updates

Rolling updates replace Pods gradually under availability and surge constraints.

maxSurge

maxSurge bounds additional Pods above the desired replica count during a Deployment rolling update.

maxUnavailable

maxUnavailable bounds permitted unavailability during the relevant rollout strategy.

progress

Deployment progress records rollout advancement; a progress deadline failure does not automatically implement every desired rollback policy.

pause

Pausing a Deployment suspends further rollout processing while allowing controlled changes to accumulate.

rollback

Rollback abandons uncommitted database changes or returns a deployed component to an earlier version, depending on the boundary. Code rollback does not automatically undo committed data, emitted events, or external effects.

apiVersion: apps/v1
kind: Deployment
metadata: {name: evidence-api}
spec:
  replicas: 4
  strategy:
    rollingUpdate: {maxSurge: 1, maxUnavailable: 0}
  minReadySeconds: 10
  progressDeadlineSeconds: 300
  selector: {matchLabels: {app: evidence-api}}
  template:
    metadata: {labels: {app: evidence-api}}
    spec:
      containers:
      - name: api
        image: registry.example/api@sha256:DIGEST
        readinessProbe: {httpGet: {path: /ready, port: 8000}}
