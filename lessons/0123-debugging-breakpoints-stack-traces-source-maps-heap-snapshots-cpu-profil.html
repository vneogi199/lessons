01

Debugging

Debugging tests explanations for an observed failure. Reproduce the symptom, preserve evidence, isolate one cause, and verify a targeted change against the original case.

02

breakpoints

A breakpoint pauses execution at a selected location or condition so you can inspect values and control flow. Pausing can change concurrency and timing behavior.

03

stack traces

A stack trace records call locations associated with execution or failure. Match it to the deployed artifact and account for asynchronous boundaries and source maps.

04

source maps

A source map relates generated code locations to original source. Debuggers and error systems need the exact deployed map and artifact to reconstruct reliable stacks.

05

heap snapshots

A heap snapshot records objects and their retaining relationships at a point in time. Compare snapshots under controlled workloads to investigate unexpected retention.

06

CPU profiles

A CPU profile samples or records where execution spends CPU time. It does not directly measure time spent waiting for an external service.

07

tracing

A distributed trace connects spans of work across an operation, such as an HTTP request and its database calls. Sampling and missing instrumentation limit what a trace proves.

import assert from "node:assert/strict";
import test from "node:test";

function normalize(value) { return value.trim().normalize("NFC").toLowerCase(); }

for (const [input, expected] of [[" Ada ", "ada"], ["É", "é"]]) {
  test("normalize " + JSON.stringify(input), () => {
    assert.equal(normalize(input), expected);
    assert.equal(normalize(normalize(input)), expected); // idempotence property
  });
}

test("abort is observable", async () => {
  const controller = new AbortController();
  const reason = new Error("test cancellation");
  controller.abort(reason);
  await assert.rejects(
    () => fetch("https://example.invalid", { signal: controller.signal }),
    error => error === reason
  );
});
