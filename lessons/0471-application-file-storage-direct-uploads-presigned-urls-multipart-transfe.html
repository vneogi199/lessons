01

Application file storage

Application file storage keeps user-supplied bytes in an object store and stores ownership, state, policy, and display metadata separately in a database.

02

direct uploads

A direct upload sends file bytes from the client to object storage using a narrowly scoped temporary grant, so the application server does not relay the large body.

03

presigned URLs

A presigned URL is a bearer capability for a specific storage request, not a single-use token. S3 also checks credential validity and access policy, so it can fail before its stated expiry. An accepted download may continue after expiry.

04

multipart transfer

Multipart transfer divides a large object into independently retriable parts and completes them as one object. Abandoned part sets require lifecycle cleanup.

05

validation

File validation checks declared size and type, actual magic bytes, parser limits, checksums, ownership, and policy before the application trusts or serves content.

06

malware scanning

Malware scanning examines quarantined bytes with current detection tools before promotion. A clean result reduces risk but does not replace safe parsing and isolation.

07

metadata

File metadata records the stable object key, owner, original display name, media type, size, checksum, state, and retention dates without putting file bytes in normal relational rows.

08

lifecycle

A file lifecycle defines pending upload, quarantine, clean or rejected state, versions, retention, archival, expiration, and complete deletion of bytes and metadata.

09

delivery

File delivery authorizes every read and returns a short-lived private URL or controlled response with safe content type, disposition, caching, and range behavior.

from pathlib import PurePosixPath
from uuid import uuid4

ALLOWED = {"image/png", "image/jpeg", "application/pdf"}
MAX_BYTES = 25 * 1024 * 1024

def begin_upload(user, request, s3, db):
    if request.content_type not in ALLOWED or type(request.size) is not int or not 0 < request.size <= MAX_BYTES:
        raise ValueError("unsupported file")
    upload_id = str(uuid4())
    key = "quarantine/" + upload_id  # Server-generated key, tenant ownership lives in DB.
    db.files.insert({"id": upload_id, "owner": user.id, "key": key,
                     "name": request.display_name, "checksum": request.checksum, "size": request.size,
                     "state": "pending"})
    return s3.generate_presigned_post(
        Bucket="private-uploads", Key=key,
        Fields={"Content-Type": request.content_type,
                "x-amz-checksum-sha256": request.checksum},
        Conditions=[{"Content-Type": request.content_type},
                    {"x-amz-checksum-sha256": request.checksum},
                    ["content-length-range", 1, MAX_BYTES]],
        ExpiresIn=600,
    )

def complete_upload(user, upload_id, s3, db, jobs):
    record = db.files.require_owner(upload_id, user.id)
    head = s3.head_object(Bucket="private-uploads", Key=record.key, ChecksumMode="ENABLED")
    version = head.get("VersionId")
    if not version or version == "null":
        raise ValueError("versioned bucket required")
    if head["ContentLength"] != record.size or head.get("ChecksumSHA256") != record.checksum:
        raise ValueError("stored object failed validation")
    with db.transaction():
        # Adapter atomically compares state and records this immutable version.
        # A repeat returns false only for the same already-accepted version;
        # a competing different version must raise, not silently replace it.
        if db.files.accept_version(upload_id, "pending", "quarantined", version):
            jobs.insert_once("scan:" + upload_id, {"file_id": upload_id, "version_id": version})

# jobs is a same-database durable job/outbox adapter, not a remote queue client.
# A presigned upload can be reused until expiry. Scan and copy this exact VersionId,
# never the mutable latest key; publish only the version whose scan passed.
# Configure bucket versioning, validate the base64 SHA-256 input, authorize tenant
# ownership, bound display-name metadata, and supply checksum/KMS permissions.
# Scanner validates magic bytes, malware result, and page/image limits before
# moving to a non-public clean prefix. Downloads require authorization and a
# short-lived URL with safe Content-Disposition; deletion removes bytes and metadata.

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace a file upload lifecycle from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Upload a valid file, a mislabeled executable, an oversized multipart file, and an abandoned upload; then revoke download access.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Grant conditions, object checksum and size, multipart state, scanner result, metadata transition, authorization decision, lifecycle action, and bytes removed.
