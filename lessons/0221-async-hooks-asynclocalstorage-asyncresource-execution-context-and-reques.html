04 · Detailed term guide

How they connect: Trace async resource creation, trigger relationships, callback execution, destruction, and context propagation through supported boundaries.

01

async_hooks

What it means: async_hooks exposes lifecycle events for asynchronous resources and their trigger relationships. Direct hooks are low-level and can add overhead or recursion risk.

02

AsyncLocalStorage

What it means: AsyncLocalStorage associates a store with an asynchronous execution chain so request context can be read without unsafe process-global mutation.

03

AsyncResource

What it means: AsyncResource lets a custom async abstraction create a resource boundary and invoke callbacks within the correct async context.

04

execution context

What it means: exec runs a command string through a shell and buffers output, making untrusted interpolation dangerous and large output expensive.

05

request correlation

What it means: Request correlation carries a bounded identifier through logs, metrics, traces, and downstream calls so events from one operation can be connected.

06 · Practical lab

Attach a request ID with AsyncLocalStorage and verify propagation through timers, promises, fetch, and a custom AsyncResource.

  1. Predict the state changes and one likely failure.

  3. Change one condition, then run the same check again.

import { AsyncLocalStorage, AsyncResource } from "node:async_hooks";
import { randomUUID } from "node:crypto";

const context = new AsyncLocalStorage();

function log(event) {
  console.log({ event, requestId: context.getStore()?.requestId });
}

async function handle() {
  await Promise.resolve();
  await new Promise(resolve => setTimeout(resolve, 1));
  log("handled");
}

await context.run({ requestId: randomUUID() }, handle);

const resource = new AsyncResource("lesson-resource");
resource.runInAsyncScope(() => context.run({ requestId: "custom" }, log), null, "custom");
resource.emitDestroy();

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace an event-loop operation from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Trace one operation with async hooks and inject a timeout or shutdown.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Async IDs, handle count, event-loop delay, response, and exit sequence.
