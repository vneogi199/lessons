Node streams

Node streams implement incremental I/O with buffering, backpressure, errors, and destruction protocols.

Web Streams

WHATWG Web Streams use readers, writers, controllers, locking, and queuing strategies. Node provides adapters, but lifecycle details differ from classic Node streams.

adapters

Stream adapters bridge Node and Web Stream protocols, with possible differences in buffering and cancellation behavior.

fetch bodies

Node fetch provides a Web-standard client implemented on Undici, including streaming bodies and AbortSignal while hiding lower dispatcher and pool details.

compression

Compression reduces bytes using CPU and buffering; limit decompressed output and handle partial-input failures.

interoperability

Interoperability aligns contracts across APIs or module systems rather than assuming similar names imply identical behavior.

import { createReadStream, createWriteStream, promises as fs } from "node:fs";
import { createGzip } from "node:zlib";
import { pipeline } from "node:stream/promises";
import { dirname, join } from "node:path";

async function gzipFile(source, target, signal) {
  // Trusted paths; stage on the target filesystem in a directory owned by this call.
  const directory = await fs.mkdtemp(join(dirname(target), ".gzip-"));
  const temporary = join(directory, "output.gz");
  try {
    await pipeline(
      createReadStream(source), createGzip(),
      createWriteStream(temporary, { flags: "wx", mode: 0o600 }), { signal }
    );
    await fs.rename(temporary, target);
  } finally {
    await fs.rm(directory, { recursive: true, force: true });
  }
}
// await gzipFile("input.ndjson", "input.ndjson.gz", AbortSignal.timeout(5000));
// A shared .tmp name can overwrite or delete another call's work. Unique staging
// prevents that, but successful concurrent replacements still have last-writer wins.
// ponytail: replacement is not crash-durability proof; add file/directory fsync
// and platform-specific failure tests when persistence across power loss matters.
