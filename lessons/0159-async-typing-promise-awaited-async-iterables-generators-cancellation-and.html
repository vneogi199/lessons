Async typing

Async typing models eventual and streamed values through Promise, AsyncIterable, and AsyncGenerator contracts. It does not model event-loop scheduling or guarantee cancellation.

Promise

Promise<T> describes eventual fulfillment with T. It does not encode a rejection type, deadline, cancellation, or concurrency limit.

Awaited

Awaited recursively models how await unwraps promises and thenables and distributes through null or undefined according to the built-in utility definition.

async iterables

An async iterable supplies values through asynchronously resolved iterator results. Consumers must still handle errors, cleanup, and bounded work.

generators

Generator types describe yielded, returned, and received values. Async generators wrap protocol results in asynchronous delivery.

cancellation

Cancellation requests that work stop. Each participating API must cooperate, and cleanup still needs an owner; cancelling a wait may leave an external operation running.

error channels

Errors can be thrown, rejected, or returned as explicit result variants. Choose a consistent boundary contract and preserve useful causes.

Promise<T> describes the fulfilled value, not the rejection type or the operation's deadline. Async iterable and generator types describe streamed protocol values without limiting total work. Cancellation still requires cooperation and cleanup. In the pagination exercise, check HTTP errors and malformed pages as well as early consumer exit. Cursor loops, page limits and URL policy need explicit controls before the generator becomes a service component.

type Page<T> = { items: T[]; nextCursor?: string };

async function* pages<T>(
  firstUrl: URL,
  parse: (input: unknown) => Page<T>,
  signal: AbortSignal
): AsyncGenerator<T, number, void> {
  let url: URL | undefined = firstUrl;
  let count = 0;
  while (url) {
    signal.throwIfAborted();
    const response = await fetch(url, { signal });
    if (!response.ok) throw new Error("page request failed: " + response.status);
    const page = parse(await response.json());
    for (const item of page.items) {
      signal.throwIfAborted();
      count += 1; yield item;
    }
    const next: URL | undefined = page.nextCursor ? new URL(page.nextCursor, url) : undefined;
    if (next && next.origin !== firstUrl.origin) throw new Error("cross-origin page URL");
    url = next;
  }
  return count;
}

// Types express values and protocol slots. They do not enforce deadlines,
// schedule work, cancel losing operations, or make rejection exhaustive.

Check your understanding

Async types describe eventual values and iterator protocol slots, not timeouts, concurrency limits, or cancellation guarantees.

Answer before opening

The generator checks HTTP status and cancellation, but still needs a trusted URL policy, redirect controls, repeated-cursor detection, page/item limits, and a deadline. Same-origin cursor checks alone are not an SSRF defense.
