Isolation levels

An isolation level defines which concurrent histories a transaction may observe. Stronger levels prevent more anomalies but can abort work that must be retried.

Read Committed

In PostgreSQL Read Committed, an ordinary SELECT sees a snapshot taken when that statement starts. A later statement in the same transaction can see newly committed changes.

Repeatable Read

PostgreSQL Repeatable Read uses a transaction snapshot for ordinary queries. It prevents changing snapshots but can still allow serialization anomalies such as write skew.

Serializable

Serializable transactions must have an outcome consistent with some serial execution. PostgreSQL can abort a transaction to preserve that guarantee, so callers must be able to retry the whole transaction.

anomalies

Transaction anomalies are surprising outcomes permitted by an isolation level, such as stale reads or conflicting concurrent decisions.

SSI

Serializable Snapshot Isolation detects dangerous dependency patterns and may abort transactions to preserve serializable behavior.

Isolation determines which concurrent history a transaction can observe. Read Committed uses statement snapshots; Repeatable Read keeps a transaction view but can permit write skew. Serializable rejects histories that cannot match a serial outcome. The caller must retry the whole transaction with fresh reads after a serialization failure. It does not run all transactions one at a time or turn an invariant rejection into a retryable error.

SELECT count(*) FROM duty WHERE shift_id = 7 AND on_call;
UPDATE duty SET on_call = false
WHERE shift_id = 7 AND doctor_id = $1 AND on_call
  AND (SELECT count(*) FROM duty WHERE shift_id = 7 AND on_call) > 1;
