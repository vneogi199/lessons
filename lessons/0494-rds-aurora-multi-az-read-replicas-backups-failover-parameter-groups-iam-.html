RDS

RDS manages database infrastructure tasks while the customer still owns schema, queries, connections, access, migrations, performance, and recovery verification.

Aurora

Amazon Aurora separates database compute from managed replicated cluster storage under engine-specific contracts. Writer/reader endpoints, failover and recovery semantics differ from a conventional standalone database.

Multi-AZ

Multi-AZ database deployments place supported database components across zones for resilience. Traditional RDS standby instances and readable Multi-AZ cluster replicas have different roles; identify the deployment type.

read replicas

Read replicas serve eligible read traffic with an explicit replication and freshness contract. They may lag and do not automatically preserve every session's read-your-writes behavior.

backups

Backups retain recoverable database state independently of the current serving copy. Retention, encryption-key access, restore duration and validation determine practical recovery.

failover

Failover transfers responsibility after a failure. Detecting failure, preventing two active owners, and preserving acknowledged data are separate problems.

parameter groups

Database parameter groups collect engine configuration applied at instance or cluster scope. Changes may apply dynamically or require restart, so review engine/version and rollout effects.

IAM auth

IAM database authentication uses supported temporary authentication tokens to establish database connections. Database users, privileges, TLS and token generation remain configured separately from IAM permission to connect.

RDS Proxy

RDS Proxy manages database connection pools and supported authentication/failover behavior. Session pinning and transaction state affect multiplexing; it cannot resolve every unknown commit outcome.
