01

Production image optimization

Image optimization removes unnecessary content while preserving required runtime libraries, diagnostics, and operational behavior.

02

dependency caching

Dependency caching reuses installation work when relevant inputs are unchanged, without substituting for pinned dependencies.

03

distroless

Distroless images omit many general-purpose tools, reducing content while requiring another debugging approach.

04

resource limits

Resource limits bound consumption or admission, such as memory, CPU, payload size, or concurrency. Define rejection and recovery behavior.

05

immutability

Image immutability means a content digest continues to identify the same image bytes/configuration. Running containers still have mutable state unless constrained, and tags can point to new digests.

06

operational tradeoffs

Operational trade-offs compare image size, startup, security, diagnostics, portability, and recovery under real constraints.

Common mistakes

Memorizing the label

A definition is not enough. Trace an image build and delivery from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Change one dependency and predict exactly which build nodes invalidate.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Context size, build log, cache hits, layer history, digest, SBOM, and signature.
