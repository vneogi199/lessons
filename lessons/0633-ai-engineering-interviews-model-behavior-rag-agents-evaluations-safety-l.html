AI engineering interviews

An AI engineering interview tests product and systems judgment around probabilistic behavior, data, retrieval, tools, evaluations, safety, serving, latency, cost, and monitoring.

model behavior

Model-behavior reasoning explains probabilistic outputs, context limits, failure modes, and what evaluation evidence supports deployment.

RAG

RAG interview evidence covers retrieval quality, permissions, context construction, grounding, freshness, and evaluation rather than only vector-database selection.

agents

Agent interview evidence explains tool authority, state, termination, retries, cost limits, and recoverable failures.

evaluations

Evaluation evidence ties datasets, metrics, grading, critical slices, and uncertainty to a concrete release decision.

safety

Safety reasoning identifies harmful outcomes and controls, including tool permissions and data exposure, without claiming a prompt guarantees protection.

latency

Latency is elapsed time between a defined start and completion boundary. Specify that boundary and report a distribution; an average can hide slow requests.

cost

Cost reasoning connects workload and usage to unit economics, including retries, idle resources, data transfer, and model tokens.
