01

Transactions

A PostgreSQL transaction groups transactional changes into one commit or rollback boundary. Sequence increments and external effects are not generally rolled back; durability of acknowledged commits depends on configured flush and replication guarantees.

02

ACID

ACID summarizes transaction guarantees: atomic outcome, preserved invariants, controlled concurrent visibility, and survival of acknowledged commits.

03

autocommit

Autocommit runs statements in separate transactions unless an explicit transaction groups them.

04

BEGIN

BEGIN starts an explicit transaction whose subsequent operations share a transaction boundary.

05

savepoints

Savepoints permit rollback of part of a transaction without abandoning all prior work.

06

commit

COMMIT requests successful transaction completion; durability depends on database configuration and covered failure assumptions.

07

rollback

Rollback abandons uncommitted database changes or returns a deployed component to an earlier version, depending on the boundary. Code rollback does not automatically undo committed data, emitted events, or external effects.

BEGIN;
SET LOCAL statement_timeout = '3s';
SELECT balance_cents FROM accounts WHERE id = 10 FOR UPDATE;
SELECT balance_cents FROM accounts WHERE id = 20 FOR UPDATE;
UPDATE accounts SET balance_cents = balance_cents - 500 WHERE id = 10;
SAVEPOINT credited;
UPDATE accounts SET balance_cents = balance_cents + 500 WHERE id = 20;
INSERT INTO transfers(request_id, from_id, to_id, amount_cents)
VALUES ('req-42', 10, 20, 500);
COMMIT;

-- A UNIQUE(request_id) conflict rolls back this transaction; it does not by
-- itself return a successful replay. Persist intent and result with the transfer,
-- compare repeated intent, and check account existence and sufficient funds.
