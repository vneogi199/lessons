TaskGroup, cancellation, timeouts, queues, semaphores, and backpressure

ELI5 example

Orders arrive faster than one worker can handle them. An unlimited waiting list keeps growing. A bounded queue forces a decision when it fills: wait, reject or reduce incoming work.

This is backpressure. A semaphore limits concurrent work, while a timeout limits how long a caller waits. Cancellation needs cleanup and does not necessarily undo work already completed elsewhere.

Does a timeout prove an external operation did nothing?

No. The operation may have completed even if its result was not received.

TaskGroup keeps child tasks within an owned lifetime and waits for their cleanup. When a worker fails, it cancels siblings and collects failures. Cancellation is delivered at a suspension point, so cleanup must account for it. A bounded queue limits waiting items, a semaphore limits active permits, and a timeout limits waiting time. These controls address different limits; none makes an external effect reversible.

01

TaskGroup

TaskGroup owns a set of child tasks as one structured lifetime. It waits for cleanup and combines independent failures before the block exits.

02

cancellation

Async cancellation injects CancelledError at a suspension point. Code should release resources in finally and usually propagate cancellation after cleanup.

03

timeouts

A timeout limits how long a caller waits. It does not prove that the underlying operation stopped or that a remote side effect did not happen.

04

queues

A queue holds work waiting to be processed. Define capacity, admission, ordering, acknowledgement, retry, and expiration; a queue cannot create processing capacity.

05

semaphores

A semaphore controls access using a count of permits. It can bound concurrent operations, but the waiting queue and cancellation behavior also need limits.

06

backpressure

Backpressure makes producers slow down when consumers or resources reach capacity. Bounded queues and semaphores turn overload into controlled waiting or rejection.

import asyncio

async def worker(name: str, queue: asyncio.Queue[int | None]) -> None:
    while True:
        item = await queue.get()
        try:
            if item is None:
                return
            async with asyncio.timeout(1):
                await process(item)
        finally:
            queue.task_done()  # Includes every sentinel put into the queue.

processed = []
async def process(item: int) -> None:
    await asyncio.sleep(0)
    if item < 0:
        raise ValueError("synthetic failure")
    processed.append(item)

async def main(items: list[int]) -> None:
    queue = asyncio.Queue(maxsize=20)
    async with asyncio.TaskGroup() as group:
        for index in range(4):
            group.create_task(worker(f"w-{index}", queue))
        for item in items:
            await queue.put(item)  # bounded admission is backpressure
        for _ in range(4):
            await queue.put(None)
        await queue.join()

async def check():
    async with asyncio.timeout(2):
        await main(list(range(100)))
    assert sorted(processed) == list(range(100))
    failed = False
    try:
        async with asyncio.timeout(2):
            await main([-1, 2, 3])
    except* ValueError:
        failed = True
    assert failed

asyncio.run(check())
# TaskGroup cancels siblings and propagates failure; this in-memory queue is
# not durable. task_done is queue accounting, not proof of a committed effect.
# The timeout check catches the old sentinel-accounting deadlock.
