01

Node.js with TypeScript

Node TypeScript code must align compile-time resolution and platform types with Node's actual ESM or CommonJS loader, process lifecycle, and runtime input.

02

ESM

ESM is the import/export module system. Package type, extensions, emitted syntax, and host resolution jointly determine runtime loading.

03

configuration

Configuration selects checks, platform assumptions, file discovery, and output behavior. Record effective options rather than trusting inherited defaults.

04

processes

Processes own runtime resources, signals, and exit status. Type annotations do not stop admission or drain work during shutdown.

05

streams

Streams deliver chunks under backpressure and lifecycle rules. Chunk types do not enforce bounded buffering, cancellation, or resource cleanup.

06

errors

An error value needs classification, cause preservation, and a safe external representation. unknown catches require evidence before property access.

07

service boundaries

Service boundaries separate independently failing or evolving components. Validate inputs and define authorization, timeouts, and version compatibility explicitly.

Build a typed ESM service entry point with validated configuration and graceful shutdown.

Service integration sketch: serve is an adapter the learner must implement. Requires Node types and matching ESM configuration. Test invalid configuration and SIGTERM with active work; record deadline and resource closure.

import process from "node:process";

type Config = { port: number; shutdownMs: number };
function loadConfig(env: NodeJS.ProcessEnv): Config {
  const port = Number(env.PORT ?? "3000");
  const shutdownMs = Number(env.SHUTDOWN_MS ?? "10000");
  if (!Number.isInteger(port) || port < 1 || port > 65535) throw new Error("invalid PORT");
  if (!Number.isFinite(shutdownMs) || shutdownMs < 0) throw new Error("invalid SHUTDOWN_MS");
  return { port, shutdownMs };
}

const config = loadConfig(process.env);
const controller = new AbortController();
process.once("SIGTERM", () => controller.abort(new Error("SIGTERM")));

try { await serve(config, controller.signal); }
catch (error: unknown) {
  console.error(error instanceof Error ? error.message : String(error));
  process.exitCode = 1;
}

Understand, challenge, verify

Node executes JavaScript under a concrete module and process model; successful type checking does not guarantee loading or shutdown behavior.

Senior reasoning checkpoint — answer before opening

Aborting a controller is a signal, not a shutdown implementation. Stop admission, drain within a deadline, close owned resources, and preserve exit errors. Reject malformed configuration before binding a port.
