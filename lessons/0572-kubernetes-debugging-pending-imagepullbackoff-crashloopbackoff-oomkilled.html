Treat Kubernetes status labels as starting points for diagnosis. ImagePullBackOff concerns image retrieval, while CrashLoopBackOff calls for prior exit and log evidence. OOMKilled needs memory and node context. Preserve owner, UID and termination reason before changing the workload. Kubernetes debugging

Kubernetes debugging traces desired state, scheduling, startup, readiness, networking, and application behavior in order.

Pending

A Pending Pod has been accepted but its containers are not yet set up to run. Scheduling constraints and image preparation are different possible causes; inspect conditions and events.

ImagePullBackOff

ImagePullBackOff means Kubernetes is backing off failed image pulls. Check the image reference, registry access, credentials, and events.

CrashLoopBackOff

CrashLoopBackOff describes delayed retries after repeated container failures. It is a symptom, not a root cause; inspect previous logs, exit reason, configuration, and probes.

OOMKilled

OOMKilled reports termination due to an out-of-memory condition. Inspect container limits, actual memory use, and node evidence before assuming the application has a leak.

DNS

DNS resolves names to records such as addresses using a distributed hierarchy and caches. Record lifetimes, resolver behavior, and negative caching affect changes and failures.

networking

Cluster networking connects Pods and Services under routing, DNS, and policy rules implemented by installed components.

storage

Cluster storage coordinates claims, provisioning, attachment, mounting, and application consistency across workload lifetimes.

nodes

Nodes supply execution capacity through kubelet, a container runtime, networking, and host resources.
