System design method, requirements, estimation, Little's Law, capacity, and bottlenecks

01 · Beginner foundation

This topic belongs to APIs and distributed systems. An API defines communication rules. A distributed system coordinates work across processes and computers.

Input → output
Something starts the operation. The system returns a value, effect, message, or error.
Boundary and state
A boundary separates system parts. State is information a part keeps or changes.
Mechanism and evidence
The mechanism does the work. A test, log, trace, or state change shows what happened.
Failure and tradeoff
A failure mode describes how it can break. A tradeoff is the cost of choosing one solution over another.

06 · Practical lab

Lead a timed design using requests per second, object size, retention, concurrency, latency, availability, and cost estimates and identify the first likely bottleneck.

  1. Predict the state changes and one likely failure.
  2. Run the smallest working example and save the result.
  3. Change one condition, then run the same check again.
  4. Compare the evidence and explain the tradeoff.
const estimate = {
  writesPerSecond: 2_000,
  readsPerSecond: 20_000,
  averageObjectBytes: 4_096,
  retentionDays: 365,
  peakFactor: 4,
  targetP99Ms: 300
};

estimate.annualRawBytes = estimate.writesPerSecond * estimate.averageObjectBytes * 86_400 * estimate.retentionDays;
estimate.peakRequestsPerSecond = (estimate.writesPerSecond + estimate.readsPerSecond) * estimate.peakFactor;
estimate.averageConcurrency = estimate.peakRequestsPerSecond * (estimate.targetP99Ms / 1000); // conservative Little's Law input
console.table(estimate);

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace a distributed request or message from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Change one dominant constraint after the first design and evolve it without discarding guarantees.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Estimates, diagram, invariant table, critical trace, load curve, failure result, SLO, cost, migration steps, and rollback.
