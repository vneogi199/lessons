API security

API security combines authentication, authorization, input limits, safe outputs, and protection against valid-looking abusive requests.

threat modeling

Threat modeling identifies assets, actors, trust boundaries, abuse paths, controls, and residual risks before security work becomes a checklist.

injection

Injection occurs when untrusted data is interpreted as instructions by a command, query, template, or other interpreter. Preserve the data/code boundary with the appropriate safe API.

SSRF

Server-side request forgery tricks a server into making attacker-chosen network requests with the server's reachability or credentials.

mass assignment

Mass assignment binds untrusted fields directly onto a domain object, allowing clients to set properties they were never authorized to control.

abuse resistance

Abuse resistance limits exploitation of legitimate functionality, such as enumeration or expensive query patterns.

Threat modeling follows assets through specific trust boundaries. An allowlisted update shape prevents arbitrary field assignment, but changing an allowed field may still require permission. An outbound destination policy needs enforcement through URL parsing, resolution, connection, redirects and body reads. Declaring it in configuration alone provides no protection. function writableProjectFields(input) {
  if (!input || typeof input !== "object" || Array.isArray(input) ||
      Object.keys(input).some(key => !["name", "visibility"].includes(key)) ||
