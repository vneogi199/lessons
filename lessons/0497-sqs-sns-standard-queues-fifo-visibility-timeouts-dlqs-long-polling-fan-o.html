SQS

SQS durably buffers messages between producers and consumers. Standard queues deliver at least once, so visibility timeouts and idempotent consumers are central.

SNS

Amazon SNS publishes notifications to independently configured subscriptions. Endpoint type, topic type, retries and subscription filtering determine delivery semantics.

standard queues

SQS standard queues provide at-least-once delivery and best-effort ordering under the service contract. Repeated or out-of-order deliveries require application-level handling.

FIFO

SQS FIFO queues order work within message groups and provide bounded producer deduplication. Visibility expiry can still repeat processing; external business effects need their own duplicate protection.

visibility timeouts

A visibility timeout temporarily hides a received SQS message from normal delivery. It does not stop the worker when it expires; successful processing must delete the correct delivery receipt.

DLQs

Dead-letter queues retain messages redirected after configured delivery failures. Retention, alarms, ownership and authorized redrive are necessary to recover useful work.

long polling

SQS long polling waits for available messages up to a configured duration instead of repeatedly returning empty immediately. Client timeouts must permit the wait, and processing still needs bounded concurrency.

fan-out

Fan-out sends one publication to multiple independent consumers or subscriptions. Each branch has its own delivery, failure, authorization and cost implications.

idempotency

Idempotency means repeating the same logical operation has the same intended effect as applying it once. It does not require every response, log, or timestamp to be identical.
