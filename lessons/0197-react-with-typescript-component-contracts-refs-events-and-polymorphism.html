React with TypeScript models component and event relationships statically while retaining runtime and accessibility obligations.

02

component contracts

Component contracts state supported props, outputs, state ownership, and accessible interaction behavior.

03

refs

Refs retain mutable references without triggering renders; avoid using them as hidden render state.

04

events

React event handlers respond to browser interactions through React's event system. Capture, bubbling, default behavior and the component's current render snapshot determine what each handler observes.

05

polymorphism

Polymorphic components vary their rendered element while preserving valid props and accessibility; excessive flexibility complicates callers and tests.

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace a render and commit cycle from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Change one input or key and predict which component state is preserved.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: React DevTools, render count, DOM mutations, focus, and displayed state.
