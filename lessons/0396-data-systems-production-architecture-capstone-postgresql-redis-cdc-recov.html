Reconcile them before resuming consumers and keep cache availability separate from durable acceptance.

Data systems production architecture capstone

The capstone combines PostgreSQL as authoritative state with Redis as optional acceleration, then proves consistency, recovery, security, and capacity through failure experiments.

PostgreSQL

PostgreSQL is a relational database with transactional constraints and extensibility; model its actual isolation and durability contract.

Redis

Redis provides in-memory data structures with configurable persistence and replication; treat cache, coordination, and durable-state uses differently.

CDC

Change data capture exposes committed data changes for downstream processing, with explicit position and schema-evolution handling.

recovery

Recovery restores a usable state after failure. Specify which data and effects survive, how work resumes, and how restoration is verified.

performance

Performance describes latency, throughput, and resource cost under a defined workload. Report measurements and bottlenecks, not just asymptotic claims.

operations

Operations covers running, observing, changing, and recovering a service, with named owners and tested procedures.

# Transaction contract:
# 1. Authenticate and authorize tenant; validate payload and request key.
# 2. Claim UNIQUE(tenant_id, request_id), saving canonical intent.
# 3. Existing claim: read its saved result in a separate READ COMMITTED statement,
#    reject changed intent, and return the original job ID without another write.
# 4. New claim: INSERT job, INSERT outbox event, and save the returned job ID
#    in the receipt, all on the same connection and in one transaction.
# 5. Commit before responding. An exception rolls back all three records.
#
# Failure checks and expected evidence:
# - Concurrent identical submissions: one job, one event, same returned job ID.
# - Same key + changed payload: conflict, no new job; another tenant is isolated.
# - Crash before commit: no partial records. Crash after commit before response:
#   retry returns the existing result rather than accepting another job.
# - Relay publishes then crashes before marking sent: duplicate delivery is
#   allowed, but the consumer inbox and local business effect commit together.
# - Redis unavailable: PostgreSQL acceptance remains durable subject to the
#   documented backlog limit; reject excess work explicitly, not silently.
# - Restore drill: measure missing accepted jobs against the declared RPO.
