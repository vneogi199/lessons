01 · Beginner foundation

This topic belongs to cloud computing and AWS. Cloud services provide computing resources through network APIs. AWS groups these resources by account, Region, and service.

Input → output
Something starts the operation. The system returns a value, effect, message, or error.
Boundary and state
A boundary separates system parts. State is information a part keeps or changes.
Mechanism and evidence
The mechanism does the work. A test, log, trace, or state change shows what happened.
Failure and tradeoff
A failure mode describes how it can break. A tradeoff is the cost of choosing one solution over another.

def handler(event, context):
    message_id = event["Records"][0]["messageId"]
    if idempotency.claim(message_id) is False:
        return {"duplicate": True}
    try:
        process(event["Records"][0]["body"], deadline_ms=context.get_remaining_time_in_millis())
        return {"ok": True}

        idempotency.release(message_id)

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace a concurrent task from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Change one identity, Region, quota, or dependency and predict the API and workload outcome.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: AWS API response, resource state, CloudTrail, CloudWatch, quota, cost, and client behavior.
