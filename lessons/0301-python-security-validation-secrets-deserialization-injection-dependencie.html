Python security, validation, secrets, deserialization, injection, dependencies, and hardening

ELI5 example

A visitor types a name into a form. Treat that value as data even if it contains characters that resemble a command or query.

Use parameterized queries, validate permitted operations and keep secrets out of source code. Valid input format does not establish permission: a well-formed account ID can still belong to another user.

Does a valid account-ID format prove the caller may access it?

No. Authorization must check access separately.

Identify each point where untrusted data can influence an operation. Parse input under size limits, use safe query and command APIs, and check permission before accessing protected data. Paths and external tools have their own rules. Keep secrets out of source and logs, restrict privileges, and review dependency trust. Validation alone cannot contain arbitrary code execution or prevent resource exhaustion without corresponding limits.

Python security

Python security begins at trust boundaries: parse input, parameterize interpreters, authorize actions, bound resource use, protect secrets, and avoid executable data formats.

validation

Validation checks input against explicit rules before relying on it. Structure, length, range, allowed values, and business constraints may require different checks.

secrets

Secrets are credentials or sensitive values that grant access, such as tokens and private keys. Limit their scope and lifetime, rotate them, and exclude them from source and logs.

deserialization

Deserialization reconstructs values from external representations and may be unsafe or insufficiently validated depending on the format.

injection

Injection occurs when untrusted data is interpreted as instructions by a command, query, template, or other interpreter. Preserve the data/code boundary with the appropriate safe API.

dependencies

Dependencies are components required for behavior or builds. Their versions, failure modes, and trust become part of the system's obligations.

hardening

Hardening reduces attack surface through least privilege, safe defaults, dependency control, validation, and resource limits.

from pathlib import Path
import hmac
import os
import secrets
import subprocess

UPLOAD_ROOT = Path("/srv/uploads").resolve()

def safe_target(filename: str) -> Path:
    candidate = (UPLOAD_ROOT / filename).resolve()
    if candidate == UPLOAD_ROOT or not candidate.is_relative_to(UPLOAD_ROOT):
        raise ValueError("path traversal")
    return candidate

# Path.resolve is a lexical/filesystem check, not race-free authorization:
# an attacker who can replace directories or symlinks can race the later open.
# Use a trusted, non-writable directory tree or descriptor-relative/no-follow
# access, plus sandboxed decoding, when processing hostile uploads.

token = secrets.token_urlsafe(32)
assert hmac.compare_digest(token, token)

subprocess.run(["convert", "--", str(safe_target("input.png"))],
               check=True, timeout=5, env={"PATH": os.environ["PATH"]})

# Never eval untrusted input, never unpickle it, parameterize SQL, bound sizes
# and time, keep secrets out of source/logs, and review dependency artifacts.
