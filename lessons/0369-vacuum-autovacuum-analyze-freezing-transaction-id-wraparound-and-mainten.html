VACUUM, autovacuum, ANALYZE, freezing, transaction ID wraparound, and maintenance tuning

A data system stores information and returns correct information when programs read or change that information.

Senior practice for this track ↗ · The reading estimate excludes the lab and interview rehearsal.

Vacuum makes eligible dead-version space reusable and maintains visibility and transaction-age safety. Analyze refreshes planner statistics. Old snapshots or slot requirements can prevent removal of versions still needed, even while maintenance runs. Dead-tuple counters are estimates, and table thresholds need workload-specific tuning. Ordinary VACUUM and VACUUM FULL have different effects and costs; neither label alone proves that a cleanup backlog is solved.

VACUUM

VACUUM makes dead tuple space reusable, maintains visibility information, and freezes old transaction IDs. It normally does not shrink the table file.

autovacuum

Autovacuum schedules vacuum and analyze work to manage dead versions, statistics, and transaction-age safety.

ANALYZE

ANALYZE collects planner statistics. In EXPLAIN ANALYZE, ANALYZE means actually execute the statement and report measured execution; use caution with writes and side effects.

freezing

Freezing marks sufficiently old tuple transaction information so it remains safe across transaction-ID wraparound.

transaction ID wraparound

Transaction-ID wraparound can make old visibility information ambiguous unless vacuum freezing advances safely.

maintenance tuning

Maintenance tuning adjusts vacuum, analyze, and related work based on churn, age, locking, and measured resource pressure.
