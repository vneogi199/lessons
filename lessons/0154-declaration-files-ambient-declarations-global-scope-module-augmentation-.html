01

Declaration files

A declaration file describes the static surface of existing runtime code without implementing it. An inaccurate declaration makes unsafe code appear checked.

02

ambient declarations

An ambient declaration tells TypeScript a value, module, or global exists elsewhere. It emits no code to create that runtime value.

03

global scope

Declarations in script files can contribute to shared global scope. Module files isolate declarations unless they explicitly augment globals.

04

module augmentation

Module augmentation merges additional declarations into an existing module's types. Runtime implementation must still supply the augmented behavior.

05

lib selection

The lib option chooses standard declaration sets assumed available, such as ECMAScript, DOM, or WebWorker APIs. It does not install those APIs at runtime.

Understand, challenge, verify

A declaration file promises which values already exist at runtime; it supplies no implementation.

Senior reasoning checkpoint — answer before opening

An accidental script-global declaration can affect unrelated files. Module augmentation changes a known module's contract; it does not install a runtime feature. Choosing DOM libs cannot make browser APIs exist in Node.
