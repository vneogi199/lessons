Modules, packages, imports, sys.modules, finders, loaders, and circular imports

ELI5 example

A module lets several files use the same definitions. Importing it makes those definitions available without copying its source into every caller.

Python normally reuses a module recorded in sys.modules. If two modules import each other during initialization, one may observe the other before it has finished defining everything. Moving shared definitions to a separate module can remove that cycle.

Does every ordinary import rerun the entire module?

No. Python normally reuses the cached module.

Import creates or retrieves a module object with its own namespace. Finders locate the module, loaders initialize it, and sys.modules caches it. A module can enter that cache before its code finishes running. If two modules import each other, one can therefore see the other only partly initialized. Moving shared policy to a lower-level module can remove the cycle; delaying an import only changes when it occurs.

01

Modules

A module is an object with a namespace, usually initialized by executing one source file. Import normally creates it once per interpreter and caches it in sys.modules.

02

packages

A package organizes modules under a dotted import namespace. Its filesystem layout, distribution metadata, and public import API are related but separate concerns.

03

imports

Import searches for a module, creates its object, places it in sys.modules, and asks a loader to execute it. Early cache insertion is why cycles see partially initialized modules.

04

sys.modules

sys.modules caches imported module objects by name and affects later imports and partially initialized circular imports.

05

finders

Import finders locate module specifications using the configured import machinery.

06

loaders

Import loaders create or execute modules according to a module specification.

07

circular imports

Circular imports form a dependency cycle while modules are being initialized. Python registers a module before executing its body, so another module can encounter it before a requested attribute exists. Moving shared contracts out of the cycle addresses the dependency rather than repeatedly clearing the import cache.
