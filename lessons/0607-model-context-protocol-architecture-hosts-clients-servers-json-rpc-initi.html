01

Model Context Protocol architecture

Model Context Protocol architecture connects an AI application host to capability servers through one isolated client connection per server and a shared JSON-RPC-based protocol.

02

hosts

An MCP host is the user-facing AI application. It creates clients, controls model access and consent, coordinates context, and enforces the product's security policy.

03

clients

An MCP client is the host-side endpoint for one server connection. It negotiates capabilities, sends requests, receives notifications, and maintains that session.

04

servers

An MCP server exposes bounded context capabilities such as tools, resources, and prompts through local or remote transports. It must validate and authorize every operation.

05

JSON-RPC

JSON-RPC is the envelope format MCP uses for requests, responses, errors, and notifications. Request IDs correlate responses; notifications have no response.

06

initialization

MCP initialization is the first request-response exchange where both sides agree on a protocol version, identify themselves, and advertise supported capabilities.

07

capabilities

MCP capabilities declare optional protocol features that a client or server supports. A peer must not assume a feature that was not negotiated.

08

tools

Tools are narrow callable operations with a name, description, input schema, controlled execution, typed errors, and limited output. A model proposal never replaces application authorization.

09

resources

MCP resources are server-addressed context values identified by URIs. Clients discover or read them, while the host decides whether their content enters model context.

10

prompts

MCP prompts are server-provided reusable message templates with declared arguments. They are user-selectable context, not hidden instructions with automatic authority.

11

lifecycle

The MCP lifecycle covers connection, initialization, normal requests and notifications, cancellation or progress, and orderly transport shutdown.

# Partial MCP stdio dispatch lab, NOT a conforming production server.
# It illustrates request/response shapes; initialization-state enforcement,
# capability negotiation, cancellation and session ownership remain to implement.
import json
import sys

PROTOCOL = "2025-11-25"

def reply(request, result=None, error=None):
    message = {"jsonrpc": "2.0", "id": request.get("id")}
    message["error" if error else "result"] = error or result
    print(json.dumps(message, separators=(",", ":")), flush=True)

def dispatch(request):
    method = request.get("method")
    params = request.get("params", {})
    if not isinstance(params, dict): raise ValueError("params object required")
    if method == "initialize":
        return {
            "protocolVersion": PROTOCOL,
            "capabilities": {"tools": {}, "resources": {}, "prompts": {}},
            "serverInfo": {"name": "interview-tutor", "version": "0.1.0"},
        }
    if method == "tools/list":
        return {"tools": [{
            "name": "explain_term",
            "description": "Explain one technical term in simple language",
            "inputSchema": {
                "type": "object",
                "properties": {"term": {"type": "string", "maxLength": 80}},
                "required": ["term"],
                "additionalProperties": False,
            },
        }]}
    if method == "tools/call":
        if params.get("name") != "explain_term":
            raise ValueError("unknown tool")
        arguments = params.get("arguments", {})
        if not isinstance(arguments, dict) or set(arguments) != {"term"}:
            raise ValueError("one term argument required")
        term = arguments["term"]
        if not isinstance(term, str) or not term.strip() or len(term) > 80:
            raise ValueError("invalid term")
        glossary = {"idempotency": "Repeating one operation identity preserves its intended effect.",
                    "backpressure": "A slower consumer limits how much work the producer admits."}
        return {"content": [{"type": "text", "text": glossary.get(term.strip().lower(), "Term not in this two-entry fixture.")}]}
    if method == "resources/list":
        return {"resources": [{"uri": "lesson://roadmap", "name": "Roadmap"}]}
    if method == "resources/read":
        if params.get("uri") != "lesson://roadmap":
            raise ValueError("unknown resource")
        return {"contents": [{"uri": "lesson://roadmap", "text": "MCP -> RAG -> evaluation"}]}
    if method == "prompts/list":
        return {"prompts": [{"name": "quiz", "description": "Start a short quiz"}]}
    if method == "prompts/get":
        if params.get("name") != "quiz": raise ValueError("unknown prompt")
        return {"messages": [{"role": "user", "content": {"type": "text", "text": "Quiz me."}}]}
    raise LookupError("method not found")

while True:
    line = sys.stdin.buffer.readline(65_537)
    if not line: break
    request = {}
    if len(line) > 65_536:
        reply({}, error={"code": -32600, "message": "frame too large"})
        break  # Stop instead of treating the remainder as a second request.
    try:
        request = json.loads(line.decode("utf-8"))
        if not isinstance(request, dict) or request.get("jsonrpc") != "2.0" or not isinstance(request.get("method"), str):
            reply({}, error={"code": -32600, "message": "invalid request"})
            continue
        if "id" not in request:  # Valid notification shapes have no response.
            continue
        if type(request["id"]) not in (str, int):
            reply({}, error={"code": -32600, "message": "invalid request ID"})
            continue
        reply(request, result=dispatch(request))
    except (json.JSONDecodeError, UnicodeDecodeError):
        reply({}, error={"code": -32700, "message": "parse error"})
    except LookupError:
        reply(request, error={"code": -32601, "message": "method not found"})
    except ValueError as exc:
        reply(request, error={"code": -32602, "message": str(exc)})
# stdout is reserved for protocol frames; diagnostics belong on stderr. This
# fixture does not process server responses or arbitrary bidirectional messages.

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace an MCP session from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Capture every frame for initialize, discovery, one successful call, one unsupported request, cancellation, and shutdown.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Transport bytes, JSON-RPC IDs, negotiated capabilities, auth decision, tool arguments, result or error, cancellation, and correlated trace.
