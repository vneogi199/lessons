REST constraints

REST is an architectural style whose constraints include client-server separation, stateless requests, cacheability, layered systems, a uniform interface, and optional downloaded code.

statelessness

Stateless request handling carries the information needed to interpret each request rather than relying on hidden conversational server state.

hypermedia

Hypermedia places typed links and valid next actions in representations so clients can discover transitions instead of constructing every URI from private knowledge.

uniform interface

A uniform interface uses consistent resource identification, representations, and interaction semantics to reduce client-server coupling.

maturity tradeoffs

API maturity choices balance standardized constraints and discoverability against client needs and implementation cost.

REST combines several constraints to reduce coupling across clients, servers and intermediaries. Stateless requests do not forbid persistent business data or caches; they avoid hidden conversational assumptions needed to interpret a request. Links can expose possible next actions, but the server must recheck state and authority when one arrives. Document custom link relations so clients can use them meaningfully.
