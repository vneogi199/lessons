01

Node test runner

The built-in node:test runner discovers and executes tests with assertions, mocking, concurrency controls, coverage, watch behavior, and process or thread isolation options.

02

assertions

An assertion checks that a stated condition holds during a test or execution. Know whether your assertion mechanism throws, only logs, or can be disabled.

03

mocking

Mocking replaces collaborators to control tests; it cannot establish the real dependency's integration behavior.

04

timers

Node timers schedule callbacks after a minimum delay threshold. Event-loop work, operating-system scheduling, and clock behavior can make actual execution later.

05

concurrency

Concurrency allows tasks to make overlapping progress. Shared state still needs an explicit ordering or ownership rule.

06

coverage

Coverage records executed code regions, not correctness of assertions or completeness of failure cases.

07

isolation

Isolation limits interference between activities or tenants. Specify whether it covers state visibility, resource contention, permissions, or failure propagation.

import assert from "node:assert/strict";
import { afterEach, mock, test } from "node:test";

afterEach(() => mock.restoreAll());

async function loadProjects({ signal }) {
  const response = await fetch("https://api.example.com/projects", { signal });
  if (!response.ok) throw new Error("project request failed");
  return response.json();
}

test("client propagates cancellation", async t => {
  const controller = new AbortController();
  const fetchMock = t.mock.method(globalThis, "fetch", async (url, options) => {
    assert.equal(options.signal, controller.signal);
    options.signal.throwIfAborted();
    await new Promise((resolve, reject) => options.signal.addEventListener("abort", () => reject(options.signal.reason), { once: true }));
  });

  const pending = loadProjects({ signal: controller.signal });
  controller.abort(new Error("test abort"));
  await assert.rejects(pending, /test abort/);
  assert.equal(fetchMock.mock.callCount(), 1);
  await assert.rejects(loadProjects({ signal: controller.signal }), /test abort/);
  assert.equal(fetchMock.mock.callCount(), 2);
});

08 · Common mistakes

Memorizing the label

A definition is not enough. Trace a diagnostic experiment from input to output.

Testing only success

The happy path can hide a weak design. Try this failure: Make the dependency fail or resolve out of order, then remove the production guard and confirm the test detects the regression.

Changing too much

Change one condition at a time. Otherwise, you will not know what caused the result.

Guessing

Check the system instead: Requirement, controlled fixture, actual result, failing/passing assertion and cleanup evidence; browser behavior needs browser verification.
